## 1. 功能范围

系统包含：

```text
卡牌中心
├── 全部卡牌
├── 我的卡牌
├── 愿望单
└── 卡牌详情

卡组
├── 卡组列表
├── 卡组编辑
├── 卡组展示
└── 卡组统计

操作日志
├── 每日操作汇总
└── 操作明细
```

### 1.1 页面身份标识

部署实例可以通过配置文件提供 `app.display_name`，用于表示当前是谁的卡牌库。该配置可省略，默认值为空字符串。

页面标题或全局导航区域按统一逻辑展示该配置值。应用不裁剪、不校验或分支处理该字符串；值为空时展示结果自然为空字符串。

`display_name` 只用于展示，不代表登录账号、认证主体或数据权限，也不写入个人数据库或用户操作日志。修改配置并重启服务后，页面使用新名称。

全部卡牌、我的卡牌和愿望单复用导航、搜索筛选、卡图及详情入口等基础组件，但列表层的快捷操作按页面范围严格区分，不能因为复用组件而互相暴露。

### 1.2 卡牌身份与读取链路

普通卡牌具体语言印刷版本的业务标识统一为 `printing_uuid = mtgnissa_card_printing.uuid`。单面牌使用自身语言印刷行 UUID；多牌面牌使用同一印刷、同一语言主牌面（`face_index = 0`）的语言印刷 UUID，随同返回其余牌面。普通单面牌的 `face_index = -1`。详情、语言及版本跳转、收藏、愿望单、卡组候选上下文、封面版本引用和操作日志均使用该标识；卡组持久化身份仍为 `oracle_id`。系列业务标识使用 `mtgnissa_set.code`，不使用 Set UUID。

| 功能范围 | 读取链路与身份口径 |
| --- | --- |
| 普通 Set 卡牌列表、详情、语言及版本切换、收藏、愿望单、卡组展示与编辑上下文、日志快照生成 | `mtgnissa_card_printing -> mtgnissa_card -> 翻译或 Oracle 数据`；通过 `card_uuid` 关联基础卡面，以主牌面 `printing_uuid` 定位具体语言版本 |
| 卡组增加卡牌的正式名称搜索及名称联想 | 从 `mtgnissa_card_printing.printed_name` 命中，经基础卡面取得非空 `oracle_id`；正式结果按 Oracle 去重，联想按名称去重 |
| 全局名称及语法搜索、卡组代码解析、逻辑卡聚合与统计、卡面展开字段及 Oracle 级查询 | 可以直接使用 `mtgnissa_card -> 翻译、卡面展开表或 Oracle 数据`；不为命中计算建立具体印刷语言上下文 |
| Token Set 卡牌列表 | 直接读取 `mtgnissa_token`，使用自身 `uuid`，不进入普通卡牌语言印刷链路 |
| 历史操作日志读取 | 直接使用已保存快照，不重新查询 Card DB 改写历史文字、语言、图片或版本身份 |

`scryfall_id` 是外部公开 ID 和图片来源信息，不作为具体语言版本的业务键。仅卡图解析可在语言印刷行缺少图片 ID 时回退关联的 `mtgnissa_card.scryfall_id`；该回退不改变 `printing_uuid`、语言、详情目标、收藏、愿望单、卡组、封面引用或操作日志，不因共用基础卡图而合并不同版本。

卡面中文基础翻译通过 `mtgnissa_card.uuid -> card_translation.card_id` 取得；Oracle 卡面翻译通过 `card_oracle_translation_mapping -> oracle_translation.face_oracle_id`，风味翻译通过 `card_flavor_translation_mapping` 取得。不得假设基础卡表有 `face_oracle_id`，也不得直接按 `oracle_id` 混合不同牌面的翻译；逐字段沿用既定翻译优先级，中文缺失时回退当前基础卡面的英文内容。

## 2. 卡牌查看与检索

已确认需要：

- 查看 Set 列表
- 选择 Set 查看该 Set 的卡牌
- 通过右上角全局搜索框执行普通卡名或语法搜索
- 通过列表中间搜索框按名称关键字查询对应 list 接口
- 根据费用搜索
- 从检索结果进入卡牌详情
- 从“我的卡牌”列表快速修改拥有数量
- 从“愿望单”列表快速管理愿望单状态

### 2.1 搜索入口边界

系统存在两类不同搜索入口，不得共用输入解析规则：

1. 页面右上角的全局搜索框支持普通卡名和首版支持的查询语法，提示文案为“搜索卡牌或输入语法…”。提交后进入独立的全部卡牌搜索结果页；只有该入口以及功能标签跳转会解析 `otag:` 等语法。搜索框右侧必须显示独立的小型“？”语法帮助按钮，点击后在新浏览器标签页直接打开 `https://scryfall.com/docs/syntax`，并提供“查看搜索语法帮助”的可访问名称及 `noopener noreferrer` 外链隔离。
2. 提供内容区搜索框的列表页面只接受名称关键字，并作为当前页面 list 返回接口的查询参数。具体 Set 卡牌列表按卡名关键字查询，Set 列表按系列名称或缩写关键字查询；不得解析冒号操作符、布尔表达式或其他搜索语法。语法搜索结果页不提供内容区搜索框。

列表名称关键字改变并提交时重新请求对应 list 接口并重置列表加载位置；具体 Set 的筛选和排序则复用已取得的完整轻量数据，不重新请求 Card DB。卡组增加卡牌遵循第 11.4 节的主动正式搜索与自动名称联想规则，输入变化本身不触发正式搜索。右上角全局搜索与列表内关键字搜索的路由和接口参数必须相互独立。全局搜索的操作符、值、比较符、引号和布尔组合以第 2.2 节及支持矩阵为准；输入只有在能够被当前解析器完整识别时才执行语法查询，只要不能完整匹配当前支持的语法，就将完整原文作为卡名关键字执行模糊查询。因此全局搜索不存在语法错误页面或语法错误提示。

所有名称查询不区分大小写，去除关键字首尾空白，并将用户输入的 `%`、`_` 及转义字符当作普通文字。全局名称查询、收藏与愿望单名称筛选匹配 `mtgnissa_card.name`；普通 Set 列表和卡组增加卡牌正式搜索匹配 `mtgnissa_card_printing.printed_name`，执行 `%q%` 包含匹配；卡组名称联想执行同字段的 `q%` 前缀匹配。Token 列表不接受名称搜索。多选筛选参数均可省略，省略表示不限制对应维度；排序和合并参数省略时使用各页面已确认的默认值。

卡牌中心列表页的多选筛选下拉框统一采用“关闭后查询”：打开时从已提交条件复制临时选择，下拉框内的连续勾选只修改临时值，不逐项请求或刷新列表；点击下拉框外任意区域时必须立即关闭并提交最终选择。只有选择发生变化时，才在关闭完成后执行一次查询或本地筛选并重置列表加载位置；未变化时不得产生无效请求。下拉框不设置“确定”或“取消”按钮。Set 列表、我的卡牌和愿望单在关闭后重新请求对应 list 接口；具体 Set 卡牌列表继续复用已一次性取得的完整轻量结果，只进行一次本地筛选和卡图渲染批次重置，不重复请求 Card DB。

所有列表查询结果为 0 时都只保留原页面导航、标题、查询筛选工具栏、表头、分页区或结果计数，并将实际列表内容渲染为空；不设计专用空状态插画、说明卡片、清空条件按钮、返回入口或新建入口，也不区分“首次无数据”和“筛选无结果”两套空状态。空列表不是错误，不打开错误弹窗。

页面请求失败、业务校验失败、卡组代码解析失败、剪贴板写入失败以及后端返回的未预期错误，统一使用 `.pen` 中的 `Prototype / Unified Error Modal`。弹窗相对当前浏览器视口居中，使用阻断底层交互和滚动的半透明暗色遮罩；点击遮罩不关闭。弹窗不显示右上角关闭叉，只能通过底部“关闭”按钮退出。宽度固定为 520 px，高度随错误正文自然增长；后端返回的安全错误信息直接作为普通正文显示并自动换行，不增加“错误信息”标题、外框或底色容器。高度达到 `calc(100vh - 64px)` 后只滚动正文区，标题和底部按钮保持可见。未知错误显示“发生意外错误，操作未完成。请稍后重试。”，不得展示堆栈、SQL、内部路径或原始异常对象。错误后保留操作前页面状态，关闭弹窗不自动刷新、重试或清空。外部卡图加载失败继续使用固定尺寸缺图占位，不为每张图片弹出阻断错误。

语法搜索结果页复用具体 Set 卡牌列表的导航、吸顶面包屑、结果总数、五列纯卡图网格和无限滚动。面包屑固定为“卡牌中心 > 全部卡牌 > 实际执行的查询原文或规范化搜索语法”，例如 `otag:"mana rock"`；“卡牌中心”和“全部卡牌”均返回 Set 列表页。页面内容区不显示名称搜索框、筛选控件或排序控件，查询只能通过右上角全局搜索框重新提交，或由卡牌详情中的具体功能标签生成。全局搜索直接基于 `mtgnissa_card` 计算命中，固定以非空 `oracle_id` 为结果单位，同一 `oracle_id` 只返回一项，不展开不同 Set、语言或印刷版本；结果总数同样按 `oracle_id` 去重，但界面只显示“张卡牌”，不得暴露“逻辑卡”概念。名称模式先匹配基础卡牌记录，再取得非空 `oracle_id` 并去重。语法模式为每个原子条件分别计算满足条件的 `oracle_id` 集合：名称、类型、关键字异能、费用和数值等牌面属性由任一牌面满足即可，系列、稀有度等印刷属性由任一具体印刷满足即可；隐式 `AND`、`OR` 和括号组合在 `oracle_id` 集合层执行，不要求同一牌面或同一具体印刷满足完整表达式。取得最终集合后，在每个命中的 Oracle 全部基础印刷中按 `mtgnissa_card.scryfall_id ASC` 选定代表印刷，取主牌面作为摘要及排序基准，并组织完整牌面信息；不按发行日期选择最新版本，不在共享图片 ID 的牌面间任意取行。仅生成详情入口时解析代表主牌面实际存在的语言印刷行，按语言字典顺序、语言代码和 UUID 升序选取首项，返回 `printing_uuid` 及语言；搜索命中与代表基础卡图不因此改变，前端不增加版本选择步骤。代表记录及入口解析必须使用集合查询或批量关联，不按结果逐条追加查询；缺少可定位的主牌面语言印刷按 API 契约返回依赖错误，不以基础卡面 UUID 冒充版本入口。结果按主牌面英文卡名不区分大小写 A–Z 排序，同名时按 `oracle_id` 升序兜底并使用服务端游标持续加载，确保整个分页过程中同一 `oracle_id` 不重复、不遗漏；不得先从全表任意选择代表印刷再应用原子条件，也不显示分页按钮。合法语法查询或名称模糊查询没有任何匹配项时，保持同一正常结果页并显示“0 张卡牌”，卡图网格为空；不得显示错误、警告、重试入口或额外空状态文案。没有 Oracle 身份的卡牌不进入全局结果，仍可在具体 Set 列表展示。

语法搜索的服务端游标必须同时编码规范化后的英文卡名排序值与 `oracle_id` 位置，以完整延续“英文卡名不区分大小写 A–Z、同名按 `oracle_id` 升序”的复合顺序；游标对前端保持不透明。

普通 Set 列表的语言按钮和语言筛选项来自 `scryfall_language`，统一原样展示内置的 `display_name`；当前不提供用户自由修改语言展示名的能力，前端也不得维护语言代码到展示名的固定映射。页面固定按 `sort_order ASC, code ASC` 只取前 11 个语言；其余特殊语言保留在字典和卡牌数据中，不出现在 Set 列表按钮或筛选项中，不得通过具体语言代码判断截止位置。每行语言可用性直接读取普通 Set 的 `languages`，只用于确定进入对应 Set 卡牌列表时的语言；每个可用语言按钮跳转到该语言列表并阻止整行点击，置灰语言不可点击。普通行其余区域进入从左到右第一个可用语言，无可用语言则不可跳转，不额外应用中文或英文优先级。Token Set 不展示语言按钮，整行直接进入完整 Token 列表，不带语言参数。

Set 列表支持发行日期、系列名称、系列代码和卡牌数量排序，方向沿用 API 契约，默认发行日期从新到旧；这些排序仅作用于 `parent_code IS NULL` 的顶层父 Set。父节点主排序值相同时统一按 `code ASC` 兜底，日期缺失排在有日期的父节点之后，游标延续最终父节点位置。

Set 发行日期直接取 `AllPrintings.json` 的 `sets[].releaseDate`，保存在 `mtgnissa_set.released_at`；`card_count` 为导入卡面数量，普通 Set 由 `cards[]` 计数，Token Set 由 `tokens[]` 计数，不按收藏编号或 Oracle 去重，也不因后续多牌面组织而改写。列表展示和排序直接使用这两个权威值，不在页面请求期间重新聚合。

Set 列表的系列类型筛选项只从顶层父 Set 的非空 `set_type` 去重生成，按产生该值的最小父 Set `code ASC` 排列，必要时按 `set_type ASC` 兜底；只存在于子 Set 或 Token Set 的类型不进入选项。系列分类只使用类型下拉框，不提供额外快捷分类栏，语言筛选保留。

Set 父子层级唯一依据 `mtgnissa_set.parent_code`，是首版必须实现及验收的行为，不再预留到接口开发时推断。名称或代码查询、语言及类型筛选、排序和游标分页均只作用于顶层父 Set；同字段多选 OR、不同维度 AND。父节点命中后，其完整子树始终跟随并缩进，不论子孙自身是否满足条件；有搜索或筛选条件也不改为平铺。同一父节点先普通子 Set、后 Token Set，两组内均按 `released_at ASC, code ASC` 排序，日期缺失排在有日期记录之后，递归以前序遍历展开。分页按完整父组截取，不拆分子树；子孙行不消耗父组名额，列表总数按命中的顶层父组计数，实际可见行数可大于单批父组数量。不得按名称、时间或类型猜测层级。

### 2.2 首版搜索语法基线

首版查询语法以 [Scryfall Search Reference](https://scryfall.com/docs/syntax) 为表达形式参考。[搜索语法支持矩阵](search-syntax-support.md) 是本需求文档的首版需求基线组成部分，与本节具有同等约束力；矩阵当前保留的全部关键字、别名、比较符和值域构成首版必须实现和验收的完整语法范围，矩阵未列出的 Scryfall 写法不属于首版。后续增加、删除或调整语法时，必须同时修改本节与矩阵，不得只修改其中一处。Oracle 功能标签查询已按 Scryfall“Tagger Tags”条目纳入矩阵。查询只在本地 Card DB 执行，不把用户输入或查询逐次转发给 Scryfall。

#### 2.2.1 通用解析与组合规则

- 字段名、布尔关键字和英文枚举值不区分大小写；用户提交的原文仍原样保留在路由和回退名称查询中。
- 空白分隔的多个条件使用隐式 `AND`；显式 `OR` 不区分大小写；圆括号用于改变组合优先级；`AND` 的优先级高于 `OR`。
- 包含空格或标点的文字值使用双引号。支持用 `\"` 表示值内双引号、`\\` 表示反斜杠；未闭合引号视为无法完整识别。
- 没有字段前缀的词或引号短语作为卡名条件；它们可以与支持的字段条件组合。只有普通文本且没有字段、比较符、布尔关键字或分组时，直接执行完整原文的卡名模糊查询。
- `name:<值>` 显式查询卡名；未加引号的值按不区分大小写的名称片段匹配，引号值按连续名称短语匹配。
- 解析器必须消费完整输入。出现任何未支持字段、值、比较符、正则表达式、显示控制关键字或不完整表达式时，不得忽略未知部分或执行部分条件，而是把完整原文回退为卡名模糊查询。
- 合法语法结果始终按 `oracle_id` 去重。多牌面卡的名称、类型、关键字异能、费用和数值属性按逻辑卡聚合，任一牌面满足单个条件即视为该逻辑卡满足该条件；布尔表达式在逻辑卡层求值。
- `null`、空字符串或不能按当前条件解释的字段值不匹配查询条件。
- 首版不支持正则表达式、`!` 精确卡名、显示/排序关键字或矩阵未列出的其他搜索字段。未支持写法仍按完整原文回退为名称模糊查询，不显示语法错误。

#### 2.2.2 Colors and Color Identity

支持以下字段：

| 语义 | 字段及别名 | 数据来源 |
| --- | --- | --- |
| 卡牌颜色 | `c`、`color` | `mtgnissa_card.colors_mask` |
| 颜色标识 | `id`、`identity` | `mtgnissa_card.color_identity_mask` |

- 颜色值支持 `W`、`U`、`B`、`R`、`G` 字母的任意无重复组合，以及 `white`、`blue`、`black`、`red`、`green` 全名。字母顺序不影响结果。
- `c` 或 `colorless` 表示空颜色集合，`m` 或 `multicolor` 表示颜色数量至少为二；二者均可用于卡牌颜色或颜色标识查询。
- 非负整数值表示颜色集合中的颜色数量，例如 `c=2` 查询恰好双色的卡牌，`id<=2` 查询颜色标识数量不超过二的卡牌；数量比较使用普通数值比较语义。
- 支持以下固定命名颜色组，解析后先规范化为 WUBRG 位集合再比较：公会 `azorius=WU`、`dimir=UB`、`rakdos=BR`、`gruul=RG`、`selesnya=GW`、`orzhov=WB`、`izzet=UR`、`golgari=BG`、`boros=RW`、`simic=GU`；碎片 `bant=GWU`、`esper=WUB`、`grixis=UBR`、`jund=BRG`、`naya=RGW`；楔形 `abzan=WBG`、`jeskai=URW`、`sultai=BGU`、`mardu=RWB`、`temur=GUR`；学院 `silverquill=WB`、`prismari=UR`、`witherbloom=BG`、`lorehold=RW`、`quandrix=GU`；四色 `chaos=UBRG`、`aggression=WBRG`、`altruism=WURG`、`growth=WUBG`、`artifice=WUBR`。未列出的昵称不属于首版值域。
- `:` 与 `=` 表示颜色集合完全相等，`!=` 表示不相等，`>`/`>=` 表示严格/非严格超集，`<`/`<=` 表示严格/非严格子集。例如 `c=wu` 只匹配恰好蓝白色，`c>=wu` 允许包含其他颜色，`id<=esper` 匹配颜色标识属于 Esper 颜色集合的卡牌。

#### 2.2.3 Card Types

- 支持 `t:<值>` 和 `type:<值>`，查询英文 Oracle `type_line`，不查询翻译后类别文字。
- 未加引号的值按不区分大小写的类型词前缀匹配，允许匹配超类别、卡牌类别或副类别；引号值按连续短语匹配。
- 多个类型条件分别参与布尔组合，例如 `t:merfolk t:legend`。
- 首版不支持类型正则表达式。

#### 2.2.4 Card Text

支持以下字段：

| 语义 | 字段及别名 | 规则 |
| --- | --- | --- |
| 关键字异能 | `keyword`、`kw` | 精确匹配 `scryfall_card_keyword.keyword` |

- `keyword:` 与 `kw:` 是等价别名，按规范化后的完整关键字名称匹配，不使用文字包含关系模拟关键字。
- 首版不支持 `fo:`、`o:`、`oracle:` 或 Oracle 文字正则表达式；出现时必须按完整原文回退为卡名模糊查询。

#### 2.2.5 Mana Costs

支持以下条件：

| 语义 | 字段及别名 |
| --- | --- |
| 法术力值 | `mv`、`manavalue` |

- 法术力值接受 `:`、`=`、`!=`、`>`、`>=`、`<`、`<=`。`:` 等同 `=`；数值允许非负整数或小数，并按数据库中的 `cmc` 数值比较。

#### 2.2.6 Power, Toughness, and Loyalty

支持以下数值字段及别名：

| 语义 | 字段及别名 |
| --- | --- |
| 力量 | `power`、`pow` |
| 防御力 | `toughness`、`tou` |
| 力量与防御力之和 | `pt`、`powtou` |
| 初始忠诚值 | `loyalty`、`loy` |

- 支持 `:`、`=`、`!=`、`>`、`>=`、`<`、`<=`；`:` 等同 `=`。右操作数可以是十进制数字，也可以是同一牌面的力量、防御力或忠诚值字段；字段全名与缩写均可使用，即 `power`/`pow`、`toughness`/`tou`、`loyalty`/`loy`，例如 `pow>tou`、`power>toughness`。
- `pt`/`powtou` 先把同一牌面的数值力量与数值防御力相加，再执行比较；缺少任一字段时不匹配正向条件。
- 只有能够完整解析为十进制数字的卡牌字段参加数值比较。`*`、`X`、`1+*`、`∞` 等非纯数值表达不参加数值比较，也不因其中包含数字而被截断解释。
- 字段间比较要求两侧都存在并且都是纯数值；不得跨不同牌面拼接力量、防御力或忠诚值。
- `mtgnissa_card` 必须保留原始字符串列 `power`、`toughness`、`loyalty`，并增加可空数值派生列 `power_numeric`、`toughness_numeric`、`loyalty_numeric` 和 `pt_numeric`。源值只有在去除首尾空白后能够完整解析为十进制数时才写入对应数值列，否则写入 `NULL`；`pt_numeric` 仅在同一牌面的力量和防御力数值列均非空时保存二者之和，否则写入 `NULL`。
- `power_numeric`、`toughness_numeric`、`loyalty_numeric` 和 `pt_numeric` 必须分别建立普通索引。与常量比较时直接查询数值列，不得在查询时对原始字符串执行正则判断或数值转换；力量、防御力和忠诚值之间的字段比较同样使用数值列。

#### 2.2.7 Multi-faced Cards

- `is:split`、`is:flip`、`is:meld` 和 `is:leveler` 分别按对应 `mtgnissa_card.layout` 查询。
- `is:transform` 与 `is:tdfc` 是等价别名，只查询转化式双面布局。

#### 2.2.8 Spells, Permanents, and Effects

- `is:spell` 查询瞬间或法术牌。
- `is:permanent` 查询神器、战役、生物、结界、地或鹏洛客牌。
- `is:historic` 查询神器、传奇或 Saga 牌；任一条件满足即匹配。
- 上述条件通过 `scryfall_card_type` 的英文 Oracle 类型派生，不通过规则文字猜测。

#### 2.2.9 Rarity

- `r:` 与 `rarity:` 是等价别名，值支持 `common/c`、`uncommon/u`、`rare/r`、`mythic/m`、`special/s` 和 `bonus/b`。
- 支持 `:`、`=`、`!=`、`>`、`>=`、`<`、`<=`；`:` 等同 `=`。比较顺序为 `common < uncommon < rare < mythic < special < bonus`。
- 稀有度条件先匹配具体印刷记录，再按通用规则将结果按 `oracle_id` 去重。

#### 2.2.10 Sets and Blocks

- `s:`、`e:`、`set:` 与 `edition:` 是等价别名，按不区分大小写的系列代码或英文系列名称查询。
- 系列条件先匹配具体印刷记录，再按通用规则将结果按 `oracle_id` 去重。

#### 2.2.11 Tagger Tags

- 支持 `otag:<值>`，并接受 `oracletag:` 和 `function:` 别名；解析后统一规范化为带双引号及必要转义的 `otag:"<值>"`。
- 标签值按 `oracle_tag.label` 完整匹配；包含空格或标点时必须使用双引号，并沿用通用转义规则。
- 功能标签条件可以与本节其他条件使用隐式 `AND`、`OR` 和括号组合。
- 当前 Card DB 只导入 Oracle Tags，因此首版只支持 Scryfall“Tagger Tags”条目中的 `otag:`、`oracletag:`、`function:`；插画标签 `art:`、`atag:`、`arttag:` 未列入支持矩阵，仍按完整原文回退为卡名模糊查询。
- 卡牌详情接口为每个功能标签返回一个完整 `query` 字符串。该字符串同时是标签卡片的展示值和点击后提交的查询值；前端必须原样显示，并在点击时把同一字符串作为全局语法搜索接口的 `q` 参数提交，不得自行拼接、去引号、规范化或再次转义。

#### 2.2.12 回退和验收边界

- `c:r t:instant mv<=2`、`(t:angel OR t:demon) id<=esper`、`pow>tou`、`r:rare set:khm` 和 `otag:"mana rock"` 必须作为语法查询执行。
- `fo:damage`、`o:damage`、`oracle:draw`、`cmc>=5`、`lang:ja`、`fo:/draw.+card/`、`order:name` 以及其他不在本节清单中的写法，首版必须把完整输入作为卡名模糊查询，不得只执行其中已识别的部分。
- 语法解析失败和合法查询零结果是两种不同内部结果，但都不是用户可见错误：前者回退名称查询，后者正常显示“0 张卡牌”。
- API 和自动化测试必须为每个字段别名、比较符、布尔组合、引号转义、括号、多牌面聚合、非数值属性及完整回退建立用例。

### 2.3 Token Set 浏览

Token、徽记等对象直接从 `mtgnissa_token` 读取，只进入 Token Set 卡牌列表；不提供普通卡牌详情、全局搜索、收藏、愿望单或卡组入口，不继承普通系列语言。普通 Set 有 Token 时派生专用系列，其代码按数据字典的 `tokenSetCode`／`T + code` 规则生成，`parent_code` 指向来源普通系列，`languages = NULL`。

Token 页面只保留导航、无语言括号的面包屑、完整结果总数及纯卡图网格，不提供名称搜索、语言选择、筛选或排序控件。接口不接受这些参数，也不使用后端分页；一次取得完整轻量结果，前端本地分批渲染和加载图片。

同一印刷共享非空 `scryfall_id` 的多牌面按 `face_index` 组织成一个可翻面卡位，默认展示主牌面，以主牌面 Token UUID 定位；不按 `oracle_id` 合并不同印刷。缺少图片 ID 且无法可靠配对时按各自 UUID 独立保留并显示缺图占位，不合并空 ID。固定按主牌面收藏编号自然升序、主牌面 UUID 升序返回，前端保持该顺序。页面总数按组织后的印刷项计数，Set 索引的 `card_count` 仍是导入卡面数。图片缺失时不套用普通卡牌的语言印刷回退链路。

## 3. 卡牌详情

卡牌详情以具体印刷版本为入口：

```text
printing_uuid（具体印刷及语言版本）
```

展示内容包括：

- 卡图
- 双面牌或多牌面的所有内容
- 卡名
- 费用
- 类型
- 卡牌文字
- 力量、防御、忠诚等属性
- Set
- 收藏编号
- 稀有度
- 卡牌原语言（UI 统一显示为“语言”）
- 数据库提供的其他必要字段

### 3.1 卡牌原语言与翻译后语言

项目规则内部统一区分以下两个概念：

- **卡牌原语言**：具体印刷记录及卡图对应的语言，来源为 `mtgnissa_card_printing.language_code`。
- **翻译后语言**：卡牌名称、类别、规则文字、风味文字和官方释疑等卡牌说明使用的展示语言，首版固定为简体中文。

UI 交互不暴露“卡牌原语言”术语。页面中的“语言”筛选、按钮、下拉框、面包屑和合并选项均指卡牌原语言。翻译后语言不作为筛选或切换项展示，只用于生成卡牌说明内容。

卡牌详情不提供翻译后语言切换，卡牌说明统一使用翻译后语言。

卡牌名称、类型、规则文字等说明内容：

```text
优先使用翻译后语言
    ↓
不存在时显示英文
```

翻译后语言与卡牌原语言相互独立。

例如卡牌原语言为日文、系统配置的翻译后语言为简体中文时：

```text
UI 语言：日文
卡牌说明：简体中文
```

翻译后语言的说明不存在时显示对应英文内容。官方释疑同样每条只显示一份正文：存在翻译时只显示翻译，不并列、折叠或附带英文原文；仅在该条翻译为空时回退显示英文 `oracle_ruling.text`。官方释疑只展示发布日期和正文，不展示来源，也不构造或补充 `source`。

### 3.2 印刷版本

详情页展示同一逻辑卡牌的全部印刷版本：

- 不同 Set
- 不同收藏编号
- 不同卡牌原语言（UI 显示为“语言”）
- 各版本拥有数量

支持切换到其他印刷版本详情。

### 3.3 拥有数量

普通卡和闪卡在同一个数量字段中展示：

```text
普通卡数量:闪卡数量*
```

例如：

```text
3:1*
```

表示普通卡 3 张、闪卡 1 张。普通和闪卡数量是同一具体语言印刷收藏记录中的两个数量桶，不以数据源的 `finishes` 限制可录入工艺。

详情页支持分别增加或减少普通卡和闪卡数量。

## 4. 我的卡牌

只展示普通与闪卡数量之和大于零的收藏记录。页面及系列分组总计统一为“共 X 张，Y 种”：X 是普通与闪卡数量之和，Y 按非空 `oracle_id` 去重，缺少 Oracle 的记录按各自 `printing_uuid` 独立计种。

收藏数量至少区分：

```text
具体印刷及语言版本（printing_uuid）
├── 普通卡数量
└── 闪卡数量
```

收藏记录按 `printing_uuid` 唯一定位具体印刷及语言，普通与闪卡数量保存在同一条记录中；多牌面共享该版本的收藏，不按牌面拆分。不为每一张实体卡建立独立档案。

### 4.1 排序

“我的卡牌”支持系列、颜色、法术力和名称四种排序。默认“排序：系列”：系列按发行日期从新到旧，系列内按收藏编号自然序从小到大；收藏编号按数字段和文本段交替比较，兼容字母、符号、跳号和缺失编号，不能直接按字符串排序。颜色排序固定按白、蓝、黑、红、绿、多色、无色排列，同色再按英文卡名不区分大小写 A–Z 和返回展示卡的 `printing_uuid` 排序。法术力排序按 `mtgnissa_card.cmc` 从低到高，数值相同再按英文卡名不区分大小写 A–Z 和返回展示卡的 `printing_uuid` 排序。名称排序按英文卡名不区分大小写 A–Z，同名时按返回展示卡的 `printing_uuid` 排序；所有 `printing_uuid` 兜底均为升序。

“我的卡牌”的系列与语言筛选项只从当前收藏数量大于零的记录生成。系列选项按发行时间从新到旧排列，无发行时间的系列排在最后，发行时间相同或缺失时按 `set_code` 升序兜底；语言选项按 `scryfall_language.sort_order` 升序、语言 `code` 升序兜底。

具体 Set、具体语言的卡牌列表单独支持收藏编号升序／降序、法术力低到高／高到低和名称 A 到 Z／Z 到 A；默认收藏编号升序，不提供颜色排序。收藏编号排序只允许用于单一 Set 列表，基于已一次性取得的当前 Set 轻量结果在前端执行自然排序；主排序值相同时继续按收藏编号自然升序，最终按 `printing_uuid` 升序兜底。跨 Set 的语法搜索结果不提供收藏编号排序。

### 4.2 系列合并

按 Set 排序时不提供跨 Set 合并。

按颜色、法术力或名称排序时提供：

“合并不同系列”使用滑动开关，产品默认值为关闭。

关闭时，不同印刷版本展示为多张卡：

```text
Lightning Bolt / M11 / 2:1*
Lightning Bolt / M10 / 3:0*
Lightning Bolt / 2X2 / 1:1*
```

这些卡牌按照排序结果连续展示。

开启时，同一逻辑卡牌展示为一张汇总卡：

```text
Lightning Bolt / 全部 Set / 6:2*
```

汇总卡不提供各 Set 明细入口；列表直接选择合并范围内发行日期最新的具体印刷版本作为卡图和详情跳转目标。

### 4.3 语言合并

收藏严格区分语言，并提供：

“合并不同语言”使用滑动开关，产品默认值为开启。原型中为展示普通卡、闪卡数量加减控件而画出的关闭状态仅是特定页面状态，不代表首次进入页面的默认值；只有两个合并开关均关闭时，才按具体语言印刷记录展示数量加减控件；任一开关开启时只展示汇总数量，并完全隐藏加减符号及热区，不允许以汇总代表版本修改数量。

关闭时：

```text
Lightning Bolt / M11 / 英文 / 2:1*
Lightning Bolt / M11 / 日文 / 1:0*
Lightning Bolt / M11 / 简中 / 3:0*
```

开启时：

```text
Lightning Bolt / M11 / 全部语言 / 6:1*
```

汇总卡不提供语言明细入口；列表直接选择合并范围内发行日期最新的具体印刷版本作为卡图和详情跳转目标。

### 4.4 合并组合

| 系列合并 | 语言合并 | 展示单位 |
| --- | --- | --- |
| 关闭 | 关闭 | 每个具体印刷及语言版本独立展示 |
| 开启 | 关闭 | 同一逻辑卡、同一语言合并不同系列及收藏编号 |
| 关闭 | 开启 | 同一逻辑卡、同一系列及收藏编号合并不同语言 |
| 开启 | 开启 | 每个逻辑卡牌展示一张 |

普通和闪卡始终通过 `普通:闪*` 汇总。没有 `oracle_id` 的对象始终按自身 `printing_uuid` 独立分组和计种，不把多个空 Oracle 合并；同一逻辑卡的不同收藏编号仍是不同具体印刷版本。

合并只改变列表分组和数量汇总，不新增版本选择、明细抽屉、弹层或独立页面。同一合并分组内候选印刷版本最终按发行日期从新到旧排列；取该顺序中的第一张，也就是最新发行版本，作为汇总卡的展示卡图和详情跳转目标。发行日期相同时使用 `printing_uuid` 升序兜底，避免重复查询时展示版本漂移。点击汇总卡卡图进入当前展示的该具体印刷版本详情页；卡图下的数量操作必须阻止详情跳转事件。

## 5. 愿望单

愿望单只展示用户明确标记的具体印刷及语言版本，以主牌面 `printing_uuid` 唯一定位；多牌面共享一个愿望单状态，不按牌面拆分。

愿望项严格区分：

```text
Set
+ 收藏编号
+ 语言
```

不跨 Set 合并，不跨语言合并。

愿望单不记录：

- 目标数量
- 闪卡偏好
- 备注
- 优先级

愿望项只支持：

- 加入愿望单
- 移出愿望单

不提供修改语言操作。需要改变语言时：

```text
移出原愿望项
    ↓
使用新语言重新加入
```

即使已经拥有该版本，也不自动移出愿望单。

愿望单的系列、语言、颜色、法术力和稀有度筛选与“我的卡牌”一致；系列和语言选项只从当前愿望单记录生成，系列按发行时间从新到旧、`set_code` 升序兜底且无发行时间排在最后，语言按 `sort_order` 升序、`code` 升序兜底。法术力固定为 0、1、2、3、4、5、6、7、8+，稀有度界面文案固定为铁、银、金、秘稀、特殊、额外，对应接口原值 `common`、`uncommon`、`rare`、`mythic`、`special`、`bonus`。愿望单同样支持系列、颜色、法术力和名称四种排序并复用“我的卡牌”的比较顺序，最终按 `printing_uuid` 升序兜底；只有系列排序使用系列分组，其余三种排序连续平铺。愿望单不提供任何合并开关。

愿望单可以在卡牌详情页和愿望单列表中直接管理。从全部卡牌或我的卡牌列表进入卡牌详情后，也可以在详情页管理愿望单；全部卡牌和我的卡牌列表本身不提供愿望单快捷操作。

## 6. 卡牌中心复合

普通卡牌的全部卡牌、我的卡牌和愿望单按各自范围复用以下基础组件；全局结果不提供内容区搜索、筛选或排序，Token 浏览按第 2.3 节单独约束：

- 搜索与筛选
- 排序
- 卡牌列表或图片展示
- 卡牌详情入口

列表快捷操作不共享，必须遵循以下边界：

| 页面范围 | 列表快捷操作 |
| --- | --- |
| 全部卡牌 | 不提供任何个人数据操作；不显示拥有数量、普通卡/闪卡加减按钮或愿望单状态按钮。卡图只用于进入卡牌详情。此规则同时适用于普通 Set 卡牌列表和语法搜索结果列表；Token 卡图仅供浏览，不进入普通卡牌详情。 |
| 我的卡牌 | 支持快速编辑当前卡牌的普通卡与闪卡拥有数量；不提供愿望单快捷操作。 |
| 愿望单 | 支持快速取消或重新加入愿望单；不提供普通卡或闪卡数量编辑。 |

可复用卡牌详情页不属于上述列表快捷操作范围，仍按详情页规则提供收藏数量和愿望单管理。

我的卡牌数量加减、愿望单星标以及卡牌详情“我的收藏”中的数量和愿望单操作统一采用后端确认后更新，不执行乐观更新。用户发起请求后，当前卡位或当前详情收藏面板的全部收藏与愿望单操作热区立即禁用，显示数值和星标保持不变；返回前的再次点击不排队、不合并，也不得重复发送请求。返回成功后才更新对应数量或星标并重新启用；返回失败时原状态不变，重新启用并打开统一错误弹窗。成功后不重新请求整个列表；数量归零或愿望单取消的列表项保留到重新进入页面并取得后端权威列表时才消失。

分组列表中的系列折叠使用整条系列标头作为点击热区，最右侧箭头只提示展开状态。卡牌下方的愿望单星标和数量加减属于局部快捷操作：每个符号必须具有略大于符号本身的独立热区，但不得把整条信息栏或数量栏变成对应操作按钮。

所有具有独立正反面卡图的双面或多牌面印刷均复用同一套列表展示逻辑，不区分模式双面、转化式双面或其他双面 `layout`：只计为一个列表结果并占一个标准卡位，默认显示正面。卡牌插画区域右上角提供独立翻面按钮，避开牌名栏及法术力费用标志，并在当前卡位切换正反面；翻面操作不进入详情页、不改变后端数据。我的卡牌中各牌面共享同一份普通卡与闪卡数量，愿望单中各牌面共享同一个愿望单状态。是否使用翻面控件以当前具体印刷能否取得不同正反面卡图为准；`split`、`flip`、`adventure` 等多个规则牌面共用同一张正面卡图的单面布局不显示翻面按钮。

桌面卡图列表以 1440 × 900 为主原型，并在实现和验收阶段覆盖 1280、1366、1440 与更宽视口，不为每个尺寸复制整页设计稿。1440 px 宽度显示五列卡图；1366 px 与 1280 px 宽度根据内容区可用宽度自然降为四列。卡图固定为 244 × 340 px，横向间隔固定为 35 px；降列时网格保持左对齐并将剩余宽度留在行尾，不放大间隔、不缩放或裁切卡图。响应式实现使用流式容器、Flex/Grid 重排、媒体查询或容器查询，不得对整个页面、字体、按钮和点击热区执行等比缩放。页面主体最小布局宽度固定为 1280 px；视口低于 1280 px 时不再继续降列或重排，由浏览器提供整页横向滚动。视口高度低于 720 px 时使用浏览器正常纵向页面滚动，所有尺寸、间距与点击热区保持不变。

所有能够取得不同正反面卡图的双面或多牌面印刷，其详情页均在卡图下方提供独立的“查看反面／查看正面”按钮，不使用列表页叠加在卡图上的按钮。当前显示正面时按钮为“查看反面”，显示反面时按钮为“查看正面”。切换牌面时，卡图、中间对应牌面的翻译后语言说明及名称右上角的法术力费用符号同步切换；费用符号直接取当前选中的 `faces[]` 项之 `mana_cost`，不使用顶层 `card.mana_cost`，也不重新请求详情。面包屑保持组合名称，右侧收藏、愿望单、语言、印刷版本和卡组使用数据不变。非模式双面牌与模式双面牌完全复用该展示交互。

卡牌详情中的当前系列语言及其他版本语言统一原样展示 `scryfall_language.display_name`，并按 `scryfall_language.sort_order` 升序，顺序相同时按语言代码升序；只复用 Set 列表的语言字典顺序，不套用其“仅前 11 项”的范围限制。其他系列版本按发行日期从新到旧排列，发行日期相同时依次按 Set 缩写、收藏编号和该版本分组语言项中的最小 `printing_uuid` 升序兜底。官方释疑按 `published_at DESC, ruling_key ASC` 排列。功能标签按 `oracle_tag.tag_id` 升序。使用该牌的卡组列表按卡组 `updated_at` 从新到旧，更新时间相同时按 `deck_id` 升序。上述数组均由后端按权威顺序返回，前端直接展示，不再自行排序。

卡牌中心使用统一二级标头提供范围切换：

```text
[全部卡牌] [我的卡牌] [愿望单]
```

三个范围使用独立页面与独立路由，二级标头只负责切换，不把三种列表和操作合并到同一页面中。

## 7. 卡组列表

支持：

- 创建卡组
- 查看卡组
- 编辑卡组
- 修改卡组名称
- 复制卡组
- 复制卡组代码
- 删除卡组
- 查看更新时间
- 查看卡牌总数
- 查看异常状态
- 查看卡组统计

不进行卡组合法性校验。

卡组列表页面沿用系统统一的一级导航，并在导航下使用与“我的卡牌”二级标头相同视觉规格的 100 px 深绿色渐变身份栏：左侧显示中文标题与说明，右侧显示“新建卡组”操作。点击后以固定默认名称“新建卡组”创建空白卡组，创建成功后直接进入该卡组编辑页；编辑页顶部名称输入框显示“新建卡组”并允许立即修改，只有后续保存成功才持久化修改后的名称。该身份栏不包含二级切换按钮，不代表卡组新增二级菜单。下方单行吸顶工具栏支持按卡组名称查询，以及按最近更新、创建时间、名称或卡牌总数排序。各排序使用固定方向，不显示独立升序、降序按钮；所有主排序值相同的卡组统一按 `deck_id` 升序兜底。页面不提供异常状态筛选。

卡组以可视化信息卡片展示。桌面端卡片尺寸固定为 328 × 292 px，封面视口固定为 328 × 180 px；标准卡图等比显示为 328 × 457 px，并相对封面顶部固定偏移 `-54 px`，不同卡牌不单独调整取景。更新时间参考 Archidekt 的轻量相对时间样式，固定在封面右下角，距右侧 12 px、距底部 8 px；只显示小型时钟图标及相对时间文字，不使用胶囊、底框或色块，也不随渐变区或卡图取景位置移动。封面从 `y = 108 px` 开始叠加 72 px 高、由透明到纯白的纵向渐变，让卡图柔和淡出至六色比例带和信息区，不使用不透明横框硬切；渐变末端至少 8% 保持纯白，六色比例带容器显式使用相同纯白背景，避免渐变终点与透明后继层在裁切边缘插值形成细缝。该效果直接作用于后端生成的外部卡图 URL，不要求另存裁切图；前端必须允许对应图片 CDN，并提供加载失败占位。封面下方使用固定白、蓝、黑、红、绿、无色六类的宽度比例表达卡组颜色含量，不允许随机取色。颜色含量与详情统计采用相同范围，只统计指挥官和主牌，备牌与备选均不参与；后端返回 `W/U/B/R/G/C` 六类按 `quantity` 计权的原始张数。`W/U/B/R/G` 来自卡牌颜色，多色牌完整计入其包含的每一种颜色；颜色集合为空的牌不计入任何颜色。只有 `mana_cost` 明确包含 `{C}` 或包含 `C` 的复合符号时才按牌张数计入无色 `C`，同一张牌含多个无色符号也只计一次；前端以六类计权张数之和为分母计算比例。无色 `C` 是明确的无色法术力分类，不表示任意颜色或通用法术力。信息区显示卡组名称，分区摘要同一行右侧显示总张数；固定底栏左侧按需显示“数量不足”或“卡组占用”状态，但不显示异常项数量，无异常时不显示状态，右侧固定显示“查看卡组”。卡组列表中的每个分区数量均为该分区已保存 `quantity` 之和；总牌数固定为指挥官、主牌和备牌三个分区数量之和，备选区不计入。卡组列表的分区数量、总牌数、颜色比例、封面和异常全部使用数据库已保存状态，不读取浏览器中的未保存编辑态。整张卡片的非操作区域和“查看卡组”均按 `deck_id` 进入对应详情页；独立的更多菜单必须阻止卡片跳转，并从上到下固定提供“编辑卡组”“复制卡组”“复制卡组代码”“删除卡组”。“删除卡组”必须位于菜单最下方并使用危险色文字和删除图标；菜单不提供独立重命名。点击菜单外部立即关闭菜单。

当 `color_distribution` 的 `W/U/B/R/G/C` 六项全部为 `0` 时，前端不得计算比例或绘制任何颜色段，比例带只保留未填充的容器背景；不得把空分布显示成无色分类。

卡组列表只使用卡组已保存的封面逻辑卡。后端根据 `deck.cover_oracle_id` 按统一展示版本规则选择具体印刷并返回完整 `cover_card`，前端不自行筛选或改选；没有配置封面时 `cover_card` 为 `null`，统一显示无卡图占位，不从指挥官或主牌自动补选。

卡组列表更多菜单中的“编辑卡组”按当前 `deck_id` 进入编辑页；“复制卡组”创建内容相同的新卡组、名称设为“复制 原卡组名”，成功后进入新卡组编辑页；“复制卡组代码”将当前已保存的标准代码写入剪贴板且不跳转。复制代码成功与详情页共用不可交互、约 2.5 秒自动消失的“卡组代码已复制”提示；失败使用统一错误弹窗。“删除卡组”打开统一删除确认弹窗，不得直接删除。弹窗标题为“删除卡组？”，第一行正文为“删除后无法恢复。”，第二行解释为“该卡组记录将被永久删除。”，底部从左到右显示“取消”和危险色“删除卡组”；不设置右上角关闭按钮，点击遮罩不关闭。取消后关闭弹窗并保留卡组；确认成功后关闭弹窗和更多菜单、从当前列表移除该卡组并更新结果总数，失败时保留卡组并打开统一错误弹窗。

确认删除必须以当前 `deck_id` 为唯一目标，在同一事务中删除卡组及其全部 `deck_card` 分区牌张记录并写入“删除卡组”操作日志；任一步失败时整体回滚。操作日志保存删除发生时的卡组名称快照，不随卡组数据一并删除。

### 7.1 卡组详情

卡组详情页面沿用系统一级导航，并将深绿色渐变连续铺满整个页面，不在标头与卡牌区之间分成两段背景。页面按 `deck_id` 加载卡组；标头只显示卡组名称、总张数、相对更新时间和收集率。标头右侧从左到右固定显示“编辑卡组”“复制卡组”“复制卡组代码”“删除卡组”。前三个按钮统一使用 36 px 高、7 px 圆角、相同内边距的橙色主按钮样式，并共用橙色底和描边、深色图标文字；“删除卡组”位于并排按钮最右侧，保持相同高度和圆角，使用危险色底、描边及白色图标文字。“编辑卡组”按当前 `deck_id` 进入当前卡组编辑页面；“复制卡组”创建内容相同的新卡组，将名称设为“复制 原卡组名”，创建成功后进入新卡组编辑页面；“复制卡组代码”不跳转，将数据库中按 `About / Commander / Deck / Sideboard / Maybeboard` 分区、卡牌行仅含 `AMOUNT CARDNAME` 的标准代码写入系统剪贴板。复制成功显示 `.pen` 中 `Prototype / Copy Deck Code — Success Toast`：提示文案为“卡组代码已复制”，不设置按钮、关闭图标、遮罩或交互热区，不接受焦点，不阻断原页面操作，并在约 2.5 秒后自动淡出；复制失败使用统一错误弹窗。“删除卡组”与列表共用统一删除确认弹窗，不得直接删除；确认成功后进入卡组列表，失败时停留详情页并打开统一错误弹窗。详情页本身不提供拖拽改牌或卡图上的数量编辑。总张数和收集率统计指挥官、主牌和备牌，备选不计入。

卡牌区域不显示“卡牌堆叠”标题条，也不提供主备切换、展示方式、分组或排序控件。主牌、备牌、备选属于同一个连续详情页，不拆分为单独页面或路由；页面依次展示三个区域，每个区域左上角显示区域名称和总张数，备牌从主牌最长列结束后开始，备选从备牌最长列结束后开始。主牌区域按指挥官、神器、生物、结界、瞬间、法术、鹏洛客、地的固定类型顺序及固定列坐标展示，其中指挥官列只承载 `commander`；备牌和备选分别承载 `sideboard`、`maybeboard`，只按神器、生物、结界、瞬间、法术、鹏洛客、地排列，不显示指挥官列。当前区域不存在的类型不渲染标题、卡图或可见空占位，但后续存在的类型仍须与主牌中的同名类型垂直对齐，不得向左补位。普通七类之外的牌归入 `other`；页面不存在 `other` 牌时不渲染该列，任一可见区域出现时在地之后追加最右侧“其他”列，并由三个区域共同保留该列坐标。每个区域的类型列必须保持在同一横行且禁止换行；1440 px 桌面端使用 158 px 类型列宽和 14 px 列间距，使默认主牌八种类型完整显示在内容区内。动态增加“其他”列后，可用宽度足够时内容区向右扩展，不足时保持列宽和间距并在当前区域启用横向滚动；不得换行、压缩卡图或缩小交互目标。在 1280 px 及以上视口中，内容区不足时可在当前区域内部横向滚动作为降级方案，此时不触发整页横向滚动；低于 1280 px 时改为同时遵循后述全局最小宽度规则。前端对同一区域、同一类型列内的牌固定按法术力值 `mtgnissa_card.cmc` 从低到高、颜色组合顺序、英文卡名不区分大小写 A–Z、`printing_uuid` 升序的优先级排序，并在首次加载及每次编辑后重新执行。颜色组合先按颜色数从少到多，再按 WUBRG 色环顺序细分：单色 `W、U、B、R、G`；双色 `WU、UB、BR、RG、GW、WB、UR、BG、RW、GU`；三色 `WUB、UBR、BRG、RGW、GWU、WBG、URW、BGU、RWB、GUR`；四色 `WUBR、UBRG、BRGW、RGWU、GWUB`；五色 `WUBRG`；无色 `C` 最后。排序不得改变卡牌所属区域或类型列。

在 1280 × 720 等不足以完整容纳默认八列的常用桌面视口中，各列仍保持 158 px 列宽、14 px 间距及固定列坐标，主牌、备牌和备选分别使用自身的横向滚动区域查看右侧类型；动态出现的第九个“其他”列遵循相同规则。不得换行、压缩卡图或等比缩放整个页面。该规则不要求维护单独的 1280 设计画板。视口低于 1280 px 时，除类型区域自身的滚动能力外，页面还按全局最小宽度规则产生浏览器整页横向滚动。

卡组详情和卡组编辑页面必须在牌张悬浮时于卡牌侧边显示翻译信息气泡，内容只包括翻译后语言的卡牌名、类别和规则文字。气泡复用卡牌详情页的信息面板视觉，不得使用卡组页的深色异常提示样式。桌面端宽度固定为 300 px，高度由翻译后的卡牌名、类别和规则文字自动撑开；文本增加时只允许向下扩展，不得横向增宽、截断内容或建立内部滚动条。当前样例内容高度约 164 px。主体使用白色纸张底、`#D7DBD6` 边框、12 px 圆角与轻阴影；正文颜色为 `#18201D`，字段小标题为 `#7A8580`。卡牌名使用 16 px 标题；类别和规则文字分别显示灰色字段标题及 12 px 常规正文，规则文字保留换行及符号顺序。气泡默认位于卡牌右侧并以尖角指向卡牌，空间不足时自动翻转到左侧，必须限制在视口内并覆盖于所有牌列之上；气泡不承载操作，也不得阻挡卡牌点击、局部按钮或拖拽。

卡组详情页的气泡只随鼠标悬浮显示，离开对应卡牌后隐藏，卡牌点击仍进入卡牌详情。卡组编辑页的气泡同时响应鼠标悬浮和点击固定看牌：卡牌被点击固定后，气泡在鼠标移开后继续显示；再次点击同牌、切换固定目标或牌张被移除时同步隐藏。临时悬浮其他牌不得自动取消已固定牌张。

桌面端卡图固定为 150 × 210 px，收起状态的纵向叠距固定为 30 px，必须完整露出每张牌的牌名栏，不能只露出边框或颜色条。卡牌左上角使用覆盖卡角的低饱和中深绿色三角形数量标志（原型色 `#426B59`），只比页面深色底色略亮。三角标铺到卡位最外缘，并与卡位共用同一个 8 px 圆角裁切：必须保留左上角圆弧，但三角标与圆弧之间不得残留额外的黑色描边圈。数字使用浅色、`900` 字重。标志内容为该牌在当前区域的 `deck_card.quantity`，不得使用纯黑、高亮薄荷绿、方形或圆角矩形徽标，也不是法术力值或拥有数量。鼠标移入第 i 张牌时，其后的牌整体下移 180 px，完整露出当前卡图；移出后恢复 30 px 叠距。点击卡图进入后端为该卡组牌张选定的具体印刷版本详情页。印刷版本固定按“拥有版本 → 愿望单版本 → 最新印刷版本”选择；同一优先级存在多个候选时先取发行时间最新者，发行时间相同时按 `printing_uuid` 升序兜底。

关闭状态下，网页右侧固定显示“卡组统计”书签。桌面端书签固定为 38 × 118 px，文字按“卡／组／统／计”单列竖排，图标为 15 px；书签相对浏览器视口固定在 `y = 310 px`，不随卡组卡牌页面纵向滚动，也不占用卡牌列宽度。点击后从右侧打开深绿色长抽屉，不使用居中弹窗，也不创建独立页面或路由。1440 px 桌面原型中抽屉宽 1080 px，左边缘为 `x = 360 px`，右边缘贴住视口。刚打开时抽屉顶部为 `y = 150 px`，在视口上方保留 150 px 模糊背景，不依据 Deck Detail Header 高度开始，也不要求初始底部贴边。

背景模糊层覆盖整个视口，显示抽屉左侧、初始顶部及滚动到底后的底部背景。抽屉打开期间必须锁定底层卡组页滚动并阻止点击、悬浮、拖拽、滚轮、触控滑动及键盘滚动穿透遮罩；点击任何未被抽屉覆盖的模糊背景关闭，并恢复原滚动位置。点击打开时，书签只做水平向左移动，从浏览器右侧移动到抽屉左边缘；初始打开状态的屏幕绝对高度仍为 `y = 310 px`，不得上下跳动。完成水平打开后，书签成为抽屉结构子元素并与抽屉一起滚动，允许滚出视口；再次点击书签也可关闭。不显示右上角关闭叉或其他关闭按钮。

滚动范围为抽屉所属的整个统计遮罩页，不是底层卡组页，也不是抽屉内部的第二层独立滚动容器。所有滚动输入只驱动统计遮罩页，底层卡组页必须保持打开前的位置不动。向下滚动时长抽屉整体上移并覆盖初始顶部模糊背景；滚动到底时抽屉底边停在 `y = 750 px`，在视口底部露出 150 px 模糊背景。初始顶部与最终底部露出的模糊背景高度必须相同。抽屉最右侧必须显示整个统计遮罩页的滚动条；刚打开状态滑块位于顶部，滚到底状态滑块位于底部，该滚动条不代表抽屉内部另有一层滚动。

抽屉说明固定为“统计主牌 · 备牌、备选不计入”。统计范围只包含主牌；指挥官牌属于主牌并参与统计，备牌和备选均不参与。所有指标按 `quantity` 计权。内容包括平均法术力值、地牌张数、费用颜色与产费颜色、六色明细、0 至 8+ 的整体法术力曲线、按颜色／类型／功能标签拆分的子曲线、抽到概率表格和数量分布柱状图；不显示总法术力值。整体法术力曲线及其分组子曲线排除 `statistics.is_land = true` 的牌，0 至 8+ 九个档位横向铺满统计内容宽度，标题右侧不额外显示“不含地牌”，同一行不并排放置类型分布块。费用颜色从 `mana_cost` 汇总，对应颜色费用比例为该颜色费用点数除以白、蓝、黑、红、绿、无色六类费用点数总和；混血、非瑞克西亚及其他复合符号按其中包含的全部 `W/U/B/R/G/C` 颜色分别各计 1 点，例如 `{W/U}` 同时计入白和蓝，`{W/P}` 与 `{2/W}` 均计入白。只有专门的 `{C}` 或包含 `C` 的复合符号计入无色；通用数字、`X/Y/Z`、非颜色组成部分及“任意颜色”不进入无色。产费颜色从 `produced_mana` 汇总，并按相同方式使用对应颜色产费点数除以六类产费点数总和；同时包含多个值时分别计入，只有明确包含 `C` 才计入无色，任意颜色不得自动映射成 `C`。费用点与产费点均按 `quantity` 计权。六色明细固定压缩为同一行，依次显示 Scryfall 法术力图标、费用比例条、“x点·x张”、产费比例条和“x点·x张”。颜色块是否降低透明度只按费用点数判断：该颜色费用点数为 0 时整个颜色块降透明度，产费点数为 0 不单独触发。“张”为统计范围内至少包含一个对应费用点或产费点的卡牌数量，按 `quantity` 计数。平均法术力值默认排除地牌。法术力颜色使用固定六色色板：白色 `#FBF6D3`、蓝色 `#96C4D4`、黑色 `#B0A8A3`、红色 `#D88F73`、绿色 `#93CBA4`、无色 `#A9A8A8`。白、蓝、黑、红、绿取自 Archidekt `aang` 页面，无色取自 `eldrazi` 页面；卡组列表六色比例带共用同一色板，不得使用系统主题色或随机色替代。法术力曲线强调色为 `#FA890D`。法术力图标使用 Scryfall 符号表：`W/U/B/R/G` 为五种有色法术力，`C` 是具有专门符号并作为第六类统计展示的无色法术力；无色、通用费用和任意颜色是三个不同概念，不得互相代替。基础符号可按 `https://svgs.scryfall.io/card-symbols/{symbol}.svg` 拼接，复杂符号按 `/symbology` 返回的 `svg_uri` 映射。卡牌详情名称右上角同样按 `mana_cost` 的符号顺序显示这些图标，不显示花括号纯文本；双面牌切换牌面时同步切换费用图标。页面不展示价格、浏览量、社区作者、热度或赛制合法性。

卡牌摘要中的 `cmc`、`mana_cost`、`colors`，以及卡组统计中的 `cmc`、`mana_cost`、`colors`、`produced_mana`，均使用具体展示印刷的主牌面：普通单面牌取 `face_index = -1`，多牌面牌取 `face_index = 0`。`is_land` 不使用该单面规则，只要逻辑卡任一牌面的英文 Oracle 主类型包含 `Land` 就为 `true`；因此一面为法术、一面为地的多牌面牌整体从平均法术力值和法术力曲线中排除。多牌面类型集合仍按全部牌面合并，不受本段主牌面取值规则影响。

整体法术力曲线下方紧接“法术力曲线分组（Mana curve by）”模块。模块标题与选择器位于同一行，标题在左侧，分组下拉固定对齐到右上角，与抽到概率和数量分布的筛选位置保持一致。该模块使用单个下拉选择器，依次支持“类型”“颜色”“功能标签”，默认选择第一个“类型”，不得把三个维度同时显示为三个固定图表。每个分组值渲染一个 0 至 8+ 的子曲线框，桌面端一行最多 6 个，超过 6 个自动换行。颜色视图固定按白、蓝、黑、红、绿、无色展示并使用对应法术力颜色；类型和功能标签视图只展示当前统计范围实际存在的分组，使用统一的曲线强调色。子曲线沿用主牌范围、排除地牌规则和 `quantity` 计权；类型使用系统稳定顺序。功能标签通过牌张的 `oracle_id` 关联 `oracle_tag_mapping` 和 `oracle_tag`，统计当前范围内全部非地牌实际具有的全部标签，不按 `weight` 过滤；同一张牌具有多个标签时分别计入每个对应标签，因此不同标签的统计不是互斥分组。每个标签的牌张数量为关联该标签的非地牌 `quantity` 之和，按牌张数量从高到低排序，数量相同时按标签名称稳定排序。功能标签视图默认展示前 12 个标签；只有实际标签数超过 12 个时才在列表底部显示“显示全部”，展开后展示剩余全部标签并将操作改为“收起”，收起后回到前 12 个。展开内容直接增加统计抽屉长页高度并沿用整页滚动，不建立子区域滚动条。

颜色子曲线、颜色数量分布与列表 `color_distribution` 使用同一归类规则：`W/U/B/R/G` 按牌面颜色统计；颜色集合为空不进入任何颜色；只有 `mana_cost` 明确包含 `{C}` 或包含 `C` 的复合符号时才按 `quantity` 进入无色，同一张牌含多个无色符号也只计一次。

“法术力曲线分组”下方显示“抽到概率（Probability of draw）”表格。条件栏固定使用“至少 x 张”的概率语义，不提供“恰好”等模式切换；默认条件为“至少 1 张，抽 7 张”。“至少张数”和“抽牌张数”均使用紧凑的减号、数值、加号步进控件，并允许直接输入整数；至少张数最小为 1，抽牌张数最小为至少张数、最大为当前统计范围的总张数，减号到达下限后置灰。分组下拉提供“类型”“法术力值”“功能标签”“产费颜色”，默认选择“类型”。条件栏左侧依次显示“抽到概率　至少 [x] 张　抽 [n] 张”，分组下拉独立对齐到条件栏最右侧；不在分组下拉前显示“按”。

所有统计分类选择器统一使用全局优先顺序“类型 → 颜色 → 法术力值 → 功能标签 → 产费颜色”。每个模块仅从该顺序中保留自己支持的选项，并默认选中保留选项中的第一个；不得为单个模块另设不同排序或记忆上次选择作为初始值。设计稿用四份完整统计状态覆盖选择器内容：默认“类型／类型／类型”、组合“颜色／法术力值／颜色”、功能标签“功能标签／功能标签／功能标签”、产费颜色“类型／产费颜色／类型”，三项依次对应法术力曲线分组、抽到概率、数量分布。

法术力曲线分组的子曲线卡片使用固定列宽，桌面端每行最多 6 个；末行不足 6 个时左对齐并保持与首行相同宽度，不得拉伸填满剩余空间。模块外框按实际内容行数自适应高度，颜色分组固定六项一行时必须收缩为单行高度。抽到概率选择“功能标签”时默认显示排序后的前 12 个，实际标签超过 12 个时显示“显示全部”；展开后显示全部并改为“收起”，使用统计抽屉整页滚动，不建立表格内部滚动。数量分布只有功能标签为容纳最多 24 项使用窄柱；类型和颜色按实际分组数均分横向空间并使用更宽的柱体。

卡组统计抽屉的整个外框及其内部纵向内容必须使用内容驱动高度，不得设置固定总高度，也不得为了对齐不同选择器状态而在底部保留空白。任一模块因选择器切换、功能标签展开或收起而改变高度时，抽屉外框同步扩展或收缩，并保持既定模块间距和底部内边距。统计遮罩页的总滚动长度由抽屉当前实际高度计算，但必须沿用原滚动边界：初始位置的抽屉顶部固定为 `y = 150 px`，滚动到底时抽屉底边固定为 `y = 750 px`。内容高度变化只改变两者之间的最大滚动距离，不得改变顶部或底部露出的 150 px 模糊背景。

表格列为当前分组名称、“牌张数”和“概率”。牌张数按 `quantity` 计权；概率使用不放回抽样的超几何分布计算在总牌数 `N`、该行牌张数 `K`、已抽张数 `n` 下至少抽到 `x` 张的概率。计算范围继续沿用主牌加指挥官、排除备牌与备选的统计口径。类型统计直接使用每张牌的 `statistics.type_groups`，按神器、生物、结界、瞬间、法术、鹏洛客、地、其他的系统展示顺序列出实际存在的分组；不得改用单值 `type_group`，多类型或多牌面牌可以同时计入多个类型统计行。法术力值按 `cmc` 从 0 到 8+ 展示实际存在的档位；功能标签使用 `oracle_id → oracle_tag_mapping → oracle_tag`，按牌张数从高到低、标签名称稳定排序，默认显示前 12 个，实际标签超过 12 个时显示“显示全部”，展开后显示全部并改为“收起”。产费颜色从 `produced_mana` 读取，固定按白、蓝、黑、红、绿、无色、不产费显示七行，包括数量为 0 的颜色；颜色行的 `K` 表示能够产生对应颜色法术力的牌张数量，不使用产费点数，一张牌能够产生多种颜色时分别计入每个对应颜色行。`produced_mana` 为空或不存在的牌按 `quantity` 计入“不产费”，并且不进入前六个颜色行。多类型牌、多标签牌及多色产费牌均可能分别计入多个关联行，因此各行牌张数与概率均为独立统计，不能跨行相加。任一条件改变时前端立即重新计算并刷新整张表格，不重新请求卡组数据。

抽到概率表格下方显示“数量分布（Quantity of）”图表。标题位于左侧，分组下拉位于同一行最右侧，提供“类型”“颜色”“功能标签”，默认选择“类型”。数量均按 `quantity` 计权。类型和颜色使用纵向柱状图，柱高与柱顶数字表示牌张数量，横轴显示分组名称；类型使用与概率表格相同的主类型口径和系统顺序。颜色固定按白、蓝、黑、红、绿、无色顺序并使用既定六色色板：`W/U/B/R/G` 按牌面颜色统计，多色牌分别计入其具有的每一种颜色；颜色集合为空的牌不计入任何颜色；只有 `mana_cost` 明确包含 `{C}` 或包含 `C` 的复合符号时才按牌张数计入无色，同一张牌含多个无色符号也只计一次。

功能标签同样使用纵向柱状图。标签按牌张数量从高到低排列，数量相同按标签名称稳定排序，只显示排序后的前 24 个；超过 24 个的标签不渲染，也不提供展开、第二行或内部滚动。24 根窄柱固定在同一行并共用同一纵轴比例。每根柱顶显示牌张数，柱底标签允许最多三行换行并保持居中，不旋转文字；超出标签区域的名称省略，完整内容通过悬停提示显示。多类型、多色和多标签分组均可能重复计入同一张牌，各项之间不能求和作为卡组总张数。切换分组只在前端重组已加载的统计数据，不重新请求卡组数据。

## 8. 卡组编辑

卡组代码的卡牌行输入格式固定为：

```text
AMOUNT CARDNAME (SETCODE) NUMBER *F*
```

`AMOUNT` 是正整数数量，`CARDNAME` 是卡牌名称；`(SETCODE)`、收藏编号 `NUMBER` 和闪卡标记 `*F*` 都是可选输入。以下写法均可读取：

```text
1 Counterspell (CMR) 632 *F*
1 Sol Ring
1 Arcane Signet *F*
```

点击“读取卡组配置”时，系统只使用数量、卡名和所在分区建立卡组编辑记录；Set 代码、收藏编号和 `*F*` 只作为允许存在的输入信息，解析后全部忽略，不得用于指定卡组中的具体印刷版本、语言或工艺。卡名由后端直接按 `mtgnissa_card` 的标准英文名称解析为非空 `oracle_id`；无法唯一识别或无法识别的卡名必须明确提示并中止本次读取，不得静默丢弃、模糊猜测或部分覆盖当前编辑内容。命中记录没有 `oracle_id` 时整次读取失败并定位原代码行，不以印刷 UUID 替代 Oracle 身份。重复卡牌行在同一分区内合并并累加数量，跨分区记录保持独立。

读取完成后的展示印刷版本继续由后端按“拥有版本 → 愿望单版本 → 最新印刷版本”选择；同一优先级存在多个候选时按发行日期从新到旧，再以 `printing_uuid` 升序兜底。前端不得根据导入代码中的 Set、收藏编号或闪卡标记选择版本。

卡组代码使用以下固定英文分区标题，标题独占一行，标准顺序不得调整：

```text
About
Name Jace upgraded

Commander
1 Jace, Multiverse Architect

Deck
1 Absolute Virtue

Sideboard
1 Vexing Bauble

Maybeboard
1 Example Card
```

- `About` 是元数据区；其合法、非空且未超出名称长度上限的 `Name ` 后文本是卡组名称，读取成功时同步更新编辑页顶部的卡组名称输入框。没有 `Name ` 行、`Name ` 后为空白或名称超出长度上限时，解析响应的名称为 `null`；这只表示没有有效名称覆盖，不影响卡牌解析，也不得导致读取失败。前端此时必须保留读取前的当前名称输入值，不得清空或回退为已保存名称。
- `Commander` 写入指挥官分区。
- `Deck` 写入主牌分区，不包含已列入 `Commander` 的牌。
- `Sideboard` 写入备牌分区。
- `Maybeboard` 写入备选区。
- 没有任何分区标题的纯卡牌列表兼容按 `Deck` 主牌读取。出现分区标题后，卡牌行必须归属于已识别的卡牌分区；未知标题必须报错，不得默认归入主牌。
- 空行允许存在并在解析时忽略。标准保存结果固定使用上面的标题大小写和顺序；除 `About` 与 `Deck` 外，没有牌张的卡牌分区可以省略。

卡组只允许加入具有非空 `oracle_id` 的普通卡牌；正式候选、名称联想、上下文、代码导入及保存均保持此约束，Token 不允许加入卡组。卡组数据库仍以 `oracle_id + 分区 + 编辑数量` 为卡牌事实来源，不要求用户指定 Set、收藏编号、语言、普通／闪卡或展示版本。

卡组必须记录每张牌所属的分区，并按分区展示。至少支持：

- 主牌（mainboard）
- 备牌（sideboard）
- 指挥官（commander）
- 备选区（maybeboard）

同一逻辑卡牌可以分别出现在多个分区；每个分区内只保留一条数量汇总。分区在卡组中的展示顺序必须稳定。

卡组牌张同时保留两个职责不同的类型字段。单值 `type_group` 只用于固定牌列归类，枚举为 `land`、`creature`、`planeswalker`、`instant`、`sorcery`、`enchantment`、`artifact`、`other`；多值 `statistics.type_groups` 用于卡组统计。后端必须先合并同一逻辑卡全部牌面的英文 Oracle 类型，去重收集命中的地、生物、鹏洛客、瞬间、法术、结界、神器类型；全部牌面均未命中时使用 `other`。双面牌按全部牌面的复合类型参与判断。`type_group` 再按 `land → creature → planeswalker → instant → sorcery → enchantment → artifact → other` 取第一项；前端不得自行解析类别栏或重新推导。指挥官分区忽略 `type_group` 的当前位置，始终显示在指挥官列，但仍保留两个字段供统计和移出指挥官区后归列。

分区为系统固定类型，不支持用户创建、重命名、删除或调整分区顺序。数据与 API 始终保留 `commander`、`mainboard`、`sideboard`、`maybeboard` 四个真实分区。界面只展示主牌、备牌、备选三个可见区域：主牌区域同时承载 `commander` 与 `mainboard`，其中 `commander` 只进入固定的指挥官列，`mainboard` 进入其余类型列；备牌和备选区域分别对应 `sideboard` 与 `maybeboard`。视觉上处于同一主牌区域不得改变两者的真实分区身份。

`commander` 分区允许为空，创建、编辑、保存及代码导入均不得要求卡组至少包含一张指挥官；标准代码中没有指挥官时可以省略 `Commander` 段。本期允许传奇生物、传奇鹏洛客和传奇载具进入 `commander` 分区。卡组相关详情与编辑上下文 DTO 必须返回业务资格字段 `can_be_commander`，不得改为仅表示“是否传奇”的属性字段：后端仅在同一个卡面的英文 Oracle 类型栏包含 `Legendary`，并同时包含 `Creature`、`Planeswalker`、`Vehicle` 三个类型词元中的至少一个时返回 `true`；不得跨不同卡面合并类型词元，也不得由前端解析翻译类型或英文类型栏。该字段只表达本期进入指挥官区的资格，不代表完整的 Commander 赛制合法性。

主牌、备牌和指挥官计入卡组总张数与拥有量比较；备选区只用于展示候选牌，不计入这两项结果。卡组统计使用独立范围，只统计主牌；指挥官属于主牌中的固定类型并参与统计，备牌和备选均不参与卡组统计。

保存卡组时必须以当前可编辑卡组名称、封面逻辑卡以及指挥官、主牌、备牌、备选区的真实内容重新生成标准代码。封面选择单独保存到 `deck.cover_oracle_id`，不写入卡组代码。`About` 区写入 `Name DECKNAME`；每个卡牌分区中的行只保存 `AMOUNT CARDNAME`，不得保存导入时携带的 `(SETCODE)`、收藏编号或 `*F*`。区内先按固定类型列顺序输出，`other` 位于地之后；同一类型列内按法术力值、颜色、英文卡名、`printing_uuid` 升序的既定优先级输出；分区之间保留一个空行。数据库保存该标准化代码；文本框中的原始导入文本不得直接入库。

## 9. 卡组展示版本

卡组不支持手动指定印刷版本。前端候选、上下文、导入响应和编辑提交均使用后端返回的主牌面 `printing_uuid`；封面版本引用字段为 `cover_printing_uuid`，保存时由后端解析并校验 Oracle 身份。

系统自动选择展示版本：

```text
拥有的版本
    ↓
愿望单版本
    ↓
最新印刷版本
```

自动选择只决定卡组展示的卡图和印刷版本，不影响卡组记录。

选择版本时不考虑：

- 是否被其他卡组使用
- 所有卡组使用总数
- 当前卡组编辑数量
- 拥有数量是否足够
- 可用数量或分配数量

具体印刷版本由后端在查询卡组数据时选择，前端只消费选择结果，不自行执行版本筛选，也不向用户暴露逻辑卡概念。同一优先级存在多个候选时，选择发行时间最新的版本；发行时间相同时按 `printing_uuid` 升序兜底。本阶段只固定规则，后端筛选逻辑留待开发阶段实现。

## 10. 卡组拥有数量

卡组中的实际拥有数量按逻辑卡牌汇总：

```text
所有 Set
+ 所有语言
+ 普通卡
+ 闪卡
```

每张卡计算：

- 当前卡组编辑数量
- 实际拥有数量
- 所有卡组编辑总数
- 使用该牌的卡组数量

## 11. 卡组异常状态

正常情况不显示状态。

异常状态互斥，只显示优先级最高的一项：

```text
数量不足
    ↓
卡组占用
    ↓
正常无标识
```

### 11.1 数量不足

条件：

```text
当前卡组编辑数量 > 实际拥有数量
```

显示：

```text
数量不足 N
```

计算：

```text
N = 当前卡组编辑数量 - 实际拥有数量
```

### 11.2 卡组占用

仅在当前卡组不存在“数量不足”时判断。

条件：

```text
使用该牌的卡组数量 > 1
且
所有卡组编辑总数 > 实际拥有数量
```

显示：

```text
卡组占用 N
```

计算：

```text
N = 所有卡组编辑总数 - 实际拥有数量
```

### 11.3 判断顺序

```text
if 当前卡组数量 > 实际拥有数量
    显示「数量不足」
else if 使用卡组数 > 1
     且所有卡组数量 > 实际拥有数量
    显示「卡组占用」
else
    不显示状态
```

### 11.4 示例

实际拥有 4 张：

| 当前卡组 | 所有卡组合计 | 使用卡组数 | 显示 |
| ---: | ---: | ---: | --- |
| 5 | 8 | 2 | `数量不足 1` |
| 4 | 8 | 2 | `卡组占用 4` |
| 3 | 6 | 2 | `卡组占用 2` |
| 2 | 4 | 2 | 不显示 |
| 4 | 4 | 1 | 不显示 |

异常状态不影响卡组保存和自动版本选择，不执行实体卡分配，只用于提示和统计。

卡组列表与卡组详情必须共用同一异常名称、色相和图标语义，但列表不复制详情页的深色背景。卡组列表的两类标识均不使用背景或描边，只显示文字和图标：数量不足使用红色文字及警告图标，卡组占用使用琥珀色文字及叠层图标。卡组列表只显示异常类型，不显示异常项数量。“查看卡组”固定在卡片右下角，并通过底栏弹性占位保持位置；异常标识隐藏时也不得左移。

区域标题中的异常汇总采用紧凑文案“数量不足 x种·缺x张”和“卡组占用 x种·缺x张”，数字与“种”“张”之间不增加空格。统一的 144 px 汇总框必须至少支持“种”和“缺”同时为三位数；超过三位数时再使用千位缩写或悬停完整值，不得通过临时扩大其中一类汇总框破坏宽度一致性。

两种牌张状态使用各自的悬停提示，均只展示当前卡组数量、实际拥有数量、所有卡组编辑总数和使用卡组数四项指标，不增加结论行。提示框固定为 232 × 92 px，其指标区可用宽度为 204 px；四列间距统一为 10 px，“所有卡组合计”列固定为 48 px，其余三列各为 42 px，标题不得溢出或换行。提示框从对应状态页签向卡牌列内部展开，渲染层级高于所有卡牌与类型列，不得被相邻或后续类型列遮挡。提示框及连接箭头必须随页签位置同步移动，箭头中心始终与页签保持同一水平基准。提示框四角统一保持 8 px 圆角，连接箭头由对应侧边框直接向外突出：尖头保持 6 × 12 px，不伸入气泡内部；尖端向状态页签内部重叠 2 px。箭头内部使用提示框底色，仅描绘两条状态色斜边，不描绘贴近提示框的竖直底边；侧边遮罩必须覆盖完整的 12 px 连接高度，气泡边框上下不得露出 1 px 短线，连接处不得出现突出边或 `|` 形分隔线。箭头渲染在页签边框上层，以遮住重叠位置的一小段页签边框。不得使用纯状态色实心三角、旋转方块或双重描边。

卡组详情中的指挥官、主牌和备牌必须在牌张级直接展示上述异常。状态标识使用贴在卡牌右侧外缘的 `12 × 22 px` 图标页签，页签顶部距卡图顶部 7 px。卡位必须拆成外层卡位与内层卡图：内层 150 × 210 px 卡图保持 8 px 圆角裁切，使左上角数量三角标服从同一圆角；页签由外层卡位承载并伸入相邻类型列留白，不受卡图裁切。页签贴卡牌的左侧边不显示描边，仅保留上、右、下三边及右侧圆角，使页签与卡牌连续连接；页签不得覆盖牌名、右上角费用或左上角数量三角标。数量不足使用暗红色警告页签，卡组占用使用暗琥珀色叠层页签。所有卡图均不显示外边框，异常状态不得通过卡图描边表达。页签本身不显示长文字，悬停时显示“数量不足 N”或“卡组占用 N”，并提示四项数量明细；点击状态页签不得触发卡牌详情跳转。

卡组编辑页整体复用卡组详情页的背景、顶部导航、主牌、备牌、备选类型列、卡牌堆叠、异常状态和卡组统计书签。卡组名称在编辑页改为可编辑输入框；标头摘要保留总张数和收集率但去除更新时间。标头右侧从左到右显示“增加卡牌”“选择封面”“保存卡组”，普通编辑态下三个按钮统一使用 36 px 高、7 px 圆角、相同水平内边距和相同橙色主按钮样式；进入封面选择模式后，仅“选择封面”改为深绿底、橙色描边和橙色图文的反色状态，用于表示当前模式。三个按钮必须在 Full Page、增加卡牌悬浮窗背景、代码折叠和离开确认弹窗背景等全部编辑页画板中保持一致；编辑页不得显示“复制卡组”或“复制卡组代码”。点击“选择封面”只在当前编辑页原地切换模式，不跳转页面、不打开弹窗、不新增提示区，也不改变卡组代码区、卡牌区域或任何既有布局；此时卡组内四个分区的卡牌都可选择，点击卡图只把该卡牌的 `printing_uuid` 记录为本地 `cover_printing_uuid` 并退出选择模式，不执行固定看牌、拖拽或详情跳转；选择模式下按 Esc 或再次点击按钮取消且保留进入前选择。已选逻辑卡在所有分区中的卡图使用 3 px 橙色高亮描边，不增加右上角或右下角标签，避免遮挡费用、卡名和异常页签；同一逻辑卡跨分区出现时高亮同步。封面按钮和高亮只在编辑页生效，卡组详情页不得显示封面按钮或指出哪张牌被选作封面。移除该逻辑卡在全部分区中的最后一条记录时自动清空本地封面选择，不自动改选其他卡；无卡组牌时“选择封面”禁用。“增加卡牌”打开当前编辑页的增加卡牌悬浮窗。“保存卡组”是编辑页唯一的入库入口：前端提交当前 `cover_printing_uuid`，把主牌可见区域中的指挥官列还原为 `commander`、其余类型列还原为 `mainboard`，并与 `sideboard`、`maybeboard` 一起提交四个真实分区；各卡牌及封面都只提交后端返回的 `printing_uuid`，由后端解析并校验对应 `oracle_id`、重新生成标准格式卡组代码并保存。成功后跳转到当前卡组详情页，失败时停留在编辑页、保留当前页面修改并打开统一错误弹窗。

卡组编辑页不提供草稿、临时保存或自动保存。名称、封面选择、数量、分区及代码导入造成的变化只保存在当前页面会话中，只有点击“保存卡组”且提交成功后才写入后端。当前页面存在尚未成功保存的修改时，用户通过网站一级导航、卡组相关标签或其他站内入口离开当前编辑路由，必须先显示固定在当前浏览器视口中央的离开确认弹窗。弹窗使用不带背景模糊的半透明暗色阻断遮罩；打开期间锁定底层页面滚动和全部交互，点击遮罩不得关闭弹窗或触发底层导航。弹窗只提供“继续编辑”和“放弃修改并离开”：前者关闭弹窗并保留当前页面修改，后者丢弃全部未提交修改并继续执行原导航。保存成功后的详情页跳转不触发确认；没有修改，或最近一次保存成功后尚未产生新修改时，离开页面也不显示确认。

点击“增加卡牌”必须在当前卡组编辑页上方打开增加卡牌悬浮窗，并使用半透明暗色遮罩阻止背景交互；该遮罩只压暗底层页面，不使用背景模糊。Full Page 长画板只用于摊开展示完整页面，不代表实际浏览器高度。遮罩必须固定覆盖当前浏览器视口；桌面端悬浮窗必须固定在当前视口中央并保持 940 × 702 px，不得按页面原位置定位，也不得随搜索结果数量改变位置、尺寸。悬浮窗打开期间必须锁定底层卡组编辑页滚动，并阻止点击、拖拽、滚轮、触控滑动及键盘滚动穿透遮罩。整体沿用卡牌详情页的纸张底色、白色内容面、浅灰边框和圆角视觉。悬浮窗标题与搜索区保持固定，搜索结果使用固定高度的内部滚动视口；滚动只发生在该结果视口中，不得带动背景编辑页。关闭按钮必须固定在悬浮窗最右上角，不得紧跟标题排列；悬浮窗只能通过该关闭按钮关闭，点击悬浮窗之外的遮罩或底层页面不关闭，也不得触发底层操作。关闭悬浮窗不得撤销已经加入主牌区的牌张，并应恢复打开前的编辑页滚动位置。

在 1280 × 720 常用桌面视口中，增加卡牌悬浮窗继续保持 940 × 702 px，水平和垂直居中，上下各保留 9 px 安全空间；不得为了增加外边距而压缩十行结果视口。该行为通过响应式约束实现，不维护单独的 1280 设计画板。低于 720 px 可视高度时不得整窗等比缩放，固定使用 `max-height: calc(100vh - 18px)` 并由悬浮窗内部滚动；底层页面保持锁定。

增加卡牌搜索框与正式查询状态分离，查询字段为 `mtgnissa_card_printing.printed_name`。输入、粘贴或删除文字不自动执行 `%q%` 查询；点击右侧“搜索”按钮才提交当前关键字。按钮不设最小长度或字符类型限制，空白或省略关键字表示不加名称条件，仍可查询全部可加入卡组的候选；关键字去除首尾空白后最长 512 个 Unicode 字符。按钮使用与“加入”一致的浅灰 Stepper 风格，不使用突兀的主按钮颜色；同一查询进行中锁定按钮，避免重复提交。尚未提交的新输入不清空上次正式结果，新查询成功后才替换结果、更新计数并重置结果视口。

输入至少包含 3 个英文字母（`A–Z/a–z`），或至少包含 2 个中文汉字（Unicode Han）时，短暂防抖后自动执行 `printed_name LIKE 'q%'` 前缀联想，两个门槛均含等号；数字、空格及标点不计入门槛，中英文混合输入分别计数、满足任一门槛即可。只保留基础卡面 `oracle_id` 非空的名称，按相同的不区分大小写口径去重、名称升序及原值稳定兜底，最多返回 5 个非空名称。门槛不足或输入为空时关闭联想，后端返回空列表且不执行联想查询；过期响应不得覆盖当前输入的结果。

联想下拉框覆盖在输入框下方并处于可见内容上层，与输入框同宽，使用与弹窗一致的白底、边框和深色文字，不改变弹窗或正式结果区尺寸。点击联想项时回填完整名称、关闭联想，并立即以该名称执行与按钮相同的 `%q%` 正式搜索。联想本身不替换正式结果。原型将联想与结果行悬停气泡画在同一画板只是展示两个独立状态，不要求实际同时出现。正式包含搜索是用户主动、低频触发的查询，当前直接实现，不要求额外搜索引擎；`printed_name` 前缀索引用于联想。

增加卡牌悬浮窗从语言印刷名称命中候选，只保留非空 Oracle 并按逻辑卡组织正式结果；搜索结果必须按 `oracle_id` 去重，不得将不同系列、语言或印刷版本展开成重复结果。去重后固定按英文卡名不区分大小写 A–Z 排序，同名时按 `oracle_id` 升序兜底；排序由后端执行，服务端游标必须延续该复合顺序。结果数量统一显示“找到 N 张”，不得显示“逻辑卡”字样。结果列表不得显示“卡牌／数量／操作”等说明表头；每行固定高 58 px，结果视口固定高 580 px并始终预留 10 条结果的显示高度，左侧只显示常规字重的翻译后卡牌名，不加粗且不额外显示类别。结果不足 10 条时保留剩余空白，悬浮窗和结果视口不得收缩。结果不显示页码按钮；用户在结果视口内向下滚动并接近已加载内容底部时继续请求下一批结果，并追加到现有列表，直至全部加载完成。超出可视数量时只滚动悬浮窗内部的结果视口。鼠标悬浮结果行时，直接在悬浮窗结果区域上层显示“卡图 + 翻译信息”的复合气泡，不得为气泡预留左侧栏或空白。气泡固定宽 440 px，高度由翻译文字自然撑开；右侧信息区必须限定宽度并自动换行，卡牌名、类别和规则文字均不得越出气泡。左侧为后端按“拥有版本 → 愿望单版本 → 最新印刷版本”选定的完整代表性卡图，右侧沿用卡牌详情页信息面板视觉；前端不得自行筛选具体印刷版本。离开结果行后隐藏。复合气泡只覆盖视觉层，不得阻断结果行、数量输入或加入按钮的交互。

每条搜索结果右侧提供正整数数量输入框和“加入”按钮。数量输入框维持 62 × 34 px 的详情页浅灰样式，数量默认 1、最小为 1，不接受 0、负数或小数；“加入”按钮固定为 72 × 34 px，使用普通卡牌 Stepper 的浅灰底色 `#F0F2EE`、深色文字、`#D6DBD6` 边框和 8 px 圆角，不得使用绿色或橙色。首次点击尚未缓存编辑上下文的候选牌“加入”时，前端先禁用当前行的数量输入和按钮，并以候选项 `printing_uuid` 请求卡牌上下文；成功后才将当前输入数量加入主牌区，失败时不加入并打开统一错误弹窗。上下文已缓存时直接加入，不重复请求。主牌已存在同一 `oracle_id` 时累加数量，不得创建重复记录，不存在时进入上下文指定的固定类型列并按卡组规则重新排序。加入成功不得关闭悬浮窗或重置数量输入；连续多次点击必须每次按当前输入值继续累加。每次加入成功后立即更新主牌与卡组总张数、异常汇总、收集率和卡组统计。悬浮窗打开期间，遮罩后的卡牌点击、拖拽、数量操作和卡组统计书签均不可交互。

卡组编辑页必须在卡组名称标头与主牌区域之间提供卡组代码导入区。“卡组代码”区域标签使用常规字重，不得加粗或形成与卡组名称竞争的标题层级。区域标头参照“我的卡牌”页面的系列分组标头，采用“卡组代码 + 浅色横向分隔线 + 最右侧箭头”的 34 px 单行结构，整条标头均为展开／折叠点击热区；展开态仅显示向上箭头，折叠态仅显示向下箭头，不显示“收起”或“展开”文字。区域默认展开。桌面原型中展开态导入区高 350 px、左右内边距 32 px，其中多行文本框横向铺满内容区、高 256 px，供用户粘贴最多 1,000 行的标准卡组代码；文本框为空时只在编辑区内部显示灰色占位文案“在此粘贴卡组代码…”，开始输入或粘贴后按常规编辑区逻辑隐藏，不显示其他辅助说明。下方右侧显示 32 px 高的“读取卡组配置”按钮，按钮文字使用常规字重、不加粗。折叠后只保留 46 px 高的区域标头，隐藏文本框和读取按钮；再次展开必须恢复此前输入内容，不得清空或重新请求。粘贴或输入代码不得自动修改卡组；只有点击读取按钮后才解析和校验。解析成功时，前端对响应中的 `printing_uuid` 去重、排除已缓存项，再按每批最多 200 项取得编辑上下文；只有解析和全部上下文批次均成功且返回完整时，才一次性应用解析结果：仅当响应名称非 `null` 时更新顶部卡组名称；响应名称为 `null` 时保留读取前的当前名称输入值，并以 `Commander / Deck / Sideboard / Maybeboard` 填充指挥官、主牌、备牌和备选区。`Commander` 中每张牌都必须满足后端返回的 `can_be_commander = true`，任一牌不符合“传奇生物、传奇鹏洛客或传奇载具”条件时整次读取失败，不得自动移入主牌或部分覆盖当前编辑态。卡牌行只使用数量和卡名，忽略 Set 代码、收藏编号与闪卡标记。此后在卡牌区执行增加、删除、数量加减或分区调整，不得反向修改文本框中已有代码；只有再次点击读取按钮时，才重新以文本框当前内容覆盖卡组名称和卡牌编辑态。解析请求或任一上下文批次失败时打开统一错误弹窗，不在导入区显示行内错误，且不得改变当前编辑态；用户确认保存前不得覆盖已保存的卡组。导入区必须占用独立页面高度，不得压缩或裁切主牌、备牌和备选区域。

卡组最终保存入库时，文本框中的原始代码不得作为最终事实来源。系统必须以当前可编辑卡组名称以及指挥官、主牌、备牌和备选区域中的真实卡牌、数量和分区为准，按第 8 节定义的 `About / Commander / Deck / Sideboard / Maybeboard` 顺序重新生成标准代码。卡牌行只保存 `AMOUNT CARDNAME`，不保存 Set、收藏编号、语言或闪卡标记。读取后继续编辑卡牌区时，允许文本框代码与当前卡牌区暂时不一致；只有点击“保存卡组”成功后，重新生成的标准代码才随卡组数据入库。

编辑页的卡组统计书签必须相对主牌区域保持与卡组详情页相同的位置关系。由于代码导入区新增 350 px 页面高度，桌面原型中的书签初始纵坐标由详情页的 `y = 310 px` 同步调整为 `y = 660 px`；其视口固定、打开抽屉、随抽屉滚动和关闭方式继续沿用卡组详情页规则。

卡组代码区域折叠时，主牌、备牌、备选和卡组统计书签必须随页面流共同上移，不得在原位置留下空白。桌面折叠态相对展开态减少 304 px，卡组统计书签原型纵坐标同步调整为 `y = 356 px`，继续保持与主牌区域的相对位置。

卡组编辑页悬停卡牌时，除沿用详情页的完整看牌和下方牌张让位行为外，还必须在当前卡图底部显示快速数量编辑浮层。桌面原型中浮层尺寸为 96 × 30 px，相对 150 × 210 px 卡图定位为 `x = 27 px、y = 172 px`。浮层不重复显示当前数量，卡牌左上角数量三角标是唯一数量展示。操作栏必须设计为单个 7 px 圆角的分段矩形，不得渲染两个独立胶囊；内部使用 1 × 16 px 浅色竖线二等分，左右各为 46.5 × 28 px 的透明按钮热区，左半减少、右半增加。两个完整半区均为点击命中区，不得只允许点击符号；正常可用状态下减号和加号统一使用白色，半区不使用独立背景、描边或圆角。浮层不得改变卡图尺寸、牌列宽度或堆叠间距，也不得给卡图增加外边框。数量变化需要同步更新牌张数量标识、区域与卡组总张数、收集率和统计数据。

卡组编辑页中的卡牌点击不得跳转卡牌详情。首次点击卡牌时，将其切换为固定看牌状态，效果等同鼠标长时间悬停：卡牌保持完整展示、下方牌张保持让位，鼠标移开后不收起；再次点击同一张牌时取消固定状态并恢复原堆叠。同一时间只允许一个固定看牌状态，点击另一张牌时切换固定目标；临时悬停其他牌不得自动取消已固定卡牌。数量加减按钮、异常状态页签及其他局部操作必须阻止卡牌点击事件；形成拖拽后的指针释放不得触发固定状态切换。只有未形成拖拽且落在卡牌非局部操作区域的完整点击才执行该交互。

卡组编辑页允许牌张数量从 1 减到 0；只有数量已经为 0 时减少按钮才禁用并将减号置灰。数量刚变为 0 时，卡牌必须在当前悬停期间暂时保留，左上角数量标识显示 0，加号继续保持白色可用，以便用户在离开前恢复数量。鼠标离开该卡牌时，如果数量仍为 0，才将卡牌从当前分区列表移除并重新计算牌列；若已恢复到 1 或更高则取消移除。不得在数量变为 0 的点击瞬间移除卡牌。

首版卡组分区移动沿用拖拽，按钮、菜单和键盘换区入口列入后续版本。卡组编辑页支持通过拖动卡牌在主牌、备牌和备选区域之间移动；主牌区域内的指挥官列同时是独立分区投放目标。按下后快速移动并开始拖拽时只移动 1 张；保持按下约 350 ms 后再拖拽时移动该逻辑卡在来源区域中的全部数量。指针按下时开始长按计时：在 350 ms 到达前移动距离超过约 4 px，立即进入单张拖动模式；在移动阈值内保持到 350 ms 后进入整条拖动模式。只按下并松开、未形成拖动时不得改变数据；数量为 1 时两种模式结果相同。当前界面不显示该手势的提示短语。

单张拖动成功后，来源分区数量减 1，目标分区对应逻辑卡数量加 1；目标分区不存在该牌时新建数量为 1 的记录，来源数量减为 0 时移除来源记录。整条拖动成功后，来源记录移除，其全部数量并入目标分区对应逻辑卡；目标分区已存在该牌时合并数量，不得生成重复记录。拖动开始后原位置保留同尺寸占位，卡图以浮层跟随指针；三个可见区域及主牌内的指挥官列在拖动过程中的视觉反馈保持一致，指挥官列不得根据资格增加特殊高亮、禁用态或其他提前提示。用户在指挥官列松开时才使用 DTO 的 `can_be_commander` 判断投放结果：值为 `true` 时完成投放并将分区改为 `commander`，值不为 `true` 时取消本次投放并返回原分区与原位置。从指挥官列拖入主牌其他类型列后改为 `mainboard`；拖入备牌或备选后分别改为 `sideboard`、`maybeboard`。除指挥官列外，投放成功的卡牌按自身类型进入目标区域的固定类型列，并按法术力值从低到高、颜色组合按颜色数及 WUBRG 色环顺序、英文卡名不区分大小写 A–Z、`printing_uuid` 升序的优先级重新排序；多色组合沿用卡组详情定义的固定顺序。拖拽只改变所属分区，不提供任意手工排序。

拖拽投放只更新前端未保存编辑态，并立即重新计算来源与目标区域张数、牌张数量标识、异常汇总、标头总张数、收集率和卡组统计。拖拽不得反向修改卡组代码文本框；最终保存必须把三个可见区域还原为四个真实分区后提交并重新生成标准代码。数量加减操作栏、异常状态页签及其他卡牌局部按钮必须阻止拖拽启动。数量为 0、等待鼠标离开移除的卡牌不得开始拖动。拖动取消、按 Escape、投放到可见区域之外，或不具备资格的牌投向指挥官列时，必须恢复原位置，不改变编辑态。后端保存时必须重新计算并校验 `commander` 中每张牌的资格，不能信任前端字段；不符合条件时整次保存失败，不得自动移区或部分保存。

鼠标和触屏必须共用 Pointer Events 或等效指针状态机。触屏点击卡牌同样切换固定看牌状态，点击局部按钮仍执行对应局部操作；触屏快速拖动移动 1 张，保持约 350 ms 后拖动移动全部，计时与移动阈值和鼠标一致。触屏卡牌区域必须禁止系统原生长按菜单、文字选择和图片拖拽；确认进入拖动模式后捕获当前指针，直到成功投放、取消或抬起。当前阶段不考虑键盘替代交互，界面不显示该拖动手势的提示短语。

异常卡位的定稿尺寸为：外层卡位 162 × 210 px、内层卡图 150 × 210 px、状态页签 12 × 22 px；页签相对卡位定位为 `x = 150 px、y = 7 px`。悬停提示框固定为 232 × 92 px、8 px 圆角；连接尖头固定为 6 × 12 px，侧边框遮罩固定为 3 × 12 px。当前原型的提示框与尖头已随页签同步下移 3 px；实现时必须以页签为相对定位锚点维持该视觉关系，不得直接使用原型画布的绝对坐标。

主牌和备牌区域标题分别汇总“数量不足 x 种 · 缺 x 张”和“卡组占用 x 种 · 缺 x 张”；两类异常汇总框必须使用相同宽度，桌面原型统一为 144 px，不得按文案类型使用不同尺寸。没有某类异常时隐藏对应汇总。“种”按 `oracle_id` 去重。数量不足的“缺 x 张”是该区域各牌 `max(当前卡组编辑数量 - 实际拥有数量, 0)` 的合计；卡组占用的“缺 x 张”是该区域各牌 `max(所有卡组编辑总数 - 实际拥有数量, 0)` 的合计。主牌、备牌、备选的区域总数统一使用“共 x 张牌”，并固定在区域标题横条最右侧；异常汇总位于总数左侧。备选不参与拥有量比较，不显示牌张异常或区域异常汇总。

## 12. 多卡组使用情况

多卡组使用情况按页面层级分别展示。卡牌详情展示当前逻辑卡牌的完整使用汇总：

```text
实际拥有：4
出现在 2 个卡组中
所有卡组编辑总数：8
跨卡组缺口：4
```

并可以查看使用该牌的具体卡组：

```text
Burn：4
Modern Red：4
```

卡组详情和卡组编辑页不重复展示具体卡组列表，但会在牌张异常状态及其悬停提示中使用当前卡组数量、实际拥有数量、所有卡组编辑总数和使用卡组数，并据此判断“数量不足”或“卡组占用”。卡组列表只显示当前卡组是否存在“数量不足”或“卡组占用”异常类型，不展示牌张级指标、缺口数量或具体使用卡组。

以上信息均属于统计，不代表具体实体卡已经分配给某个卡组。

## 13. 卡组统计

卡组统计的功能范围、统计口径、选择器、图表、抽到概率及交互方式统一以第 7.1 节“卡组详情”中的统计抽屉规则为准，本节不再维护第二套统计字段清单。

统计范围只包含主牌；指挥官属于主牌并参与统计，备牌和备选不参与。所有指标按卡组中的 `quantity` 计权。卡组总张数、收集率、数量不足和卡组占用等详情页摘要与异常信息继续按各自既定规则展示，不因为统计抽屉的范围而改变。

## 14. 操作日志

日志只记录以下 8 种操作：

```text
增加卡牌
减少卡牌
加入愿望单
移出愿望单
创建卡组
删除卡组
复制卡组
修改卡组
```

不记录普通查看和查询。卡牌日志在实际操作时生成具体语言版本快照，记录主牌面 `printing_uuid`，图片来源单独解析；仅图片允许回退，不能改写版本身份或语言。历史日志只使用快照，不依赖当前 Card DB 重新补齐或改写，原版本失效时日志仍可展示；日志明细行只读，不提供收藏编辑、愿望单编辑或卡牌详情跳转。

### 14.1 每日类型汇总、查询与分页

日志时间 `occurred_at` 按 UTC 保存；自然日 `operation_date` 由后端按应用配置时区派生，不持久化为另一个事实字段，前端不按浏览器时区重新划日。日期边界采用本地零点到下一本地零点分别转换 UTC 的左闭右开范围，不固定加 24 小时，以兼容夏令时。

操作日志首页必须保留“按日期和操作类型合并”的大前提。每条汇总记录以 `operation_date + action_type` 为唯一分组，同一自然日内同一种操作只显示一行；操作次数为当前日期条件实际包含的 `operation_log` 行数，当天未发生的类型不显示。

汇总页使用传统表格和页码分页，不使用行内折叠或滚动自动加载。表格列固定为日期、操作类型和操作次数。页面直接保持 API 契约规定的结果顺序，不在前端重新排序：`operation_date DESC`；同一天内按 `action_type`（操作类型）枚举顺序，即增加卡牌、减少卡牌、加入愿望单、移出愿望单、创建卡组、删除卡组、复制卡组、修改卡组。不提供排序选择。

页面只提供自定义开始日期和结束日期查询，不提供预设时间范围或操作类型筛选。两个输入框只显示年月日，不接受或展示时、分、秒。日期条件直接作用于 `operation_date`：两个条件均为空时查询全部日志，只填写一端时使用单侧日期边界，两端均填写时使用闭区间，完整包含开始日期、结束日期及中间每个自然日的全部操作。开始日期晚于结束日期时不得发送请求，并使用统一错误弹窗说明日期范围无效，不显示行内错误。操作区只提供“查询”按钮，不提供“清空”按钮；需要查询全部日志时，由用户将两个输入框置空后点击查询。每次点击查询均回到第一页。

“查询”按钮固定为 72 × 34 px，复用 `Screen / Deck Edit — Add Card Floating Window` 中“加入”按钮的普通卡牌 Stepper 风格：浅灰底色 `#F0F2EE`、深色文字、`#D6DBD6` 描边和 8 px 圆角，不使用绿色或橙色。

汇总列表每页固定 10 条，底部使用上一页、页码和下一页进行传统分页，不提供每页条数切换。查询栏右侧及页码区显示的是汇总行总数，例如“共 18 条汇总”，不是原始操作总数。切换页码时保留当前日期条件。汇总列表和明细悬浮窗的分页按钮统一使用普通卡牌 Stepper 风格：32 × 32 px、浅灰底色 `#F0F2EE`、深色图标或文字、`#D6DBD6` 描边和 8 px 圆角；当前页使用稍深的灰绿色 `#DCE4DF`、`#AEBAB3` 描边和加粗页码区分，不得使用绿色实心按钮，禁用按钮只降低透明度。

操作类型名称是打开明细悬浮窗的入口。点击后在当前汇总列表页上方打开对应明细，范围由 `operation_date` 和 `action_type` 确定，并展示该自然日、该类型的全部操作；不得在汇总表内直接展开具体操作，也不得跳转到独立详情路由。关闭悬浮窗后必须保留原日期条件、汇总页码和滚动位置。

### 14.2 类型明细悬浮窗

明细使用固定在当前浏览器视口中央的悬浮窗，不得按汇总列表页面的文档坐标定位。半透明暗色遮罩固定覆盖当前浏览器视口，只压暗底层页面，不使用背景模糊。悬浮窗打开期间必须锁定底层汇总列表滚动，并阻止点击、翻页、修改日期条件、滚轮、触控滑动及键盘滚动穿透遮罩。标题直接组合日期和操作类型，例如“2026年9月24日 · 增加卡牌”，不显示面包屑或重复页面标题；标题右侧显示具体操作总数和关闭按钮。明细内容超出可视高度时，只滚动悬浮窗内部内容区域。悬浮窗只能通过右上角关闭按钮关闭；点击悬浮窗之外的遮罩或底层页面不关闭，也不得触发底层操作。关闭后恢复底层列表打开前的滚动位置。

具体操作固定按 `occurred_at DESC, id DESC` 从新到旧排列，每页最多显示 10 条，并在悬浮窗内部使用独立的上一页、页码和下一页进行传统分页；翻页不得关闭悬浮窗。桌面端悬浮窗外层背景框固定为 1040 × 650 px，不随当前页记录数量改变。列表区域固定预留 10 行的高度；记录不足 10 条时保留空白行位，分页区保持固定位置，不随最后一条记录上下移动，也不得缩小外层背景框。悬浮窗不显示日期输入或类型筛选。明细总数必须与被点击汇总行的操作次数一致。

在 1280 × 720 常用桌面视口中，操作日志详情悬浮窗继续保持 1040 × 650 px并固定居中，左右各保留 120 px、上下各保留 35 px；八种操作类型共用该响应式几何规则，不维护单独的 1280 设计画板。更小视口空间不足时使用 `max-width`、`max-height` 和悬浮窗内部滚动，不得等比缩放全部内容。

### 14.3 卡牌操作明细

增加卡牌和减少卡牌的明细表显示：

- 卡牌名
- 必要的 Set、收藏编号和语言
- 普通或闪卡
- 数量变化

表格列为操作时间、卡牌、印刷信息和数量变化。印刷信息包含 Set、收藏编号、语言及普通／闪卡；语言显示日志写入时从 `scryfall_language.display_name` 取得的展示名快照，前端原样展示且不维护语言代码映射。增加显示 `+N`，减少显示 `-N`。示例：

```text
2026-09-24 14:26 · Lightning Bolt · M11 · 146 · 英文 · 普通 · +3
2026-09-24 14:22 · Lightning Bolt · M11 · 146 · 日文 · 闪卡 · +1
2026-09-24 13:58 · Counterspell · 2X2 · 51 · 英文 · 普通 · +2
```

加入愿望单和移出愿望单的明细表显示操作时间、卡牌、Set、收藏编号和语言，不显示工艺和数量变化。例如：

```text
2026-09-24 12:12 · Lightning Bolt · M11 · 146 · 日文
2026-09-24 11:48 · Counterspell · 2X2 · 51 · 英文
```

### 14.4 卡组操作明细

创建卡组、删除卡组、复制卡组和修改卡组的明细页只展示操作时间和卡组名快照：

```text
2026-09-24 10:35 · Burn
2026-09-24 09:20 · Modern Red
2026-09-24 08:46 · Commander Atraxa
```

卡组重命名归入 `修改卡组`，只显示新名字，不显示旧名字。

同一次卡组修改无论调整多少张牌，都作为一次 `修改卡组` 操作，不展开卡组内部卡牌变化。

## 15. 加载卡牌数据

### 15.1 功能目标

服务需要提供卡牌数据加载功能，将指定目录中的数据全量导入外置 Card DB。

- 这是系统维护功能，不是个人收藏、愿望单或卡组的导入功能；只操作 Card DB，不修改 App DB。
- 每次均为全量替换，不做增量更新、合并或单条修复；正式数据完全来自本次输入和项目内置字典，不补齐或保留旧 Card DB 数据。
- `AllPrintings.json` 是普通卡牌、Token、系列、英文裁定、赛制状态及大部分枚举值的唯一元数据来源。普通基础卡面写入 `mtgnissa_card`，Token 写入 `mtgnissa_token`，系列写入 `mtgnissa_set`，具体语言印刷写入 `mtgnissa_card_printing`。
- `scryfall_card.json` 仅作为旧翻译 UUID 到 AllPrintings 卡面 UUID 的只读桥，不读取或补充卡牌元数据。原始旧 UUID 不直接作为新翻译表关联键。
- `zhs_*.json` 是必需翻译及本地化输入，不独立产生卡牌实体；翻译字段允许为空，按既定优先级回退基础卡面的英文内容。
- 导入前识别 `isPartialPreview = true` 的系列，并按 `parentCode` 递归排除全部子系列及其卡牌、Token、语言印刷、裁定、合法性和展开数据；不为被跳过系列派生 Token Set。

### 15.2 数据目录

卡牌 JSON 目录由 Docker 映射到容器外部，并通过配置指定容器内路径，例如：

```text
CARD_DATA_DIR=/data/card-data
```

要求：

- Docker volume 使用只读挂载。
- 接口不能接收客户端传入的任意目录或文件路径。
- 服务只能读取 `CARD_DATA_DIR` 下约定的文件。

### 15.3 必需文件

每次加载必须同时读取以下九个文件，按真实格式解析：

| 文件 | 实际格式及用途 |
| --- | --- |
| `AllPrintings.json` | 标准 JSON 文档；遍历顶层 `data` 对象中的系列，校验对象键与系列 `code` 一致；不按 JSONL 解析 |
| `scryfall_card.json` | 旧 NDJSON，只读翻译映射桥 |
| `zhs_card.json` | 旧 NDJSON，卡牌翻译 |
| `zhs_flavor.json` | 旧 NDJSON，风味翻译 |
| `zhs_oracle.json` | 旧 NDJSON，Oracle 翻译 |
| `zhs_ruling.json` | 旧 NDJSON，裁定翻译 |
| `zhs_set.json` | 旧 NDJSON，系列翻译 |
| `zhs_type.json` | 旧 NDJSON，类型翻译 |
| `oracle-tags.jsonl` | 标准 JSONL，Oracle 标签及关系 |

旧 NDJSON 文件每个非空物理行是一个对象，按数据字典移除上游重复添加的一层反斜杠转义后解析，只移除一层；`oracle-tags.jsonl` 不应用该处理。全部文件按 UTF-8 流式读取，不要求将完整 AllPrintings 或 NDJSON 载入内存。已废弃的 `rulings.jsonl` 不属于输入，英文裁定只读 AllPrintings 的 `cards[].rulings[]`。

任一必需文件缺失、不可读、为空或解析失败时加载失败，现有正式库保持不变。

### 15.4 操作前完整确认

影响现有正式表之前，必须完整读取并预检全部九个文件，不能只检查存在或读取首行。

- 检查文件存在、为普通文件、可读且非空，记录大小、SHA-256 和按实际结构统计的预检记录数。
- AllPrintings 校验整个 JSON 文档及系列、普通卡、Token 和语言印刷的必填字段；NDJSON／JSONL 校验每个非空行是对象且具备对应必填标识。
- 按数据字典检查主键和组合唯一性；不得把允许跨印刷重复并聚合的 Oracle、裁定或标签关系误判成非法重复。语言转换后同一卡面的语言重复必须报错，不静默覆盖。
- `zhs_*.json` 的翻译字段可以为 `null`，通常只要求关联标识完整；`zhs_ruling.comment` 必须非空，用于生成与英文裁定统一的 `ruling_key`。
- 识别应跳过的预览系列，并按数据字典检查语言转换及必要关联。无法映射的新旧翻译记录按既定规则正常跳过，不因此终止元数据导入。

只有全部输入完成预检后才能进入临时表加载阶段。

### 15.5 加载方式

业务结果要求为：删除旧卡牌表，按固定 Schema 重新建表，并插入本次 JSON 的全部数据。

考虑到 MySQL DDL 会隐式提交，不能直接先删除正在使用的正式表，否则导入失败会留下空库或半成品库。实现时采用等价但更安全的方式：

1. 完成全部文件预检。
2. 创建一组新的临时卡牌表；此时不创建桥接暂存表。
3. 导入 AllPrintings 元数据；开始处理 `scryfall_card.json` 前，再创建不属于目标数据字典的任务级普通桥接暂存表 `card_uuid_bridge__stage_<task_id>`。
4. 继续流式导入其余文件；旧 UUID 与 AllPrintings UUID 的关系先批量写入桥接暂存表，卡牌翻译分批查询该表并直接使用新 UUID 入库。无法命中新 `mtgnissa_card` 的旧记录正常跳过，不区分 Token、预览系列或普通卡缺失；日志只打印各类计数，不打印未命中样例。
5. 全部源文件和两张翻译映射表写入完成后立即删除桥接暂存表，再按数据字典的预览排除、翻译映射跳过、语言展开、关系去重和 Oracle 聚合规则校验各表实际写入数，不将所有目标表行数直接等同源文件行数；`ruling_translation` 只导入 `zhs_ruling.json` 中实际存在的翻译记录。
6. 再次确认 SHA-256 和按实际格式统计的记录数未在导入期间变化；不重复核对文件大小。
7. 使用 MySQL 多表 `RENAME TABLE` 原子切换新旧表。
8. 切换成功后删除全部旧卡牌表。

在切换前发生任何错误时立即停止数据库操作，不自动清理临时表，现有正式卡牌表保持不变；遗留临时表用于排查并由运维人员处理。只有原子切换成功后才进入 `cleaning` 阶段，按表删除本次切换产生的旧表，任一删除失败即停止后续数据库操作。

### 15.6 表范围

加载逻辑只能操作新数据字典规定的固定白名单正式表：

- 印刷及系列：`mtgnissa_card`、`mtgnissa_token`、`mtgnissa_set`、`mtgnissa_card_printing`。
- 翻译：`card_translation`、`flavor_translation`、`oracle_translation`、`ruling_translation`、`set_translation`、`type_translation`。
- 翻译映射：`card_flavor_translation_mapping`、`card_oracle_translation_mapping`。
- Oracle 数据：`oracle_ruling`、`oracle_legality`、`oracle_tag`、`oracle_tag_relation`、`oracle_tag_mapping`。
- 卡面展开：`scryfall_card_keyword`、`scryfall_card_type`、`scryfall_card_frame_effect`、`scryfall_card_promo_type`。
- 内置字典：`scryfall_color`、`scryfall_language`、`scryfall_layout`、`scryfall_frame`、`scryfall_frame_effect`、`scryfall_finish`、`scryfall_game`。

旧 `scryfall_card`、`scryfall_set`、`scryfall_oracle_ruling` 和 `oracle_tagging` 不属于新数据字典的正式表白名单；固定白名单应与新字典第 2 至第 7 节一致，禁止枚举整个数据库后直接删除。

加载任务可在处理 `scryfall_card.json` 前创建名称严格限定为 `card_uuid_bridge__stage_<task_id>` 的普通桥接暂存表；它不属于目标字典或 `schema.go`，不参与正式表换表。全部源文件及两张翻译映射表写入完成后立即删除，再进入验证；此前失败则与本次其他临时表一同保留用于排查。执行前必须确认当前连接库名等于配置的 Card DB 名称，防止操作 App DB。

### 15.7 导入要求

- 普通卡和 Token 按卡面拆行，以 AllPrintings `uuid` 为主键；`side=a/b/c/d/e` 对应 `face_index=0/1/2/3/4`，普通单面、无 `side` 和 Meld 独立牌按字典使用 `-1`。基础普通卡 `scryfall_id` 必填，以 `(scryfall_id, face_index)` 保证唯一；Token 公开 ID 可空，不将多个空值记录合并。
- 系列元数据直接读取 `sets[]`，按 `code` 唯一，保留 `parentCode` 为 `parent_code`；发行日取 `releaseDate`，普通及 Token Set 的 `card_count` 分别为纳入的 `cards[]`、`tokens[]` 卡面数，不再从卡牌动态汇总系列或按收藏编号去重。
- 普通系列语言及语言印刷名称先转换为内置语言代码，未收录的源语言报错，不原样写入或静默舍弃；Token Set 的语言固定为 `NULL`，Token 不写语言印刷表或赛制表。字典枚举范围和代码保持新数据字典定义。
- `mtgnissa_card_printing` 以 `uuid` 为主键，`(card_uuid, language_code)` 唯一。先导入 `foreignData[]`；同语言与外层卡牌冲突时保留 foreignData 的公开 ID 和印刷文字，但 UUID 改为外层卡牌 UUID；没有相同语言时才补基础语言行，UUID 等于基础卡面 UUID。无印刷文字时不创建无意义行；转换后语言重复报错。三个印刷文字字段及补充规则以新字典为准。
- 卡面翻译桥按 `(scryfall_id, 卡面定位)` 唯一匹配新基础卡面，必要时核对 `face_name`；不得只按共享图片 ID 覆盖多牌面。旧记录名称或单面名称以 `A-` 开头的炼金再平衡牌跳过；Token、预览、删除或其他未命中的旧记录正常跳过，不写卡牌翻译或两张映射关系，独立风味及 Oracle 翻译仍可按各自主键导入。桥接读写采用分批或集合查询，不逐行查询，不在应用内存长期保留全部映射。
- 标量字段使用对应数据库类型，不将整条源对象存为单个 JSON `document`。颜色、颜色标识、颜色指示符、工艺、游戏平台和 Attraction 灯号按字典存位掩码；`produced_mana` 按源顺序以逗号连接，保存为 `VARCHAR(32) NULL`，不另建字典或关联表。关键字、类型、牌框效果及推广类型使用现有卡面展开表，关联新的基础卡面 UUID。
- `artist_ids` 按源顺序逗号连接存为 `VARCHAR(2048) NULL`；Oracle 翻译的 `former_names` 存为压缩 JSON 数组文本。其他需要保留的结构化原值按字典存 `LONGTEXT`，不另建 JSON 子表。
- 法术力值在 `faceManaValue` 属性存在时使用该值，包括合法的 `0`，仅属性不存在时回退整卡 `manaValue`。力量、防御力和忠诚值保留原始字符串，数值派生列及查询按第 2.2 节执行。主键、关联键、常用查询字段及名称联想的索引按新字典和检索要求建立；正式 `%q%` 名称搜索按主动低频查询直接实现。
- 缺省布尔标记按字典映射为 `false`，数组推导布尔值按是否包含对应值计算；其他 JSON `null` 按字典写入 SQL `NULL`，不混同空字符串、空数组或否定状态。
- 英文裁定只取 AllPrintings 的 `cards[].rulings[]`，用规范化 `text` 的 SHA-256 生成 `ruling_key`；规范化只统一换行、弯引号、不换行空格及首尾空白，不折叠或改写正文。`oracle_ruling` 以 `(oracle_id, ruling_key, published_at)` 为主键，相同 Oracle、正文和日期只保留一条，不同日期分别保留；不使用自增行 ID 作为业务关联，不保存来源。裁定翻译按相同键生成口径可选关联，两方向均不要求对方存在；显示正文优先非空翻译，否则回退 `oracle_ruling.text`。
- `oracle_legality` 以 Oracle 聚合普通卡牌的上游赛制状态，同一赛制多个状态按 `Legal > Restricted > Banned > Not Legal > NULL` 聚合；`NULL` 只表示缺少该键，不等于不合法。该表用于数据保存及规则查询，不因此新增页面赛制展示或完整卡组合法性校验。
- `oracle-tags.jsonl` 只导入 `object=tag, type=oracle` 的标签；标签主表保留 ID、名称、说明和逗号连接别名。`parent_ids` 与 `child_ids` 展开为去重的 `oracle_tag_relation`；卡牌标注写入 `oracle_tag_mapping(oracle_id, tag_id, weight)`，`weight` 原样保存，不使用枚举限制。
- 源字符串主键去除首尾空白后按 Unicode 不区分大小写检查重复，派生多值关系采用相同口径去重并保留首次原值，避免与数据库唯一键冲突；语言印刷重复、基础卡唯一性及裁定去重仍按各自明确规则处理。原子换表不建立跨表数据库外键，关联完整性由预检、验证和业务查询保证。
- 普通、闪卡和蚀刻闪的业务归类不写回只读 Card DB；收藏始终保存普通和闪卡两个数量桶，不因源工艺限制用户录入。
- 使用批量插入，逐文件记录预检记录数及实际写入／跳过／去重或展开数量，按数据字典验证目标行数；不能要求展开或聚合后的目标表行数等于源文件物理行数。解析或插入失败时记录文件及行号或 JSON 对象定位，不打印完整卡牌 JSON；未命中翻译桥只记录计数，不输出样例。
- 同一服务实例同一时间只允许一个加载任务。开始、阶段切换、逐文件校验与导入完成、计数核对、原子切换及最终结果输出结构化日志；运行中每 30 秒输出包含任务 ID、阶段、当前文件及累计记录数的心跳，不按固定批次行数额外输出进度日志。

### 15.8 接口行为

建议接口：

```http
POST /api/v1/card_data/load
```

该操作使用异步任务：

- 启动成功返回 `202 Accepted` 和任务 ID。
- 已有任务执行时返回 `409 Conflict`。
- 任务状态至少包括：`validating`、`preparing`、`importing`、`verifying`、`switching`、`cleaning`、`completed`、`failed`。
- 提供按任务 ID 查询状态的接口；启动和查询响应返回任务 ID、当前状态、开始时间，以及存在时的结束时间和错误详情。
- 每个文件的统计和处理进度只写入结构化日志，不通过任务状态接口返回。

当前不实现完整用户认证，但该接口必须具备最低限度保护：

- 默认关闭，通过配置显式启用。
- 请求必须携带固定确认文本 `LOAD_CARD_DATA`。
- 不允许请求指定数据库名、表名或文件路径。
- 部署时应只向内网或受反向代理限制的管理路径开放。

### 15.9 日志边界

卡牌数据加载属于系统维护任务，不计入用户操作日志。

任务结果至少记录：

- 任务 ID。
- 开始时间和结束时间。
- 每个文件的大小、SHA-256、按实际格式统计的预检记录数及实际写入、跳过、去重或展开计数。
- 新旧表切换结果。
- 最终状态和错误摘要。

## 17. 开发阶段调优参数

使用服务端游标的 Set 索引、全局搜索、收藏、愿望单、卡组列表及增加卡牌正式结果，其单批返回数量在后端接口开发与联调时根据查询耗时和响应体积确定，并保留为可调参数；Set 索引按完整父组计批，不能拆分子树。普通及 Token Set 卡牌接口仍一次返回完整轻量结果，只有前端单批渲染数量、图片预加载范围和接近底部的触发阈值需要根据图片加载压力和渲染表现调优，不将其改成后端分页。名称联想固定最多 5 个名称，操作日志固定每页 10 条，均不套用无限滚动批量参数。调优不得改变已确认的滚动加载、条件变化后重置和分页方式。

## 18. 本次对齐的验收场景

以下场景补充现有语法、收藏、卡组及日志验收要求；具体布局以原型和页面说明为准，HTTP 状态与 DTO 以 API 契约为准。

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| B01 | 同一印刷存在多个语言版本，其中某语言没有图片 ID | 可回退基础卡图；该语言的 `printing_uuid`、语言、详情、收藏及愿望单状态仍独立，不与共用图片的其他语言合并 |
| B02 | 双面牌从列表、全局结果或卡组进入详情并调整收藏 | 返回主牌面语言印刷 UUID 及完整牌面；翻面不改变版本身份，不重复计结果、收藏或愿望单 |
| B03 | 全局语法的两个原子条件分别由不同牌面或印刷满足 | 在 Oracle 集合层组合命中，一 Oracle 一结果；代表取基础公开 ID 最小的印刷主牌面，详情入口解析为语言印刷 UUID，无版本选择步骤 |
| B04 | Set 列表带名称、语言或类型条件，父节点命中而子节点不满足条件 | 完整子树仍跟随父节点并缩进；只匹配子节点而父节点未命中时不单独返回该子树；分页不拆分父组 |
| B05 | 同一父节点有普通子 Set 与 Token Set，切换父节点排序 | 子节点始终先普通、后 Token，各组发行日期升序、代码升序，缺失日期在后；类型选项不包含仅子节点具备的类型 |
| B06 | 进入 Token Set，其中有双面 Token 及多条空公开 ID 记录 | 无语言、搜索、筛选、排序及个人操作入口；双面一项可翻面，无法配对的空 ID 记录独立保留；列表总数按印刷项，索引数量按导入卡面 |
| B07 | 打开普通或 Token Set 列表并持续滚动 | 后端一次返回完整轻量结果；前端本地逐批渲染，不通过滚动继续请求后端分页；普通 Set 筛选及排序复用完整结果 |
| B08 | 增加卡牌输入 2 个英文字母、1 个汉字，再分别输入 3 个英文字母、2 个汉字 | 前两者不触发联想，后两者防抖后执行 `q%`；最多 5 个去重名称，输入变化不执行 `%q%`，过期响应被忽略 |
| B09 | 使用短关键字或空关键字点击搜索，再点击一个联想名称 | 按钮无联想门槛限制，空关键字不加名称条件；点击联想回填全名并执行正式 `%q%`，结果按 Oracle 去重并保留既定展示版本规则；通配符输入作为普通文字 |
| B10 | 无 Oracle 普通卡尝试通过候选、上下文、代码导入或保存加入卡组 | 不进入候选或联想，其他入口同样拒绝；导入整次失败并定位原行，不部分覆盖编辑态，不以 UUID 替代 Oracle 身份 |
| B11 | 首次请求 Set、收藏或愿望单时不传筛选、排序或合并参数 | 筛选维度不受限制，排序与合并使用既定默认值；收藏任一合并开关开启时隐藏数量加减，均关闭才按具体版本调整 |
