# MTGNissa 功能需求

## 文档状态

- 状态：需求草案
- 范围：卡牌查看、个人卡牌、愿望单、卡组和操作日志
- 暂不包含：个人数据库表定义、完整业务 API 契约、完整查询条件和页面具体布局

## 1. 功能范围

系统包含：

```text
卡牌中心
├── 全部卡牌
├── 我的卡牌
├── 愿望单
└── 卡牌详情

卡组
├── 卡组列表
├── 卡组编辑
├── 卡组展示
└── 卡组统计

操作日志
├── 每日操作汇总
└── 操作明细
```

### 1.1 页面身份标识

部署实例可以通过配置文件提供 `app.display_name`，用于表示当前是谁的卡牌库。该配置可省略，默认值为空字符串。

页面标题或全局导航区域按统一逻辑展示该配置值。应用不裁剪、不校验或分支处理该字符串；值为空时展示结果自然为空字符串。

`display_name` 只用于展示，不代表登录账号、认证主体或数据权限，也不写入个人数据库或用户操作日志。修改配置并重启服务后，页面使用新名称。

全部卡牌、我的卡牌和愿望单复用导航、搜索筛选、卡图及详情入口等基础组件，但列表层的快捷操作按页面范围严格区分，不能因为复用组件而互相暴露。

## 2. 卡牌查看与检索

已确认需要：

- 查看 Set 列表
- 选择 Set 查看该 Set 的卡牌
- 通过右上角全局搜索框执行普通卡名或语法搜索
- 通过列表中间搜索框按名称关键字查询对应 list 接口
- 根据费用搜索
- 从检索结果进入卡牌详情
- 从“我的卡牌”列表快速修改拥有数量
- 从“愿望单”列表快速管理愿望单状态

### 2.1 搜索入口边界

系统存在两类不同搜索入口，不得共用输入解析规则：

1. 页面右上角的全局搜索框支持普通卡名和已实现的查询语法，提示文案为“搜索卡牌或输入语法…”。提交后进入独立的全部卡牌搜索结果页；只有该入口以及功能标签跳转会解析 `otag:` 等语法。
2. 各列表页内容区中间的搜索框只接受名称关键字，并作为当前页面 list 返回接口的查询参数。卡牌列表按卡名关键字查询，Set 列表按系列名称或缩写关键字查询；不得解析冒号操作符、布尔表达式或其他搜索语法。

列表搜索条件改变时重新请求对应 list 接口并重置列表加载位置。右上角全局搜索与列表内关键字搜索的路由、接口参数和错误提示必须相互独立。

Set 列表的每个可用语言按钮独立跳转到该 Set 对应语言的卡牌列表，并阻止整行点击事件；置灰语言不可点击，也不触发行级跳转。点击整条 Set 横条的其他区域时，跳转到该行从左到右第一个正常显示、非置灰语言对应的卡牌列表。不得再额外应用简体中文、英文或其他隐藏语言优先级。

完整查询能力暂不确定，后续根据参考网站交互、卡牌数据库模型、数据库实际字段以及索引和查询能力设计。

不要求实现完整 Scryfall 搜索语法。

## 3. 卡牌详情

卡牌详情以具体印刷版本为入口：

```text
Set + 收藏编号
```

展示内容包括：

- 卡图
- 双面牌或多牌面的所有内容
- 卡名
- 费用
- 类型
- 卡牌文字
- 力量、防御、忠诚等属性
- Set
- 收藏编号
- 稀有度
- 卡牌原语言（UI 统一显示为“语言”）
- 数据库提供的其他必要字段

### 3.1 卡牌原语言与翻译后语言

项目规则内部统一区分以下两个概念：

- **卡牌原语言**：具体印刷记录及卡图对应的语言，来源为 `scryfall_card.lang`。
- **翻译后语言**：卡牌名称、类别、规则文字、风味文字和官方释疑等卡牌说明使用的展示语言，由系统配置指定，当前为简体中文。

UI 交互不暴露“卡牌原语言”术语。页面中的“语言”筛选、按钮、下拉框、面包屑和合并选项均指卡牌原语言。翻译后语言不作为筛选或切换项展示，只用于生成卡牌说明内容。

卡牌详情不提供翻译后语言切换，卡牌说明统一使用翻译后语言。

卡牌名称、类型、规则文字等说明内容：

```text
优先使用翻译后语言
    ↓
不存在时显示英文
```

翻译后语言与卡牌原语言相互独立。

例如卡牌原语言为日文、系统配置的翻译后语言为简体中文时：

```text
UI 语言：日文
卡牌说明：简体中文
```

翻译后语言的说明不存在时显示对应英文内容。

### 3.2 印刷版本

详情页展示同一逻辑卡牌的全部印刷版本：

- 不同 Set
- 不同收藏编号
- 不同卡牌原语言（UI 显示为“语言”）
- 各版本拥有数量

支持切换到其他印刷版本详情。

### 3.3 拥有数量

普通卡和闪卡在同一个数量字段中展示：

```text
普通卡数量:闪卡数量*
```

例如：

```text
3:1*
```

表示普通卡 3 张、闪卡 1 张。

详情页支持分别增加或减少普通卡和闪卡数量。

## 4. 我的卡牌

只展示拥有数量大于零的卡牌。

收藏数量至少区分：

```text
逻辑卡牌
+ Set
+ 收藏编号
+ 语言
+ 普通/闪卡
```

不为每一张实体卡建立独立档案。

### 4.1 排序

支持：

- 按 Set 和收藏编号排序
- 按颜色费用排序
- 按名称排序

颜色费用和收藏编号的具体排序规则，根据卡牌数据库模型确定。

### 4.2 Set 合并

按 Set 排序时不提供跨 Set 合并。

按颜色费用或名称排序时提供：

```text
[ ] 合并不同 Set
```

关闭时，不同印刷版本展示为多张卡：

```text
Lightning Bolt / M11 / 2:1*
Lightning Bolt / M10 / 3:0*
Lightning Bolt / 2X2 / 1:1*
```

这些卡牌按照排序结果连续展示。

开启时，同一逻辑卡牌展示为一张汇总卡：

```text
Lightning Bolt / 全部 Set / 6:2*
```

汇总卡可以查看各 Set 明细。

### 4.3 语言合并

收藏严格区分语言，并提供：

```text
[ ] 合并不同语言
```

关闭时：

```text
Lightning Bolt / M11 / 英文 / 2:1*
Lightning Bolt / M11 / 日文 / 1:0*
Lightning Bolt / M11 / 简中 / 3:0*
```

开启时：

```text
Lightning Bolt / M11 / 全部语言 / 6:1*
```

汇总卡可以查看语言明细。

### 4.4 合并组合

| Set 合并 | 语言合并 | 展示单位 |
| --- | --- | --- |
| 关闭 | 关闭 | 每个 Set、每种语言分别展示 |
| 开启 | 关闭 | 相同语言合并不同 Set |
| 关闭 | 开启 | 相同 Set 合并不同语言 |
| 开启 | 开启 | 每个逻辑卡牌展示一张 |

普通和闪卡始终通过 `普通:闪*` 汇总。

## 5. 愿望单

愿望单只展示用户明确标记的印刷版本。

愿望项严格区分：

```text
Set
+ 收藏编号
+ 语言
```

不跨 Set 合并，不跨语言合并。

愿望单不记录：

- 目标数量
- 闪卡偏好
- 备注
- 优先级

愿望项只支持：

- 加入愿望单
- 移出愿望单

不提供修改语言操作。需要改变语言时：

```text
移出原愿望项
    ↓
使用新语言重新加入
```

即使已经拥有该版本，也不自动移出愿望单。

可以从以下位置管理愿望单：

- 全部卡牌
- 我的卡牌
- 卡牌详情
- 愿望单

## 6. 卡牌中心复合

全部卡牌、我的卡牌和愿望单共享：

- 搜索与筛选
- 排序
- 卡牌列表或图片展示
- 卡牌详情入口

列表快捷操作不共享，必须遵循以下边界：

| 页面范围 | 列表快捷操作 |
| --- | --- |
| 全部卡牌 | 不提供任何个人数据操作；不显示拥有数量、普通卡/闪卡加减按钮或愿望单状态按钮。卡图只用于进入卡牌详情。此规则同时适用于具体 Set 卡牌列表和语法搜索结果列表。 |
| 我的卡牌 | 支持快速编辑当前卡牌的普通卡与闪卡拥有数量；不提供愿望单快捷操作。 |
| 愿望单 | 支持快速取消或重新加入愿望单；不提供普通卡或闪卡数量编辑。 |

可复用卡牌详情页不属于上述列表快捷操作范围，仍按详情页规则提供收藏数量和愿望单管理。

分组列表中的系列折叠使用整条系列标头作为点击热区，最右侧箭头只提示展开状态。卡牌下方的愿望单星标和数量加减属于局部快捷操作：每个符号必须具有略大于符号本身的独立热区，但不得把整条信息栏或数量栏变成对应操作按钮。

所有卡图列表中的模式双面牌只计为一个列表结果并占一个标准卡位，默认显示正面。卡牌插画区域右上角提供独立翻面按钮，避开牌名栏及法术力费用标志，并在当前卡位切换正反面；翻面操作不进入详情页、不改变后端数据。我的卡牌中两个牌面共享同一份普通卡与闪卡数量，愿望单中两个牌面共享同一个愿望单状态。

模式双面牌详情页在卡图下方提供独立的“查看反面／查看正面”按钮，不使用列表页叠加在卡图上的按钮。当前显示正面时按钮为“查看反面”，显示反面时按钮为“查看正面”。切换牌面时，卡图及中间对应牌面的翻译后语言说明同步切换；面包屑保持双面牌组合名称，右侧收藏、愿望单、语言、印刷版本和卡组使用数据不变。

卡牌中心使用统一二级标头提供范围切换：

```text
[全部卡牌] [我的卡牌] [愿望单]
```

三个范围使用独立页面与独立路由，二级标头只负责切换，不把三种列表和操作合并到同一页面中。

## 7. 卡组列表

支持：

- 创建卡组
- 查看卡组
- 编辑卡组
- 修改卡组名称
- 复制卡组
- 删除卡组
- 查看更新时间
- 查看卡牌总数
- 查看异常状态
- 查看卡组统计

不进行卡组合法性校验。

卡组列表页面沿用系统统一的一级导航，并在导航下使用与“我的卡牌”二级标头相同视觉规格的 100 px 深绿色渐变身份栏：左侧显示中文标题与说明，右侧显示“新建卡组”操作。该身份栏不包含二级切换按钮，不代表卡组新增二级菜单。下方单行吸顶工具栏支持按卡组名称查询，以及按最近更新、创建时间、名称或卡牌总数排序。各排序使用固定方向，不显示独立升序、降序按钮；页面不提供异常状态筛选。

卡组以可视化信息卡片展示。桌面端卡片尺寸固定为 328 × 292 px，封面视口固定为 328 × 180 px；标准卡图等比显示为 328 × 457 px，并相对封面顶部固定偏移 `-54 px`，不同卡牌不单独调整取景。更新时间参考 Archidekt 的轻量相对时间样式，固定在封面右下角，距右侧 12 px、距底部 8 px；只显示小型时钟图标及相对时间文字，不使用胶囊、底框或色块，也不随渐变区或卡图取景位置移动。封面从 `y = 108 px` 开始叠加 72 px 高、由透明到纯白的纵向渐变，让卡图柔和淡出至六色比例带和信息区，不使用不透明横框硬切；渐变末端至少 8% 保持纯白，六色比例带容器显式使用相同纯白背景，避免渐变终点与透明后继层在裁切边缘插值形成细缝。该效果直接作用于后端生成的外部卡图 URL，不要求另存裁切图；前端必须允许对应图片 CDN，并提供加载失败占位。封面下方使用固定白、蓝、黑、红、绿、无色六类的宽度比例表达卡组颜色含量，不允许随机取色。信息区显示卡组名称，分区摘要同一行右侧显示总张数；固定底栏左侧按需显示“数量不足”或“卡组占用”状态，但不显示异常项数量，无异常时不显示状态，右侧固定显示“查看卡组”。卡组总牌数和颜色比例只统计主牌、备牌和指挥官，备选区不计入。整张卡片的非操作区域和“查看卡组”均按 `deck_id` 进入对应详情页；独立的更多菜单必须阻止卡片跳转，并提供编辑、重命名、复制和删除。

### 7.1 卡组详情

卡组详情页面沿用系统一级导航，并将深绿色渐变连续铺满整个页面，不在标头与卡牌区之间分成两段背景。页面按 `deck_id` 加载卡组；标头只显示卡组名称、总张数、相对更新时间和收集率。标头右侧从左到右固定显示“编辑卡组”“复制卡组”“复制卡组代码”，三个按钮统一使用 36 px 高、7 px 圆角、相同内边距的橙色主按钮样式，并共用橙色底和描边、深色图标文字。“编辑卡组”按当前 `deck_id` 进入当前卡组编辑页面；“复制卡组”创建内容相同的新卡组，将名称设为“复制 原卡组名”，创建成功后进入新卡组编辑页面；“复制卡组代码”不跳转，将当前卡组的通用编辑码写入系统剪贴板并显示成功反馈。详情页本身不提供拖拽改牌或卡图上的数量编辑。总张数和收集率统计指挥官、主牌和备牌，备选不计入。

卡牌区域不显示“卡牌堆叠”标题条，也不提供主备切换、展示方式、分组或排序控件。主牌、备牌、备选属于同一个连续详情页，不拆分为单独页面或路由；页面依次展示三个区域，每个区域左上角显示区域名称和总张数，备牌从主牌最长列结束后开始，备选从备牌最长列结束后开始。三个区域统一按指挥官、神器、生物、结界、瞬间、法术、鹏洛客、地的固定类型顺序及固定列坐标展示。当前区域不存在的类型不渲染标题、卡图或可见空占位，但后续存在的类型仍须与主牌中的同名类型垂直对齐，不得向左补位。每个区域的类型列必须保持在同一横行且禁止换行；1440 px 桌面端使用 158 px 类型列宽和 14 px 列间距，使八种类型完整显示在内容区内。更窄视口可在当前区域内部横向滚动作为降级方案，但不得触发整页横向滚动。类型内按法术力值从低到高排序，数值相同按翻译后语言名称及稳定卡牌标识排序。

卡组详情和卡组编辑页面必须在牌张悬浮时于卡牌侧边显示翻译信息气泡，内容只包括翻译后语言的卡牌名、类别和规则文字。气泡复用卡牌详情页的信息面板视觉，不得使用卡组页的深色异常提示样式。桌面端宽度固定为 300 px，高度由翻译后的卡牌名、类别和规则文字自动撑开；文本增加时只允许向下扩展，不得横向增宽、截断内容或建立内部滚动条。当前样例内容高度约 164 px。主体使用白色纸张底、`#D7DBD6` 边框、12 px 圆角与轻阴影；正文颜色为 `#18201D`，字段小标题为 `#7A8580`。卡牌名使用 16 px 标题；类别和规则文字分别显示灰色字段标题及 12 px 常规正文，规则文字保留换行及符号顺序。气泡默认位于卡牌右侧并以尖角指向卡牌，空间不足时自动翻转到左侧，必须限制在视口内并覆盖于所有牌列之上；气泡不承载操作，也不得阻挡卡牌点击、局部按钮或拖拽。

卡组详情页的气泡只随鼠标悬浮显示，离开对应卡牌后隐藏，卡牌点击仍进入卡牌详情。卡组编辑页的气泡同时响应鼠标悬浮和点击固定看牌：卡牌被点击固定后，气泡在鼠标移开后继续显示；再次点击同牌、切换固定目标或牌张被移除时同步隐藏。临时悬浮其他牌不得自动取消已固定牌张。

桌面端卡图固定为 150 × 210 px，收起状态的纵向叠距固定为 30 px，必须完整露出每张牌的牌名栏，不能只露出边框或颜色条。卡牌左上角使用覆盖卡角的低饱和中深绿色三角形数量标志（原型色 `#426B59`），只比页面深色底色略亮。三角标铺到卡位最外缘，并与卡位共用同一个 8 px 圆角裁切：必须保留左上角圆弧，但三角标与圆弧之间不得残留额外的黑色描边圈。数字使用浅色、`900` 字重。标志内容为该牌在当前区域的 `deck_card.quantity`，不得使用纯黑、高亮薄荷绿、方形或圆角矩形徽标，也不是法术力值或拥有数量。鼠标移入第 i 张牌时，其后的牌整体下移 180 px，完整露出当前卡图；移出后恢复 30 px 叠距。点击卡图进入当前展示的具体印刷版本详情页。卡图版本优先选择同一 `oracle_id` 下用户拥有且发行时间最新的印刷版本；没有拥有版本时选择发行时间最新的可用印刷版本；发行时间相同时使用稳定卡牌标识兜底排序。

关闭状态下，网页右侧固定显示“卡组统计”书签。桌面端书签固定为 38 × 118 px，文字按“卡／组／统／计”单列竖排，图标为 15 px；书签相对浏览器视口固定在 `y = 310 px`，不随卡组卡牌页面纵向滚动，也不占用卡牌列宽度。点击后从右侧打开深绿色长抽屉，不使用居中弹窗，也不创建独立页面或路由。1440 px 桌面原型中抽屉宽 1080 px，左边缘为 `x = 360 px`，右边缘贴住视口。刚打开时抽屉顶部为 `y = 150 px`，在视口上方保留 150 px 模糊背景，不依据 Deck Detail Header 高度开始，也不要求初始底部贴边。

背景模糊层覆盖整个视口，显示抽屉左侧、初始顶部及滚动到底后的底部背景；点击任何未被抽屉覆盖的模糊背景关闭，并恢复原滚动位置。点击打开时，书签只做水平向左移动，从浏览器右侧移动到抽屉左边缘；初始打开状态的屏幕绝对高度仍为 `y = 310 px`，不得上下跳动。完成水平打开后，书签成为抽屉结构子元素并与抽屉一起滚动，允许滚出视口；再次点击书签也可关闭。不显示右上角关闭叉或其他关闭按钮。

滚动范围为整个统计遮罩页，不是抽屉内部的独立滚动容器。向下滚动时长抽屉整体上移并覆盖初始顶部模糊背景；滚动到底时抽屉底边停在 `y = 750 px`，在视口底部露出 150 px 模糊背景。初始顶部与最终底部露出的模糊背景高度必须相同。抽屉最右侧必须显示整个统计遮罩页的滚动条；刚打开状态滑块位于顶部，滚到底状态滑块位于底部，该滚动条不代表抽屉内部另有一层滚动。

抽屉说明固定为“统计主牌 · 备牌、备选不计入”。统计范围只包含主牌；指挥官牌属于主牌并参与统计，备牌和备选均不参与。所有指标按 `quantity` 计权。内容包括平均法术力值、地牌张数、费用颜色与产费颜色、六色明细、0 至 8+ 的整体法术力曲线、按颜色／类型／功能标签拆分的子曲线、抽到概率表格和数量分布柱状图；不显示总法术力值。整体法术力曲线独占完整一行，0 至 8+ 九个档位横向铺满统计内容宽度，标题右侧不显示“不含地牌”，同一行不并排放置类型分布块。费用颜色从 `mana_cost` 汇总，对应颜色费用比例为该颜色费用点数除以白、蓝、黑、红、绿、无色六类费用点数总和；通用数字及 `X/Y/Z` 等非六类符号不进入分子或分母。产费颜色从 `produced_mana` 汇总，并按相同方式使用对应颜色产费点数除以六类产费点数总和。费用点与产费点均按 `quantity` 计权。六色明细固定压缩为同一行，依次显示 Scryfall 法术力图标、费用比例条、“x点·x张”、产费比例条和“x点·x张”。颜色块是否降低透明度只按费用点数判断：该颜色费用点数为 0 时整个颜色块降透明度，产费点数为 0 不单独触发。“张”为统计范围内至少包含一个对应费用点或产费点的卡牌数量，按 `quantity` 计数。平均法术力值默认排除地牌。法术力颜色使用固定六色色板：白色 `#FBF6D3`、蓝色 `#96C4D4`、黑色 `#B0A8A3`、红色 `#D88F73`、绿色 `#93CBA4`、无色 `#A9A8A8`。白、蓝、黑、红、绿取自 Archidekt `aang` 页面，无色取自 `eldrazi` 页面；卡组列表六色比例带共用同一色板，不得使用系统主题色或随机色替代。法术力曲线强调色为 `#FA890D`。法术力图标使用 Scryfall 符号表：Scryfall 颜色码为 `W/U/B/R/G`，`C` 是无色法术力符号而不是颜色标识；基础符号可按 `https://svgs.scryfall.io/card-symbols/{symbol}.svg` 拼接，复杂符号按 `/symbology` 返回的 `svg_uri` 映射。卡牌详情名称右上角同样按 `mana_cost` 的符号顺序显示这些图标，不显示花括号纯文本；双面牌切换牌面时同步切换费用图标。页面不展示价格、浏览量、社区作者、热度或赛制合法性。

整体法术力曲线下方紧接“法术力曲线分组（Mana curve by）”模块。模块标题与选择器位于同一行，标题在左侧，分组下拉固定对齐到右上角，与抽到概率和数量分布的筛选位置保持一致。该模块使用单个下拉选择器，依次支持“类型”“颜色”“功能标签”，默认选择第一个“类型”，不得把三个维度同时显示为三个固定图表。每个分组值渲染一个 0 至 8+ 的子曲线框，桌面端一行最多 6 个，超过 6 个自动换行。颜色视图固定按白、蓝、黑、红、绿、无色展示并使用对应法术力颜色；类型和功能标签视图只展示当前统计范围实际存在的分组，使用统一的曲线强调色。子曲线沿用主牌范围和 `quantity` 计权；类型使用系统稳定顺序。功能标签通过牌张的 `oracle_id` 关联 `oracle_tagging` 和 `oracle_tag`，统计当前范围内全部牌张实际具有的全部标签，不按 `weight` 过滤；同一张牌具有多个标签时分别计入每个对应标签，因此不同标签的统计不是互斥分组。每个标签的牌张数量为关联该标签的牌张 `quantity` 之和，按牌张数量从高到低排序，数量相同时按标签名称稳定排序。功能标签视图默认展示前 12 个标签；只有实际标签数超过 12 个时才在列表底部显示“显示全部”，展开后展示剩余全部标签并将操作改为“收起”，收起后回到前 12 个。展开内容直接增加统计抽屉长页高度并沿用整页滚动，不建立子区域滚动条。

“法术力曲线分组”下方显示“抽到概率（Probability of draw）”表格。条件栏固定使用“至少 x 张”的概率语义，不提供“恰好”等模式切换；默认条件为“至少 1 张，抽 7 张”。“至少张数”和“抽牌张数”均使用紧凑的减号、数值、加号步进控件，并允许直接输入整数；至少张数最小为 1，抽牌张数最小为至少张数、最大为当前统计范围的总张数，减号到达下限后置灰。分组下拉提供“类型”“法术力值”“功能标签”“产费颜色”，默认选择“类型”。条件栏左侧依次显示“抽到概率　至少 [x] 张　抽 [n] 张”，分组下拉独立对齐到条件栏最右侧；不在分组下拉前显示“按”。

所有统计分类选择器统一使用全局优先顺序“类型 → 颜色 → 法术力值 → 功能标签 → 产费颜色”。每个模块仅从该顺序中保留自己支持的选项，并默认选中保留选项中的第一个；不得为单个模块另设不同排序或记忆上次选择作为初始值。设计稿用四份完整统计状态覆盖选择器内容：默认“类型／类型／类型”、组合“颜色／法术力值／颜色”、功能标签“功能标签／功能标签／功能标签”、产费颜色“类型／产费颜色／类型”，三项依次对应法术力曲线分组、抽到概率、数量分布。

法术力曲线分组的子曲线卡片使用固定列宽，桌面端每行最多 6 个；末行不足 6 个时左对齐并保持与首行相同宽度，不得拉伸填满剩余空间。模块外框按实际内容行数自适应高度，颜色分组固定六项一行时必须收缩为单行高度。抽到概率选择“功能标签”时默认显示排序后的前 12 个，实际标签超过 12 个时显示“显示全部”；展开后显示全部并改为“收起”，使用统计抽屉整页滚动，不建立表格内部滚动。数量分布只有功能标签为容纳最多 24 项使用窄柱；类型和颜色按实际分组数均分横向空间并使用更宽的柱体。

卡组统计抽屉的整个外框及其内部纵向内容必须使用内容驱动高度，不得设置固定总高度，也不得为了对齐不同选择器状态而在底部保留空白。任一模块因选择器切换、功能标签展开或收起而改变高度时，抽屉外框同步扩展或收缩，并保持既定模块间距和底部内边距。统计遮罩页的总滚动长度由抽屉当前实际高度计算，但必须沿用原滚动边界：初始位置的抽屉顶部固定为 `y = 150 px`，滚动到底时抽屉底边固定为 `y = 750 px`。内容高度变化只改变两者之间的最大滚动距离，不得改变顶部或底部露出的 150 px 模糊背景。

表格列为当前分组名称、“牌张数”和“概率”。牌张数按 `quantity` 计权；概率使用不放回抽样的超几何分布计算在总牌数 `N`、该行牌张数 `K`、已抽张数 `n` 下至少抽到 `x` 张的概率。计算范围继续沿用主牌加指挥官、排除备牌与备选的统计口径。类型使用 `scryfall_card_type.type_group = main` 并按系统类型顺序展示；法术力值按 `cmc` 从 0 到 8+ 展示实际存在的档位；功能标签使用 `oracle_id → oracle_tagging → oracle_tag`，展示统计范围内实际存在的全部标签，并按牌张数从高到低、标签名称稳定排序，不套用法术力曲线功能标签的“前 12 个”折叠限制。产费颜色从 `produced_mana` 读取，固定按白、蓝、黑、红、绿、无色、不产费显示七行，包括数量为 0 的颜色；颜色行的 `K` 表示能够产生对应颜色法术力的牌张数量，不使用产费点数，一张牌能够产生多种颜色时分别计入每个对应颜色行。`produced_mana` 为空或不存在的牌按 `quantity` 计入“不产费”，并且不进入前六个颜色行。多类型牌、多标签牌及多色产费牌均可能分别计入多个关联行，因此各行牌张数与概率均为独立统计，不能跨行相加。任一条件改变时前端立即重新计算并刷新整张表格，不重新请求卡组数据。

抽到概率表格下方显示“数量分布（Quantity of）”图表。标题位于左侧，分组下拉位于同一行最右侧，提供“类型”“颜色”“功能标签”，默认选择“类型”。数量均按 `quantity` 计权。类型和颜色使用纵向柱状图，柱高与柱顶数字表示牌张数量，横轴显示分组名称；类型使用与概率表格相同的主类型口径和系统顺序，颜色固定按白、蓝、黑、红、绿、无色顺序并使用既定六色色板，多色牌分别计入其具有的每一种牌面颜色，无色只统计 `colors_mask` 为空的牌。

功能标签同样使用纵向柱状图。标签按牌张数量从高到低排列，数量相同按标签名称稳定排序，只显示排序后的前 24 个；超过 24 个的标签不渲染，也不提供展开、第二行或内部滚动。24 根窄柱固定在同一行并共用同一纵轴比例。每根柱顶显示牌张数，柱底标签允许最多三行换行并保持居中，不旋转文字；超出标签区域的名称省略，完整内容通过悬停提示显示。多类型、多色和多标签分组均可能重复计入同一张牌，各项之间不能求和作为卡组总张数。切换分组只在前端重组已加载的统计数据，不重新请求卡组数据。

## 8. 卡组编辑

使用简单文本编辑器编辑卡组。

基础格式：

```text
4 Lightning Bolt
2 Counterspell
1 Sol Ring
```

卡组记录：

```text
逻辑卡牌 + 编辑数量
```

不要求用户指定：

- Set
- 收藏编号
- 语言
- 普通或闪卡
- 展示版本

无法识别的行必须明确提示，不能静默丢弃。

卡组必须记录每张牌所属的分区，并按分区展示。至少支持：

- 主牌（mainboard）
- 备牌（sideboard）
- 指挥官（commander）
- 备选区（maybeboard）

同一逻辑卡牌可以分别出现在多个分区；每个分区内只保留一条数量汇总。分区在卡组中的展示顺序必须稳定。

分区为系统固定类型，不支持用户创建、重命名、删除或调整分区顺序。固定展示顺序为：指挥官、主牌、备牌、备选区；不存在的分区不显示。

主牌、备牌和指挥官计入卡组数量、拥有量比较和卡组统计；备选区只用于展示候选牌，不计入这些结果。

简单文本格式需要提供明确的分区标题语法。首个分区标题之前的卡牌行视为主牌；无法识别的分区标题与无法识别的卡牌行一样，必须明确提示，不能静默归入主牌。

## 9. 卡组展示版本

卡组不支持手动指定印刷版本。

系统自动选择展示版本：

```text
拥有的版本
    ↓
愿望单版本
    ↓
最新印刷版本
```

自动选择只决定卡组展示的卡图和印刷版本，不影响卡组记录。

选择版本时不考虑：

- 是否被其他卡组使用
- 所有卡组使用总数
- 当前卡组编辑数量
- 拥有数量是否足够
- 可用数量或分配数量

存在多个拥有版本或愿望版本时的同级选择规则，等待卡牌数据模型确认。

## 10. 卡组拥有数量

卡组中的实际拥有数量按逻辑卡牌汇总：

```text
所有 Set
+ 所有语言
+ 普通卡
+ 闪卡
```

每张卡计算：

- 当前卡组编辑数量
- 实际拥有数量
- 所有卡组编辑总数
- 使用该牌的卡组数量

## 11. 卡组异常状态

正常情况不显示状态。

异常状态互斥，只显示优先级最高的一项：

```text
数量不足
    ↓
卡组占用
    ↓
正常无标识
```

### 11.1 数量不足

条件：

```text
当前卡组编辑数量 > 实际拥有数量
```

显示：

```text
数量不足 N
```

计算：

```text
N = 当前卡组编辑数量 - 实际拥有数量
```

### 11.2 卡组占用

仅在当前卡组不存在“数量不足”时判断。

条件：

```text
使用该牌的卡组数量 > 1
且
所有卡组编辑总数 > 实际拥有数量
```

显示：

```text
卡组占用 N
```

计算：

```text
N = 所有卡组编辑总数 - 实际拥有数量
```

### 11.3 判断顺序

```text
if 当前卡组数量 > 实际拥有数量
    显示「数量不足」
else if 使用卡组数 > 1
     且所有卡组数量 > 实际拥有数量
    显示「卡组占用」
else
    不显示状态
```

### 11.4 示例

实际拥有 4 张：

| 当前卡组 | 所有卡组合计 | 使用卡组数 | 显示 |
| ---: | ---: | ---: | --- |
| 5 | 8 | 2 | `数量不足 1` |
| 4 | 8 | 2 | `卡组占用 4` |
| 3 | 6 | 2 | `卡组占用 2` |
| 2 | 4 | 2 | 不显示 |
| 4 | 4 | 1 | 不显示 |

异常状态不影响卡组保存和自动版本选择，不执行实体卡分配，只用于提示和统计。

卡组列表与卡组详情必须共用同一异常名称、色相和图标语义，但列表不复制详情页的深色背景。卡组列表的两类标识均不使用背景或描边，只显示文字和图标：数量不足使用红色文字及警告图标，卡组占用使用琥珀色文字及叠层图标。卡组列表只显示异常类型，不显示异常项数量。“查看卡组”固定在卡片右下角，并通过底栏弹性占位保持位置；异常标识隐藏时也不得左移。

区域标题中的异常汇总采用紧凑文案“数量不足 x种·缺x张”和“卡组占用 x种·缺x张”，数字与“种”“张”之间不增加空格。统一的 144 px 汇总框必须至少支持“种”和“缺”同时为三位数；超过三位数时再使用千位缩写或悬停完整值，不得通过临时扩大其中一类汇总框破坏宽度一致性。

两种牌张状态使用各自的悬停提示，均只展示当前卡组数量、实际拥有数量、所有卡组编辑总数和使用卡组数四项指标，不增加结论行。提示框从对应状态页签向卡牌列内部展开，渲染层级高于所有卡牌与类型列，不得被相邻或后续类型列遮挡。提示框及连接箭头必须随页签位置同步移动，箭头中心始终与页签保持同一水平基准。提示框四角统一保持 8 px 圆角，连接箭头由对应侧边框直接向外突出：尖头保持 6 × 12 px，不伸入气泡内部；尖端向状态页签内部重叠 2 px。箭头内部使用提示框底色，仅描绘两条状态色斜边，不描绘贴近提示框的竖直底边；侧边遮罩必须覆盖完整的 12 px 连接高度，气泡边框上下不得露出 1 px 短线，连接处不得出现突出边或 `|` 形分隔线。箭头渲染在页签边框上层，以遮住重叠位置的一小段页签边框。不得使用纯状态色实心三角、旋转方块或双重描边。

卡组详情中的指挥官、主牌和备牌必须在牌张级直接展示上述异常。状态标识使用贴在卡牌右侧外缘的 `12 × 22 px` 图标页签，页签顶部距卡图顶部 7 px。卡位必须拆成外层卡位与内层卡图：内层 150 × 210 px 卡图保持 8 px 圆角裁切，使左上角数量三角标服从同一圆角；页签由外层卡位承载并伸入相邻类型列留白，不受卡图裁切。页签贴卡牌的左侧边不显示描边，仅保留上、右、下三边及右侧圆角，使页签与卡牌连续连接；页签不得覆盖牌名、右上角费用或左上角数量三角标。数量不足使用暗红色警告页签，卡组占用使用暗琥珀色叠层页签。所有卡图均不显示外边框，异常状态不得通过卡图描边表达。页签本身不显示长文字，悬停时显示“数量不足 N”或“卡组占用 N”，并提示四项数量明细；点击状态页签不得触发卡牌详情跳转。

卡组编辑页整体复用卡组详情页的背景、顶部导航、主牌、备牌、备选类型列、卡牌堆叠、异常状态和卡组统计书签。卡组名称在编辑页改为可编辑输入框；标头摘要保留总张数和收集率但去除更新时间；标头右侧只显示带加号图标的“增加卡牌”橙色主按钮，作为添加新牌的入口。详情页的“复制卡组”和“复制卡组代码”不得在编辑页显示。

点击“增加卡牌”必须在当前卡组编辑页上方打开增加卡牌悬浮窗，并使用半透明暗色遮罩阻止背景交互。桌面端悬浮窗必须相对视口居中并固定为 940 × 690 px，不得随搜索结果数量改变尺寸；整体沿用卡牌详情页的纸张底色、白色内容面、浅灰边框和圆角视觉。搜索结果使用固定高度的内部滚动视口，滚动结果不得带动背景编辑页或改变悬浮窗位置。关闭按钮必须固定在悬浮窗最右上角，不得紧跟标题排列；点击关闭按钮或点击悬浮窗之外的遮罩背景均关闭悬浮窗，悬浮窗内部点击必须阻止遮罩关闭事件。关闭悬浮窗不得撤销已经加入主牌区的牌张，并应恢复打开前的编辑页滚动位置。

增加卡牌悬浮窗通过卡名模糊匹配全量逻辑卡，搜索结果必须按 `oracle_id` 去重，不得将不同系列、语言或印刷版本展开成重复结果。结果数量统一显示“找到 N 张”，不得显示“逻辑卡”字样。结果列表不得显示“卡牌／数量／操作”等说明表头；每行固定高 58 px，左侧只显示常规字重的翻译后卡牌名，不加粗且不额外显示类别。超出可视数量时只滚动悬浮窗内部的结果视口。鼠标悬浮结果行时，直接在悬浮窗结果区域上层显示“卡图 + 翻译信息”的复合气泡，不得为气泡预留左侧栏或空白。气泡固定宽 440 px，高度由翻译文字自然撑开；右侧信息区必须限定宽度并自动换行，卡牌名、类别和规则文字均不得越出气泡。左侧为完整代表性卡图，右侧沿用卡牌详情页信息面板视觉。代表性卡图优先选择用户拥有版本，否则选择最新版本，离开结果行后隐藏。复合气泡只覆盖视觉层，不得阻断结果行、数量输入或加入按钮的交互。

每条搜索结果右侧提供正整数数量输入框和“加入”按钮。数量输入框维持 62 × 34 px 的详情页浅灰样式，数量默认 1、最小为 1，不接受 0、负数或小数；“加入”按钮固定为 72 × 34 px，使用普通卡牌 Stepper 的浅灰底色 `#F0F2EE`、深色文字、`#D6DBD6` 边框和 8 px 圆角，不得使用绿色或橙色。点击“加入”将当前输入数量加入主牌区；主牌已存在同一 `oracle_id` 时累加数量，不得创建重复记录，不存在时进入对应固定类型列并按卡组规则重新排序。点击加入不得关闭悬浮窗或重置数量输入；连续多次点击必须每次按当前输入值继续累加。每次加入后立即更新主牌与卡组总张数、异常汇总、收集率和卡组统计。悬浮窗打开期间，遮罩后的卡牌点击、拖拽、数量操作和卡组统计书签均不可交互。

卡组编辑页必须在卡组名称标头与主牌区域之间提供卡组代码导入区。“卡组代码”区域标签使用常规字重，不得加粗或形成与卡组名称竞争的标题层级。区域标头参照“我的卡牌”页面的系列分组标头，采用“卡组代码 + 浅色横向分隔线 + 最右侧箭头”的 34 px 单行结构，整条标头均为展开／折叠点击热区；展开态仅显示向上箭头，折叠态仅显示向下箭头，不显示“收起”或“展开”文字。区域默认展开。桌面原型中展开态导入区高 350 px、左右内边距 32 px，其中多行文本框横向铺满内容区、高 256 px，供用户粘贴系统生成的通用卡组编辑码；文本框为空时只在编辑区内部显示灰色占位文案“在此粘贴卡组代码…”，开始输入或粘贴后按常规编辑区逻辑隐藏，不显示其他辅助说明。下方右侧显示 32 px 高的“读取卡组配置”按钮，按钮文字使用常规字重、不加粗。折叠后只保留 46 px 高的区域标头，隐藏文本框和读取按钮；再次展开必须恢复此前输入内容，不得清空或重新请求。粘贴或输入代码不得自动修改卡组；只有点击读取按钮后才解析和校验。解析成功时只将代码中的主牌、备牌和备选单向填充到下方卡牌编辑区，不修改卡组名称。此后在卡牌区执行增加、删除、数量加减或分区调整，不得反向修改文本框中已有代码；只有再次点击读取按钮时，才重新以文本框当前内容覆盖卡牌编辑态。解析失败时显示错误且不得改变当前编辑态；用户确认保存前不得覆盖已保存的卡组。导入区必须占用独立页面高度，不得压缩或裁切主牌、备牌和备选区域。

卡组最终保存入库时，文本框中的原始代码不得作为最终事实来源。系统必须以主牌、备牌和备选区域中的真实卡牌、数量和分区为准，重新生成标准格式的卡组代码，并将生成后的代码随卡组数据入库。因此，读取后继续编辑卡牌区时，允许文本框代码与当前卡牌区暂时不一致。标准代码的具体语法、字段和序列化顺序等待后续参考网站确定，在此之前不得自行固化临时格式。

编辑页的卡组统计书签必须相对主牌区域保持与卡组详情页相同的位置关系。由于代码导入区新增 350 px 页面高度，桌面原型中的书签初始纵坐标由详情页的 `y = 310 px` 同步调整为 `y = 660 px`；其视口固定、打开抽屉、随抽屉滚动和关闭方式继续沿用卡组详情页规则。

卡组代码区域折叠时，主牌、备牌、备选和卡组统计书签必须随页面流共同上移，不得在原位置留下空白。桌面折叠态相对展开态减少 304 px，卡组统计书签原型纵坐标同步调整为 `y = 356 px`，继续保持与主牌区域的相对位置。

卡组编辑页悬停卡牌时，除沿用详情页的完整看牌和下方牌张让位行为外，还必须在当前卡图底部显示快速数量编辑浮层。桌面原型中浮层尺寸为 96 × 30 px，相对 150 × 210 px 卡图定位为 `x = 27 px、y = 172 px`。浮层不重复显示当前数量，卡牌左上角数量三角标是唯一数量展示。操作栏必须设计为单个 7 px 圆角的分段矩形，不得渲染两个独立胶囊；内部使用 1 × 16 px 浅色竖线二等分，左右各为 46.5 × 28 px 的透明按钮热区，左半减少、右半增加。两个完整半区均为点击命中区，不得只允许点击符号；正常可用状态下减号和加号统一使用白色，半区不使用独立背景、描边或圆角。浮层不得改变卡图尺寸、牌列宽度或堆叠间距，也不得给卡图增加外边框。数量变化需要同步更新牌张数量标识、区域与卡组总张数、收集率和统计数据。

卡组编辑页中的卡牌点击不得跳转卡牌详情。首次点击卡牌时，将其切换为固定看牌状态，效果等同鼠标长时间悬停：卡牌保持完整展示、下方牌张保持让位，鼠标移开后不收起；再次点击同一张牌时取消固定状态并恢复原堆叠。同一时间只允许一个固定看牌状态，点击另一张牌时切换固定目标；临时悬停其他牌不得自动取消已固定卡牌。数量加减按钮、异常状态页签及其他局部操作必须阻止卡牌点击事件；形成拖拽后的指针释放不得触发固定状态切换。只有未形成拖拽且落在卡牌非局部操作区域的完整点击才执行该交互。

卡组编辑页允许牌张数量从 1 减到 0；只有数量已经为 0 时减少按钮才禁用并将减号置灰。数量刚变为 0 时，卡牌必须在当前悬停期间暂时保留，左上角数量标识显示 0，加号继续保持白色可用，以便用户在离开前恢复数量。鼠标离开该卡牌时，如果数量仍为 0，才将卡牌从当前分区列表移除并重新计算牌列；若已恢复到 1 或更高则取消移除。不得在数量变为 0 的点击瞬间移除卡牌。

卡组编辑页支持通过拖动卡牌在主牌、备牌和备选区域之间移动。按下后快速移动并开始拖拽时只移动 1 张；保持按下约 350 ms 后再拖拽时移动该逻辑卡在来源区域中的全部数量。指针按下时开始长按计时：在 350 ms 到达前移动距离超过约 4 px，立即进入单张拖动模式；在移动阈值内保持到 350 ms 后进入整条拖动模式。只按下并松开、未形成拖动时不得改变数据；数量为 1 时两种模式结果相同。当前界面不显示该手势的提示短语。

单张拖动成功后，来源区域数量减 1，目标区域对应逻辑卡数量加 1；目标区域不存在该牌时新建数量为 1 的记录，来源数量减为 0 时移除来源记录。整条拖动成功后，来源记录移除，其全部数量并入目标区域对应逻辑卡；目标区域已存在该牌时合并数量，不得生成重复记录。拖动开始后原位置保留同尺寸占位，卡图以浮层跟随指针；三个区域均为有效投放目标，进入时显示轻量目标高亮。投放成功后，卡牌按自身类型自动进入目标区域的固定类型列，并按法术力值、翻译后语言名称和稳定卡牌标识重新排序；拖拽只改变所属区域，不提供任意手工排序。

拖拽投放只更新前端未保存编辑态，并立即重新计算来源与目标区域张数、牌张数量标识、异常汇总、标头总张数、收集率和卡组统计。拖拽不得反向修改卡组代码文本框；最终保存仍以三个卡牌区的真实状态重新生成标准代码。数量加减操作栏、异常状态页签及其他卡牌局部按钮必须阻止拖拽启动。数量为 0、等待鼠标离开移除的卡牌不得开始拖动。拖动取消、按 Escape 或投放到三个区域之外时必须恢复原位置，不改变编辑态。

鼠标和触屏必须共用 Pointer Events 或等效指针状态机。触屏点击卡牌同样切换固定看牌状态，点击局部按钮仍执行对应局部操作；触屏快速拖动移动 1 张，保持约 350 ms 后拖动移动全部，计时与移动阈值和鼠标一致。触屏卡牌区域必须禁止系统原生长按菜单、文字选择和图片拖拽；确认进入拖动模式后捕获当前指针，直到成功投放、取消或抬起。当前阶段不考虑键盘替代交互，界面不显示该拖动手势的提示短语。

异常卡位的定稿尺寸为：外层卡位 162 × 210 px、内层卡图 150 × 210 px、状态页签 12 × 22 px；页签相对卡位定位为 `x = 150 px、y = 7 px`。悬停提示框固定为 232 × 92 px、8 px 圆角；连接尖头固定为 6 × 12 px，侧边框遮罩固定为 3 × 12 px。当前原型的提示框与尖头已随页签同步下移 3 px；实现时必须以页签为相对定位锚点维持该视觉关系，不得直接使用原型画布的绝对坐标。

主牌和备牌区域标题分别汇总“数量不足 x 种 · 缺 x 张”和“卡组占用 x 种 · 缺 x 张”；两类异常汇总框必须使用相同宽度，桌面原型统一为 144 px，不得按文案类型使用不同尺寸。没有某类异常时隐藏对应汇总。“种”按 `oracle_id` 去重。数量不足的“缺 x 张”是该区域各牌 `max(当前卡组编辑数量 - 实际拥有数量, 0)` 的合计；卡组占用的“缺 x 张”是该区域各牌 `max(所有卡组编辑总数 - 实际拥有数量, 0)` 的合计。主牌、备牌、备选的区域总数统一使用“共 x 张牌”，并固定在区域标题横条最右侧；异常汇总位于总数左侧。备选不参与拥有量比较，不显示牌张异常或区域异常汇总。

## 15. 加载卡牌数据

### 15.1 功能目标

服务需要提供卡牌数据加载功能，将指定目录中的卡牌 JSON 数据全量导入外置卡牌数据库。

- 这是系统维护功能，不是个人收藏、愿望单或卡组的导入功能。
- 只加载只读卡牌元数据库，不得修改个人数据数据库。
- 每次执行均为全量替换，不做增量更新、合并或单条修复。
- 加载后的卡牌表内容必须完全来自本次读取的 JSON 文件。
- `scryfall_card` 是卡牌、印刷版本及英文原文的实体数据源；卡牌查询、列表和详情必须以其记录为主体。
- `zhs_*.json` 是可选的简体中文翻译、本地化及辅助词典数据，只能覆盖或补充 Scryfall 实体的展示字段，不得独立产生卡牌实体。
- 中文字段缺失、为 `null` 或仅含空白时，必须回退使用 `scryfall_card` 的对应字段。

### 15.2 数据目录

卡牌 JSON 目录由 Docker 映射到容器外部，并通过配置指定容器内路径，例如：

```text
CARD_DATA_DIR=/data/card-data
```

要求：

- Docker volume 使用只读挂载。
- 接口不能接收客户端传入的任意目录或文件路径。
- 服务只能读取 `CARD_DATA_DIR` 下约定的文件。

### 15.3 必需文件

每次加载必须同时读取以下九个 NDJSON/JSONL 文件：

1. `scryfall_card.json`
2. `zhs_card.json`
3. `zhs_flavor.json`
4. `zhs_oracle.json`
5. `zhs_ruling.json`
6. `zhs_set.json`
7. `zhs_type.json`
8. `rulings.jsonl`
9. `oracle-tags.jsonl`

任意文件缺失、无法读取、为空或包含非法 JSON 时，加载失败，现有卡牌库必须保持不变。

### 15.4 操作前完整确认

在影响现有卡牌表之前，服务必须完整读取九个文件，而不是只检查文件存在或只读取第一行。

每个文件至少检查：

- 文件存在、是普通文件、可读且非空。
- 从第一行到文件末尾的每一行都能解析为 JSON 对象。
- 每行包含该对象的必需字段。
- 记录文件大小、总行数和 SHA-256。
- 已确认唯一的关联字段不存在重复值。
- `zhs_*.json` 通常只将各文件的关联键或组合唯一键视为非空必需字段；`zhs_ruling.comment` 还必须非空，因为它用于生成跨数据源稳定规则键。翻译字段仍允许为 `null`。

只有全部九个文件都完成预检后，才能进入数据库加载阶段。

### 15.5 加载方式

业务结果要求为：删除旧卡牌表，按固定 Schema 重新建表，并插入本次 JSON 的全部数据。

考虑到 MySQL DDL 会隐式提交，不能直接先删除正在使用的正式表，否则导入失败会留下空库或半成品库。实现时采用等价但更安全的方式：

1. 完成全部文件预检。
2. 创建一组新的临时卡牌表。
3. 再次流式读取九个文件并导入临时表。
4. 校验普通源表的导入行数与预检行数一致；合并后的 `ruling_translation` 行数不得少于 `zhs_ruling.json` 的预检行数。
5. 再次确认文件大小和 SHA-256 未在导入期间变化。
6. 使用 MySQL 多表 `RENAME TABLE` 原子切换新旧表。
7. 切换成功后删除全部旧卡牌表。

在切换前发生任何错误时立即停止数据库操作，不自动清理临时表，现有正式卡牌表保持不变；遗留临时表用于排查并由运维人员处理。只有原子切换成功后才进入 `cleaning` 阶段，按表删除本次切换产生的旧表，任一删除失败即停止后续数据库操作。

### 15.6 表范围

加载逻辑只能操作以下固定白名单表：

- `scryfall_card`
- `card_translation`
- `flavor_translation`
- `oracle_translation`
- `ruling_translation`
- `scryfall_oracle_ruling`
- `oracle_tag`
- `oracle_tag_relation`
- `oracle_tagging`
- `set_translation`
- `type_translation`
- `scryfall_card_keyword`
- `scryfall_card_type`
- `scryfall_card_frame_effect`
- `scryfall_card_promo_type`
- `scryfall_set`
- `scryfall_color`
- `scryfall_language`
- `scryfall_layout`
- `scryfall_frame`
- `scryfall_frame_effect`
- `scryfall_finish`
- `scryfall_game`

禁止枚举数据库中的所有表后直接删除。执行前必须确认当前连接的数据库名称等于配置的卡牌数据库名称，防止误操作个人数据数据库。

### 15.7 导入要求

- NDJSON 必须逐行流式读取，不能将整个文件加载到内存。
- 标量 JSON 字段使用 MySQL 对应标量类型存入主表或字典表，不得将整行记录保存为单个 `document` JSON 列。
- 颜色、颜色标识、颜色指示符、工艺、游戏平台和 Attraction 灯号为取值受限的多值属性，在 `scryfall_card` 中使用可索引位掩码列保存。
- `produced_mana` 不使用字典或关联表；按源数组顺序以逗号连接后直接存入 `scryfall_card.produced_mana VARCHAR(64) NULL`，不限制元素值域。
- 关键词、类型词、牌框效果和推广类型通过多对多关联表保存。
- 源文件字符串主键去除首尾空白后，按 Unicode 不区分大小写比较重复；多值字符串派生关系采用相同的比较规则去重，并保留第一次出现的原始大小写，避免仅有大小写或首尾空白差异的数据与 MySQL `utf8mb4_unicode_ci` 唯一键规则冲突。
- 不建立费用符号关联表；完整费用保存在 `mana_cost`，法术力值查询使用 `cmc`，颜色查询使用颜色及颜色标识位掩码。
- `artist_ids` 按源数组顺序以逗号连接后保存到 `scryfall_card.artist_ids VARCHAR(2048) NULL`；`former_names` 以压缩 JSON 数组文本保存到 `oracle_translation.former_names LONGTEXT NULL`。两者均不建立关联表或索引。
- `preview` 不参与检索，以规范 JSON 文本存入 `scryfall_card.preview` 的可空 `LONGTEXT` 列，不单独建表。
- `rulings.jsonl` 的每条规则使用规范化英文 `comment` 的 SHA-256 生成 `ruling_key`；规范化只统一换行、弯引号、不换行空格和首尾空白，正文不折叠或改写。
- `scryfall_oracle_ruling` 使用自增 `id` 区分每一条源记录，并保存 `oracle_id`、`ruling_key`、来源和发布日期；`ruling_translation` 保存英文规则及翻译文本。Scryfall 中存在但翻译来源文件缺失的规则必须补成 `translation NULL` 的英文行，已有翻译不得被覆盖。
- `rulings.jsonl` 中同一 `oracle_id` 和正文可能因不同发布日期而重复出现；所有源记录必须分别保留，不得覆盖或合并。自增 `id` 只作为本次加载结果的内部行标识，业务关联仍使用 `oracle_id` 和 `ruling_key`。
- `ruling_translation.extra` 接受任意合法 JSON 值并以压缩 JSON 文本保存到 `LONGTEXT`，不建立 JSON 子表。
- `oracle-tags.jsonl` 只导入 `oracle` 标签。标签主表仅保留标签 ID、名称、说明和逗号连接的别名，不保存 Scryfall URI、slug、对象类型等本系统不用的元数据。
- `parent_ids` 和 `child_ids` 统一展开为 `oracle_tag_relation(parent_tag_id, child_tag_id)`，来自两个方向的相同关系去重；卡牌标签展开为 `oracle_tagging(oracle_id, tag_id, weight)`，`weight` 原样保存且不使用字典或枚举限制。
- 颜色、语言、布局、卡框、卡框效果、工艺和游戏平台的代码与说明由 Scryfall 官方元数据生成小型只读字典；卡牌主表保存代码或位掩码。
- 系列信息从 `scryfall_card` 的 `set_id`、`set_code`、`set_name`和 `set_type` 动态汇总到 `scryfall_set`，卡牌主表仅保留 `set_id` 关联。
- `cmc`、`mana_cost`、`type_line`、牌名、稀有度和发行日期保留在 `scryfall_card` 主表；`cmc`、`mana_cost`、牌名、稀有度和发行日期建立普通索引，类别筛选使用派生的 `scryfall_card_type` 表。
- 主键、翻译关联键和常用查询字段必须建立索引。全量原子换表不建立跨表外键约束，关联完整性由预检和业务查询保证。
- JSON 的 `null` 原样写入 MySQL `NULL`。
- 除上述明确的位掩码、`produced_mana` 字符串连接、字典关联和检索派生字段外，卡牌原始标量值不做业务转换。
- 普通、闪卡和蚀刻闪的计数归类只发生在业务查询层，不写回卡牌库。
- 使用批量插入，并记录每个文件的读取行数和插入行数。
- 解析或插入失败时需要记录文件名和行号，但不得记录完整卡牌 JSON。
- 同一服务实例同一时间只允许执行一个加载任务。
- 加载任务必须在开始、阶段切换、逐文件校验完成、逐文件导入完成、行数核对、原子切换和最终结果时输出结构化日志；任务运行期间每 30 秒输出一次包含任务 ID、当前阶段、当前文件和累计行数的心跳日志。批量写入过程不按固定行数额外输出进度日志。

### 15.8 接口行为

建议接口：

```http
POST /api/v1/card-data/load
```

该操作使用异步任务：

- 启动成功返回 `202 Accepted` 和任务 ID。
- 已有任务执行时返回 `409 Conflict`。
- 任务状态至少包括：`validating`、`preparing`、`importing`、`verifying`、`switching`、`cleaning`、`completed`、`failed`。
- 提供按任务 ID 查询状态的接口；启动和查询响应返回任务 ID、当前状态、开始时间，以及存在时的结束时间和错误详情。
- 每个文件的统计和处理进度只写入结构化日志，不通过任务状态接口返回。

当前不实现完整用户认证，但该接口必须具备最低限度保护：

- 默认关闭，通过配置显式启用。
- 请求必须携带固定确认文本 `LOAD_CARD_DATA`。
- 不允许请求指定数据库名、表名或文件路径。
- 部署时应只向内网或受反向代理限制的管理路径开放。

### 15.9 日志边界

卡牌数据加载属于系统维护任务，不计入用户操作日志。

任务结果至少记录：

- 任务 ID。
- 开始时间和结束时间。
- 每个文件的大小、SHA-256、预检行数和插入行数。
- 新旧表切换结果。
- 最终状态和错误摘要。
