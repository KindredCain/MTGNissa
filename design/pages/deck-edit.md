# 卡组编辑页

对应原型：`Screen / Deck Edit — Full Page`、`Screen / Deck Edit — Code Collapsed`、`Screen / Deck Edit — Add Card Floating Window`、`Screen / Deck Edit — Leave Confirmation Modal`。不同桌面尺寸由共用响应式规则处理，不复制独立尺寸画板。

## 页面结构

- 页面整体沿用卡组详情页的深绿色背景、顶部导航、主牌、备牌、备选单行类型列，以及固定在浏览器右侧的卡组统计书签。
- 主牌、备牌、备选仍按详情页确定的类型列、卡图尺寸、堆叠间距、数量三角标和异常状态页签展示；编辑态不另建一套卡牌布局。
- 编辑页是独立路由页面，不覆盖卡组详情页原型。

## 编辑页标头

- 卡组名称改为可编辑输入框。当前桌面原型宽 360 px、高 38 px、圆角 7 px，使用轻透明底色和琥珀色编辑态描边，名称文字后显示橙色铅笔图标，长名称时图标仍保留在输入框内。
- 标头摘要只显示“共 115 张 · 收集率 88%”，不显示更新时间。
- 编辑页标头只提供“增加卡牌”“选择封面”“保存卡组”，不保留复制代码或删除卡组的隐藏按钮。三个按钮使用统一橙色样式，封面选择模式下仅“选择封面”切换为深绿底橙色描边；四个编辑页状态保持一致。
- 点击“选择封面”只在当前编辑页原地进入封面选择模式，不跳转页面、不打开悬浮窗、不增加提示区，也不改变卡组代码区、卡牌区域或其他布局。进入编辑页时，前端直接使用详情响应中的 `cover_printing_uuid` 标记当前封面并初始化待提交值，不接收或处理封面的 `oracle_id`。进入选择模式后仅将“选择封面”按钮切换为反色，并把指挥官、主牌、备牌和备选区内的卡牌作为可选目标；点击卡图只把该卡牌的 `printing_uuid` 记录为当前未保存编辑态的 `cover_printing_uuid` 并退出选择模式，不执行固定看牌、拖拽或详情跳转。按 Esc 或再次点击“选择封面”取消选择模式并保留原封面。空卡组禁用该按钮。
- 已选封面逻辑卡在所有分区中的卡图使用 3 px 橙色高亮描边；不增加右上角或右下角标签，避免遮挡法术力费用、卡名或异常页签。同一 `oracle_id` 跨分区出现时高亮同步。该描边只在卡组编辑页显示，卡组详情页不得显示哪张牌被选作封面。删除该逻辑卡在全部分区中的最后一条记录时自动清空封面选择，不自动改选其他卡。键盘用户可聚焦卡牌后确认选择；封面配置不得只依赖悬停或拖拽。
- “增加卡牌”是向当前卡组添加新牌的入口，点击后打开本页定义的增加卡牌悬浮窗。
- “保存卡组”是编辑页唯一的入库入口。点击后前端提交当前 `cover_printing_uuid`，把主牌可见区域的指挥官列作为 `commander`、其余类型列作为 `mainboard`，连同 `sideboard`、`maybeboard` 提交四个真实分区；封面和各分区卡牌都只提交后端返回的 `printing_uuid`，由后端统一解析、校验并保存对应 `oracle_id`。前端不生成或提交标准代码，后端按既定规则根据名称和四个真实分区生成标准格式卡组代码并入库。指挥官列允许为空，保存不得要求至少存在一张指挥官。保存成功后跳转到当前卡组详情页。保存失败时停留在编辑页并保留当前页面中的修改，同时打开全局统一错误弹窗。

## 保存与离开确认

- 每次进入编辑页重新取得已保存卡组，开启独立编辑会话。未保存内容仅保留在当前会话，不因后台重新取数而覆盖；关闭页面或确认放弃后丢弃，不提供持久草稿或自动保存。
- 当前页面存在尚未成功保存的修改时，用户点击网站一级导航、卡组相关标签或其他会离开当前编辑路由的站内入口，必须先打开 `Screen / Deck Edit — Leave Confirmation Modal`，不得直接跳转。
- 离开确认弹窗固定在当前浏览器视口中央，使用半透明暗色阻断遮罩压暗底层页面，不使用背景模糊。弹窗打开期间锁定底层页面滚动和全部交互；点击遮罩不得关闭弹窗，也不得触发底层导航。
- 弹窗只提供“继续编辑”和“放弃修改并离开”两个明确选择，不设置右上角关闭按钮。“继续编辑”关闭弹窗并完整保留当前页面修改；“放弃修改并离开”丢弃当前页面全部未提交修改，并继续执行用户原本选择的导航。
- 点击“保存卡组”并保存成功后的详情页跳转不触发离开确认。没有修改，或最近一次保存成功后尚未产生新修改时，离开编辑页也不显示确认弹窗。

## 增加卡牌悬浮窗

- 候选卡、卡牌上下文、导入结果及编辑提交统一使用 `printing_uuid = mtgnissa_card_printing.uuid`；双面或多牌面使用主牌面语言印刷 UUID。封面版本字段记为 `cover_printing_uuid`；后端仍解析并保存 `oracle_id`，不改变卡组的逻辑卡持久化粒度。
- 名称搜索仍从 `mtgnissa_card_printing.printed_name` 命中候选；语言印刷行缺少图片 ID 时，仅卡图来源回退关联的 `mtgnissa_card.scryfall_id`，不替换卡牌上下文请求、加入及保存、封面提交中的业务标识。
- 增加卡牌的正式候选只包含 `oracle_id` 非空的卡牌。缺少 `oracle_id` 的卡不允许加入卡组；卡牌上下文、代码导入及保存也必须由后端校验并拒绝，不能以公开印刷 ID 代替 Oracle 身份。全局搜索维持现有查询规则，不增加无 Oracle 卡牌必须可搜到的要求。
- 当前增加卡牌画板为节省画板数量，同时绘制名称联想下拉框与结果行悬停气泡，分别表达两个独立交互状态，不代表实际同时显示；实现中按当前输入或结果行悬停状态分别展示。
- 搜索输入框与联想列表视为同一焦点区域，内部移动不关闭联想。

- 点击“增加卡牌”打开视口居中的悬浮窗，基准尺寸为 940 × 702 px，并受公共弹窗高度上限约束。遮罩阻断背景交互与滚动；结果数量变化不改变弹窗位置和尺寸。
- 悬浮窗整体沿用卡牌详情页的视觉：纸张底色 `#F1F2EC`、白色内容面、`#D7DBD6` 边框与 12 px 圆角。搜索结果承载在固定高度的内部滚动视口中，滚动结果不得带动背景编辑页或改变悬浮窗位置。
- 悬浮窗打开期间锁定底层卡组编辑页：不得点击、拖拽或滚动底层页面，滚轮、触控滑动和键盘滚动不得穿透遮罩。悬浮窗标题与搜索区保持固定；只允许搜索结果视口在悬浮窗内部滚动。关闭后恢复底层编辑页打开前的滚动位置。
- 关闭按钮固定在悬浮窗最右上角，不得紧跟标题排列。悬浮窗只能通过该关闭按钮关闭；点击悬浮窗之外的遮罩或底层页面不关闭，也不得触发底层操作。关闭只结束搜索操作，已经加入主牌区的数量继续保留。
- 搜索框以 `mtgnissa_card_printing.printed_name` 为名称查询字段。输入和已提交查询必须分离：用户输入、粘贴或删除文字时只更新本地输入值，不自动发起 `%q%` 模糊查询；点击搜索框右侧的“搜索”按钮时，无论当前关键字的字符类型或长度，均直接提交当前输入并请求后端，不设置最小输入长度。请求期间禁用搜索按钮，重复点击不得并发提交同一查询；新查询成功后替换旧结果、更新“找到 N 张”并把结果视口重置到顶部，输入变化但尚未再次提交时继续保留上一次已提交结果。结果以 `oracle_id` 去重，不把同一逻辑卡的不同系列、语言或印刷版本展开成多条。去重后固定按英文卡名不区分大小写 A–Z 排序，同名时按 `oracle_id` 升序兜底；排序由后端执行并绑定游标。搜索结果计数统一显示为“找到 N 张”，不显示“逻辑卡”字样。结果列表不显示“卡牌／数量／操作”等说明表头；每行固定高 58 px，左侧只显示常规字重的翻译后卡牌名，不加粗、不额外显示类别。结果过多时只滚动悬浮窗内部的结果视口。
- 输入框内容变化时，先去除首尾空白；当输入中包含至少 3 个英文字母或至少 2 个中文字符时，在短暂防抖后自动按 `printed_name LIKE 'q%'` 请求名称联想。联想名称去重且最多返回 5 条，只用于填充输入框，不替换或刷新主搜索结果。联想下拉框覆盖显示在输入框下方，不改变悬浮窗或主结果区尺寸。点击联想项后，将完整名称回填到输入框、关闭下拉框，并立即执行与点击“搜索”按钮相同的 `%q%` 正式查询。输入未达到联想触发条件时关闭联想；后发请求优先，过期的联想响应不得覆盖当前输入对应的结果。
- 搜索结果采用内部滚动和持续加载，不使用页码按钮；列表不随结果数量改变外框尺寸。视口高度不足时只压缩弹窗及结果区高度、减少可见行数，卡图、文字和控件保持原尺寸。
- 悬停搜索结果时显示“卡图 + 翻译信息”气泡，使用后端选定的代表版本，只展示正面。气泡宽 440 px、高度受视口限制，超长说明内部滚动；允许从结果行移入气泡，离开气泡立即隐藏。
- 每条结果右侧提供独立的正整数数量输入框，默认值为 1，以及“加入”按钮。数量输入框维持 62 × 34 px 的详情页浅灰输入样式；“加入”按钮为 72 × 34 px，使用普通卡牌 Stepper 的浅灰底色 `#F0F2EE`、深色文字、`#D6DBD6` 边框和 8 px 圆角，不使用绿色或橙色。数量输入只决定该结果下一次加入的数量，最小为 1，不接受 0、负数或小数。
- 点击“加入”时，若该逻辑卡的编辑上下文尚未缓存，先禁用当前行的数量输入和加入按钮，并以候选项的 `printing_uuid` 请求卡牌上下文；请求成功后才将当前输入数量加入主牌区，请求失败时不得加入并打开统一错误弹窗。上下文已经缓存时直接加入，不重复请求。主牌已有同一 `oracle_id` 时累加数量，不创建重复记录；不存在时使用上下文中的 `type_group` 在对应固定类型列创建记录并重新排序。
- 加入成功不会关闭悬浮窗，也不会重置该行数量输入。用户可连续多次点击，每次都按当前输入值继续累加；每次加入成功后立即刷新主牌总数、卡组总张数、异常统计、收集率和卡组统计。
- 加入期间，当前行按钮显示“加入中”，数量输入与加入按钮禁用并以 30% 不透明度淡化，其他行加入及搜索仍可操作；有加入任务时不允许关闭悬浮窗。编辑页统一维护任务状态，在请求侧阻止保存、读取配置等冲突操作；底层交互由弹窗遮罩阻断，不额外增加按钮禁用样式。任务成功或失败后恢复当前行；关闭或刷新整个浏览器页面按原有未保存提示处理，结束会话后不再应用迟到结果。
- 悬浮窗打开时，背景中的卡牌点击、拖拽、数量操作和卡组统计书签均不可交互；关闭后恢复原编辑状态和滚动位置。

## 卡牌悬停与数量编辑

- 鼠标移动到堆叠卡牌时，继续沿用卡组详情页的看牌交互：当前牌完整展示，位于其下的牌向下让位，使卡名和整张卡图可见。
- 悬停与说明气泡沿用卡组详情页规则，同时只展开一张牌；悬停其他牌时收起原牌并清除原固定状态。翻面后说明同步切换，气泡内可以滚动且不会触发底层卡牌展开。
- 点击卡图固定展开，不跳转详情；再次点击已固定卡牌只取消固定，继续按悬停状态决定是否收起。点击空白取消固定并收起。固定只保留卡图展开，不强制显示说明气泡；数量不足和卡组占用提示不参与固定逻辑。
- 数量加减按钮、异常状态页签及其他卡牌局部操作必须阻止卡牌点击事件；完成拖拽后的指针释放也不得触发固定看牌切换。只有未形成拖拽、且落在卡牌非局部操作区域的完整点击才切换固定状态。
- 编辑态在完整展示的卡牌底部叠加数量操作浮层。浮层位于卡图内部，不改变牌列宽度、堆叠间距，也不给卡图增加外边框。
- 当前原型的数量浮层为 96 × 30 px，距卡牌左侧 27 px、顶部 172 px，使用半透明深色胶囊、1 px 浅色描边与轻阴影。
- 浮层不重复显示当前数量，卡牌左上角数量三角标是唯一数量展示。操作栏使用单个 96 × 30 px、7 px 圆角的分段矩形，不渲染两个独立胶囊；内部以 1 × 16 px 浅色竖线二等分，左右各为 46.5 × 28 px 的透明按钮热区，左半减少、右半增加。
- 两个完整半区都是点击命中区域，不仅是 `−`、`+` 符号本身。正常可用状态下减号和加号统一使用白色；两个半区不使用独立背景、描边或圆角。
- 数量为 1 时允许继续减少到 0。数量变为 0 后，卡牌在当前悬停期间暂时保留，左上角数量标识更新为 0，减少按钮立即禁用并将减号置灰；增加按钮保持白色可用，点击可恢复为 1 并取消待移除状态。
- 数量为 0 时，在悬停卡牌、关联说明气泡或固定期间保留；收起时若仍为 0 才移除。收起同时清理展开位置和气泡状态。
- 零数量条目暂留时保留封面选择，收起并真正移除该逻辑卡在全部分区的最后一条记录后才清空。保存时过滤零数量条目；若封面逻辑卡在全部分区都没有正数量记录，则提交空封面。
- 原型在生物列最后一张牌上展示悬停或点击固定后的编辑样例，当前数量 1 仅显示在卡牌左上角数量三角标中。

## 拖拽调整卡牌分区

- 首版分区移动沿用已确认的拖拽交互，按钮、菜单及键盘换区入口列入后续版本，不自行增加。编辑页支持拖动卡牌，在主牌、备牌和备选三个可见区域之间移动；主牌内的指挥官列是独立的真实分区投放目标。拖拽分为两种模式：按下后快速移动并开始拖拽时只移动 1 张；保持按下约 350 ms 后再拖拽时移动该逻辑卡在来源分区中的全部数量。
- 指针按下时启动长按计时；在 350 ms 到达前移动距离超过约 4 px，立即进入单张拖动模式，不继续等待。指针在移动阈值内保持到 350 ms 后进入整条拖动模式。只按下并松开、未形成拖动时不改变数据。数量为 1 时，两种模式结果相同。
- 开始拖动后，原位置保留同尺寸占位，卡图以提升阴影的浮层跟随指针；主牌、备牌和备选区域均作为投放区域。指挥官列在拖动过程中不得根据 `can_be_commander` 显示额外高亮、禁用态或其他资格提示，其视觉反馈必须与其他投放区域保持一致。用户在指挥官列松开时才依据后端 DTO 的 `can_be_commander` 判断：值为 `true` 时完成投放，值不为 `true` 时取消本次投放并返回原分区和原位置。前端不得通过卡名、单独的传奇属性或类型栏文本自行推断资格。
- 单张拖动成功后，来源区域数量减 1，目标区域对应逻辑卡数量加 1；目标区域不存在该牌时新建数量为 1 的记录。来源数量减为 0 时移除来源记录。整条拖动成功后，来源记录移除，其全部数量并入目标区域对应逻辑卡；目标区域已存在该牌时合并数量，不生成重复记录。
- 放入目标区域后，前端只更新当前未保存的编辑态。拖入指挥官列时分区改为 `commander`；从指挥官列拖入主牌其他类型列时改为 `mainboard`；拖入备牌或备选时分别改为 `sideboard`、`maybeboard`。除指挥官列外，卡牌直接依据后端返回并缓存的单值 `type_group` 进入固定类型列，不得根据 `statistics.type_groups` 或类别文字重新推导；`type_group = other` 时进入最右侧“其他”列。任一可见区域出现 `other` 时动态显示该列，移除页面最后一张 `other` 牌后隐藏，并按当前可用宽度决定向右扩展还是启用区域横向滚动。列内按详情页既定的“法术力值从低到高 → 颜色组合按颜色数及 WUBRG 色环顺序 → 英文卡名不区分大小写 A–Z → `printing_uuid` 升序”顺序重新排序；多色组合使用详情页定义的固定顺序，拖拽只改变真实分区，不提供任意手工排序。增加卡牌、读取卡组配置和保存前整理同样使用该列内排序规则。
- 投放成功后立即更新来源区域与目标区域总张数、牌张数量标识、异常汇总、标头总张数、收集率和卡组统计。卡组代码文本框保持原内容，不因拖拽反向更新；最终保存时前端把三个可见区域还原为 `commander`、`mainboard`、`sideboard`、`maybeboard` 四个真实分区并提交，由后端根据提交内容重新生成标准代码。后端必须按与 `can_be_commander` 相同的规则重新校验指挥官分区，不得信任前端判断；失败时不自动移区或部分保存。
- 数量加减操作栏、异常状态页签及其他卡牌局部按钮必须阻止拖拽启动，避免点击操作被识别为拖动；应从卡图其他区域开始拖动。
- 数量为 0、正在等待鼠标离开移除的卡牌不得开始拖动。拖动取消、按 Escape、或放在三个分区之外的无效位置时，卡牌恢复到原区域和原位置，不改变编辑态。
- 拖拽成功后收起来源牌；若来源原本固定且仍有剩余，则保留固定展开，但不强制显示气泡。来源已空时清理原展开状态，目标不自动固定；拖拽失败或取消保留原固定状态。
- 本期按桌面原型交付，触屏专项交互与非拖拽换区入口均属后续版本。

## 卡组代码导入

- 在卡组名称标头与主牌区域之间固定显示“卡组代码”导入区，不放入主牌卡牌滚动内容中。
- “卡组代码”只作为区域标签，使用常规字重，不加粗，避免与上方可编辑卡组名称形成标题层级冲突。
- 区域标头参照“我的卡牌”页面的系列分组标头，采用“卡组代码 + 浅色横向分隔线 + 最右侧箭头”的 34 px 单行结构。分隔线填充标题与箭头之间的剩余宽度，保持轻量分组层级。
- 整条区域标头均可点击切换展开状态，不把点击范围限制在箭头上。右侧不显示“收起”或“展开”文字；展开态仅显示向上箭头，折叠态仅显示向下箭头。
- 默认展开。折叠后隐藏多行文本框和“读取卡组配置”按钮，只保留 46 px 高的区域标头；再次展开时恢复此前输入的卡组代码，不清空、不重新请求。
- `Screen / Deck Edit — Code Collapsed` 展示折叠后的完整页面状态：主牌、备牌、备选整体上移 304 px，折叠区不保留隐藏内容的空白高度。
- 导入区总高 350 px，左右内边距 32 px。多行文本框横向铺满内容区，高 256 px，使用 8 px 圆角、深色半透明底和 1 px 浅色描边。文本框为空时只在编辑区内部显示灰色占位文案“在此粘贴卡组代码…”；用户开始输入或粘贴后，占位文案按常规编辑区逻辑消失，不保留额外说明文字。
- 文本框用于粘贴系统生成的通用卡组代码，最多允许 1,000 行。卡牌行输入格式为 `AMOUNT CARDNAME (SETCODE) NUMBER *F*`，其中 Set 代码、收藏编号和 `*F*` 均可省略。粘贴和输入本身只改变文本框内容，不自动修改当前卡组。
- 文本框下方右侧显示 32 px 高的橙色“读取卡组配置”按钮，按钮文字使用常规字重、不加粗。点击后先解析并校验卡组代码：只使用数量、卡名和分区；忽略 Set 代码、收藏编号及闪卡标记，不以这些信息选择印刷版本。解析成功后，对响应中的 `printing_uuid` 去重并排除已经缓存的上下文，再按每批最多 200 项取得卡牌编辑上下文；只有解析请求和全部上下文批次均成功且返回完整时，才按 `About / Commander / Deck / Sideboard / Maybeboard` 一次性填充卡组名称、指挥官、主牌、备牌和备选。没有分区标题的纯卡牌列表按 `Deck` 读取。
- `About` 区中存在合法、非空且未超出名称长度上限的 `Name ` 后文本时，同步更新顶部可编辑卡组名称。没有 `Name ` 行、`Name ` 后为空白或名称超出长度上限时，解析响应的 `name = null`；这只表示没有有效名称覆盖，不影响卡牌解析，前端必须保留读取前的当前名称输入值，不得清空或回退为已保存名称。`Commander`、`Deck`、`Sideboard`、`Maybeboard` 分别映射 `commander`、`mainboard`、`sideboard`、`maybeboard`。`Commander` 中任一牌的 `can_be_commander` 不为 `true` 时，后端必须使整次读取失败；不得自动移入 `Deck`，也不得部分覆盖当前编辑状态。标题独占一行且保存时使用固定大小写和顺序。未知标题或无法唯一识别的卡名同样必须使整次读取失败。
- 同一分区内重复卡名合并并累加数量，跨分区保持独立。具体印刷版本仍由后端按“拥有版本 → 愿望单版本 → 最新印刷版本”选择，前端不得根据导入文本自行筛选。
- 卡组代码与卡牌编辑区不是双向绑定。读取完成后，用户在下方增加、删除、加减数量或调整分区，都不得反向修改文本框中已有的代码；只有再次点击“读取卡组配置”时，才重新使用文本框当前内容覆盖下方卡牌编辑态。
- 解析请求或任一上下文批次失败时打开全局统一错误弹窗，不在导入区内显示行内错误，也不部分修改当前编辑态；读取成功只更新尚未保存的卡牌编辑态，用户确认保存前不得覆盖已保存的卡组。
- 最终保存入库时，前端不提交文本框中的原始代码，也不维护标准代码；只提交当前卡组名称以及指挥官、主牌、备牌和备选区域的真实卡牌、数量及分区。后端必须以这些提交内容为唯一事实来源，按 `About / Commander / Deck / Sideboard / Maybeboard` 顺序重新生成标准代码并入库。
- 标准代码的 `About` 区保存 `Name 当前卡组名`；卡牌行只保存 `AMOUNT CARDNAME`，不得保存导入时携带的 Set 代码、收藏编号或 `*F*`。没有牌张的 `Commander`、`Sideboard` 或 `Maybeboard` 可以省略，分区之间保留一个空行。
- 编辑页画布高度由 1480 px 增加为 1830 px，为导入区增加完整空间，不压缩主牌、备牌或备选区域。
- 编辑页的“卡组统计”书签固定在浏览器视口 `y = 356 px`，不随代码区展开、折叠或正文滚动移动；打开抽屉时保持相同屏幕纵坐标，仅水平向左移动。

## 保留规则

- 卡牌异常状态、区域汇总、类型列定位及统计抽屉均沿用卡组详情页规则。
- 悬浮窗受公共弹窗高度上限约束；高度不足时减少可见结果行数，保留原控件和文字尺寸，不等比缩放。
- 卡牌数量变化应同步更新牌张数量标识、区域总张数、标头总张数、收集率和卡组统计；这些都只是当前页面状态，点击“保存卡组”并提交成功后才入库。提交失败时不得回滚或清空页面中的当前修改。
