# 卡牌中心 / 全部卡牌 / Set 列表

## 1. 页面定位

- 页面名称：Set 列表。
- 对应原型：`Screen / All Cards — Set Index`。
- 入口路径：`卡牌中心 → 全部卡牌`。
- “全部卡牌”的默认落地页就是 Set 列表，不先展示全量卡牌网格。
- 点击某个 Set 后进入该 Set 的全卡牌列表。
- 本页面只描述全部卡牌范围，不统计或展示用户拥有数量、愿望单数量等个人数据，也不提供任何收藏或愿望单快捷操作。

## 2. 导航层级

页面顶部固定使用两层结构：

1. 一级导航：网站标题，以及“卡牌中心 / 卡组 / 操作日志”。
2. 卡牌中心二级标头：左侧显示当前二级菜单“全部卡牌”，说明文字固定为“查看全部卡牌”；右侧提供“全部卡牌 / 我的卡牌 / 愿望单”切换。
3. 内容面包屑：“卡牌中心 > 全部卡牌”。

正文中不得再重复出现“全部卡牌 / 我的卡牌 / 愿望单”，也不增加“按系列”等额外菜单层级。

补充约定：卡组和操作日志没有二级菜单列表；卡牌详情为跨入口复用页面，不固定显示卡牌中心二级标头。

“卡牌中心 > 全部卡牌”面包屑与搜索、筛选、排序工具栏组成吸顶区域。滚动下面的系列列表时，两者固定在持久导航下方，不随列表内容滚动。工具栏及控件高度为 36 px，搜索框宽度为 250 px，控件间距为 9 px；搜索文字使用 12 px，筛选和排序文字使用 11 px。

面包屑中的“卡牌中心”和“全部卡牌”均跳转到本 Set 列表页。

## 3. 数据来源

### 3.1 Set 基础信息

Set 数据来自 `mtgnissa_set`：

- `code`：Set 唯一标识及系列缩写。
- `name`：系列英文名称。
- `set_type`：系列类型。

翻译系列名称通过 `set_translation.code = mtgnissa_set.code` 逻辑关联取得；没有翻译名称时回退到 `mtgnissa_set.name`。`set_translation.set_id` 只是翻译记录自身的主键，不作为 Set 的业务标识。

发行日期直接使用 `mtgnissa_set.released_at`。卡牌数量直接使用 `mtgnissa_set.card_count`，其口径为该系列纳入的卡面数量，页面请求期间不再实时聚合。普通系列的可用语言直接读取 `mtgnissa_set.languages`；Token 系列的该字段固定为 `NULL`。上述字段均不使用个人数据库统计。

### 3.2 系列类型

- 类型筛选值来自 `mtgnissa_set.set_type`。
- `set_type` 是数据源提供的原始字符串，不在前端维护另一套系列类型枚举。
- 系列分类只使用“系列类型”下拉筛选，不再提供额外快捷分类栏；语言筛选保留。
- 不再同时提供“扩展系列 / 核心系列 / 指挥官 / 选集 / 特殊系列”等快捷分类栏，避免与类型下拉重复，也避免引入数据字典中没有定义的自建分组。

### 3.3 可用语言（卡牌原语言）

语言枚举来自 `scryfall_language`，不得在前端硬编码语言列表。UI 表头、筛选器和按钮统一显示“语言”或“可用语言”，具体选项和按钮直接原样展示 `display_name`，不暴露语言代码或“原语言”术语。Set 列表页面固定按 `sort_order` 升序、`code` 升序兜底后只取前 11 个语言；其余特殊语言仍保存在字典中，但不出现在本页按钮和筛选项中。该范围是数量规则，不得通过判断具体语言代码确定截止位置。

某个 Set 的可用语言按以下规则派生：

1. 查询 `scryfall_language`，按 `sort_order` 升序、`code` 升序兜底后只取前 11 个语言代码和 `display_name`。
2. 读取当前 `mtgnissa_set.code` 对应行的 `languages`，得到该普通系列实际存在的语言代码；Token 系列的 `languages = NULL`，不显示可用语言按钮。
3. 将上述页面展示语言与 Set 实际语言做左连接。
4. 存在对应卡牌记录的语言正常显示；不存在的语言置灰。

顶部语言下拉框使用与语言按钮相同的 `ORDER BY sort_order ASC, code ASC LIMIT 11` 范围和顺序。选择语言后，只以 `languages` 包含至少一种所选语言的顶层父 Set作为命中分组；命中父 Set 的全部子孙仍随组返回，子孙自身的语言不参与筛选。

语言状态同时承担导航作用：

- 正常显示的语言按钮可以点击，进入该 Set 对应语言的卡牌列表。
- 置灰语言不可点击。
- 整条 Set 横条都是跳转热区。普通 Set 点击系列名称、缩写、类型、牌数、发行日期、语言单元格空白或横条其他非按钮区域时，进入该行从左到右第一个正常显示、非置灰语言对应的 Set 卡牌列表；Token Set 直接进入该 Token Set 的完整卡牌列表，不携带语言参数。
- 点击具体可用语言按钮时，直接进入该 Set 对应语言的卡牌列表，并阻止事件继续触发行级跳转；按钮跳转优先于横条跳转。
- 置灰语言按钮不响应点击，也不得因为点击置灰按钮而触发行级跳转；语言按钮之间和语言单元格剩余空白仍属于横条热区。
- 前端不得再使用“简体中文 → 英文”或其他隐藏语言优先级。横条目标语言只由当前行实际展示顺序中的最左侧可用语言决定。
- 普通 Set 如果数据异常导致没有任何可用语言，该行整体进入不可跳转状态；该规则不适用于 `set_type = token`，Token Set 始终按无语言入口跳转。

原型中的具体语言状态只是规则样例，不代表真实完整数据。

## 4. 系列标识

- Set 列表不显示系列图标，只使用系列名称和系列缩写识别系列。
- 页面不得为了系列图标额外下载、缓存或热链 Scryfall SVG 资源。
- 系列缩写直接使用 `mtgnissa_set.code`，不再承担图标加载失败时的替代占位逻辑。

## 5. 查询与筛选

页面提供以下查询条件：

- 系列名称或缩写关键字查询。
- 语言筛选。
- 系列类型筛选。
- 排序。

### 5.1 系列名称或缩写关键字查询

- 中间搜索框只做名称关键字搜索，不解析右上角全局搜索框支持的卡牌查询语法；关键字作为 Set list 接口的查询参数。
- 查询目标是 `parent_code IS NULL` 的顶层父 Set，不是浏览器中已经加载的行；子孙 Set 不独立参与名称或缩写匹配。
- 对顶层父 Set 的系列名称和 `code` 执行不区分大小写的模糊包含匹配。父 Set 命中后，其全部子孙 Set 始终随父 Set 返回。
- 例如输入 `so` 可以命中顶层父系列 `SOS`；若 `SOA`、`PSOS` 是其子系列，它们随父系列展示，不作为独立搜索命中项。
- 输入变化后重新执行后端全库查询，清空当前已加载行并重置分页游标。
- 清空查询后恢复完整 Set 结果集。

### 5.2 筛选组合

- 系列名称/缩写关键字、语言和系列类型条件可以组合，全部条件只作用于 `parent_code IS NULL` 的顶层父 Set。
- 子孙 Set 不独立参与查询或筛选；父 Set 命中后，不论子孙 Set 自身是否满足当前名称、语言或系列类型条件，其完整子树都随父 Set 返回并保持缩进。
- 任一查询条件变化后都重新执行后端查询，并重置分页游标和滚动加载状态。
- 筛选控件只保留一套，不在正文其他位置重复提供等价入口。

### 5.3 多选下拉与选项

所有筛选下拉框都是多选，排序下拉框仍是单选。关闭下拉框后的摘要文案统一为：未选择或全选显示“字段：全部”；只选择一项显示该项具体名称；选择两项及以上显示“字段：已选 N 项”。

打开多选下拉框时，以当前已提交条件初始化一份临时选择；用户在下拉框内勾选或取消选项时只更新临时选择，不立即查询。点击下拉框外任意区域时，下拉框立即关闭并提交最终选择；只有选择发生变化时，才在关闭完成后发起一次查询、废弃旧游标并从首批结果重新加载。选择未变化时关闭不发请求。下拉框不提供“确定”或“取消”按钮。对应展开态见 `.pen` 中的 `Prototype / Multi-select Filter Dropdown — Open`。

- 语言：选项为 `scryfall_language` 按 `sort_order` 升序、`code` 升序兜底后的前 11 个语言代码和 `display_name`，不在前端写死列表；界面原样展示 `display_name`，查询仍提交语言代码；选择后只保留 `languages` 包含至少一种所选语言的顶层父 Set。
- 系列类型：只从 `parent_code IS NULL` 的顶层父 Set 读取 `set_type` 非空去重值；只存在于子 Set 或 Token Set 的类型不进入筛选选项。各去重值按产生该值的最小父 Set `code` 升序排列，最小 `code` 相同时按 `set_type` 升序兜底。
- 同一筛选器内多项使用 OR，不同筛选器之间使用 AND。

## 6. 排序

- 排序下拉框与筛选控件之间使用一条加深后的浅灰绿色竖分隔线 `|`，明确区分筛选和排序操作。分隔线固定为 1 × 22 px，并在 36 px 工具栏中上下居中。
- 可选排序项：
  - 发行日期：新到旧、旧到新；默认使用新到旧。
  - 系列名称：A 到 Z、Z 到 A。
  - 系列缩写：A 到 Z、Z 到 A。
  - 卡牌数量：多到少、少到多。
- 不提供 Block/Group 排序；虽然 `mtgnissa_set` 保存 `block`，当前页面仍没有对应筛选或排序交互。
- 用户选择的排序只作用于 `parent_code IS NULL` 的顶层父 Set；父 Set 在主排序值相同时统一按 `code` 升序兜底，保证游标分页顺序稳定。
- 每个父 Set 的全部子孙节点始终紧跟父节点并按层级缩进，不参与父 Set 之间的全局排序。同一父节点下先展示普通子 Set，再展示 Token Set；两组内部均固定按 `released_at ASC -> code ASC` 排列，其中 `code ASC` 是数据库主键顺序的稳定兜底。存在多层普通子 Set 时按相同规则递归排序，并以前序遍历方式在各节点后展开其子树。
- 排序由后端作用于完整父 Set 查询结果集，而不是当前已加载部分；子树顺序不随排序下拉选项改变。
- 切换排序后重新查询，清空当前行并重置分页游标。

## 7. 列表字段

每行至少展示：

- 系列名称。
- 系列缩写。
- 系列类型。
- 卡牌数量。
- 发行日期。
- 普通 Set 按固定字典顺序取得的前 11 个页面语言及其可用/置灰状态；Token Set 的语言单元格留空，不显示语言按钮。

点击行为：

- 点击可用语言按钮：进入该 Set 对应语言的卡牌列表。
- 点击整条普通 Set 横条中除语言按钮以外的区域：进入该行从左到右第一个可用语言的卡牌列表。Token Set 整行直接进入该 Set 的全部 Token 列表，不携带语言参数。
- 语言按钮使用独立点击热区并阻止行级事件；置灰语言按钮不可点击，也不触发行级跳转。

## 8. 加载方式

- 页面不显示分页按钮和页码。
- Set 列表使用后端分页查询，因为每行需要关联系列中文名、发行日期和可用语言等数据，不一次性返回全部 Set。
- 使用滚轮连续浏览；接近列表底部时自动请求下一批数据。
- 后端只对命中的顶层父 Set 使用当前搜索、筛选和排序条件执行稳定游标分页；每个已分页父 Set 的完整子树随父节点一次返回，不得在父子节点之间截断。同一批实际返回的可见行数可以因子孙节点数量而超过父 Set 批量大小。
- 同一游标请求期间不得重复发起加载；成功后把新行追加到当前列表。
- 搜索、筛选或排序变化时废弃旧结果和旧游标，从第一批重新查询。
- 已无更多结果时停止观察底部触发器，并显示结束状态。
- 单批返回数量和接近底部时的触发阈值在后端 list 接口开发及联调时，根据查询耗时、响应体积和页面渲染表现确定，并保留为可调参数；该调优不得改变游标分页和滚动自动加载方式。

页面应区分以下状态：

- 首次加载。
- 继续加载。
- 空结果时系列列表直接为空，不显示专用空状态、说明文字或清空条件入口。
- 加载失败时保留已显示内容并打开全局统一错误弹窗，不在列表内增加错误卡片或重试入口。
- 已加载全部结果。

## 9. 父子层级

- `mtgnissa_set.parent_code` 是父子关系的权威来源；后端按该字段构建完整树并返回明确层级，前端只消费后端结果，不根据发行时间、系列名称或 `set_type` 自行推断。
- `parent_code = NULL` 的记录是参与查询、筛选、排序和游标分页的顶层父 Set；其全部子孙记录只作为随附子树展示。
- 前端根据后端返回的层级缩进所有子孙 Set；无论当前是否存在名称、语言或系列类型条件，子树都跟随命中的顶层父 Set，查询条件不单独隐藏子节点。
- 后端必须防止父子关系循环；父代码缺失或层级关系无效属于 Card DB 数据错误，不得由前端猜测或静默改为其他父节点。
