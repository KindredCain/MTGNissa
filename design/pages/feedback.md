# 全局空列表、错误与成功反馈规则

## 1. 对应原型

- `Prototype / Unified Error Modal`
- `Prototype / Copy Deck Code — Success Toast`

## 2. 空列表

- 所有列表查询结果为 0 时，保留当前页面标题、导航、搜索筛选工具栏、表头或结果计数，并把列表内容区直接渲染为空。
- 不增加专门的空状态插画、说明卡片、清空筛选按钮、返回入口或新建入口，也不为不同的“首次无数据”和“筛选无结果”维护不同原型。
- 空列表不是错误，不打开错误弹窗。

## 3. 统一错误弹窗

- 请求失败、业务校验失败、剪贴板写入失败、解析失败以及后端返回的未预期错误，统一使用 `Prototype / Unified Error Modal` 的居中错误弹窗反馈，不再使用行内错误、轻量提示、页面内重试卡片或错误 Toast。
- 弹窗固定在当前浏览器视口中央；半透明暗色遮罩覆盖当前视口并阻止底层页面点击、滚动、拖拽和键盘操作。弹窗不显示右上角关闭叉；点击遮罩不关闭，用户只能通过底部“关闭”按钮退出。
- 弹窗宽度固定为 520 px，高度由标题、主错误文案和后端返回的安全错误信息自然撑开。后端错误信息直接作为普通正文显示并自动换行，不增加“错误信息”标题、外框或底色容器；整体达到 `calc(100vh - 64px)` 后不再增长，只让正文区滚动，标题和底部“关闭”按钮始终可见。
- 错误发生后保留操作前的页面数据、筛选条件、分页位置、编辑内容和滚动位置。关闭弹窗只返回原页面，不自动重试、刷新或清空状态。
- 已知业务错误优先显示后端提供且允许直接面向用户的安全文案；后端未预期错误统一显示“发生意外错误，操作未完成。请稍后重试。”不得显示堆栈、SQL、内部路径或原始异常对象。
- 外部卡图无法加载继续使用固定尺寸的缺图占位，因为这是单个资源的展示回退，不弹出错误弹窗，避免一个列表产生多个阻断弹窗。

## 4. 收藏与愿望单快捷操作

- 我的卡牌数量加减、愿望单星标以及卡牌详情“我的收藏”中的数量和愿望单操作，均采用后端确认后更新，不执行乐观更新。
- 用户发起操作后，当前卡位或当前详情收藏面板中的全部收藏与愿望单操作热区立即禁用；数值和星标保持请求前状态，不显示预估结果。后端返回前的再次点击不排队、不合并，也不重复发送请求。
- 返回成功后才更新对应数量或星标，然后重新启用操作。返回失败时保持原数值和星标不变，重新启用操作并打开统一错误弹窗。
- 成功后不重新请求整个列表；当前页面继续使用已确认的新状态。数量归零或愿望单取消的列表项仍保留到重新进入页面并取得后端权威列表时才消失。

## 5. 复制卡组代码反馈

- 卡组列表更多菜单和卡组详情页的“复制卡组代码”共用同一反馈。
- 写入剪贴板成功后显示 `Prototype / Copy Deck Code — Success Toast`：文案为“卡组代码已复制”，不提供按钮或关闭图标，不接受鼠标、触控或键盘焦点，不建立遮罩，也不阻断原页面的任何点击、滚动或键盘操作。
- 成功提示显示约 2.5 秒后自动淡出并移除；显示期间用户可以继续操作页面。
- 写入剪贴板失败时不显示成功提示，改为打开统一错误弹窗。
