# 操作日志页面设计规则

## 1. 页面定位

- 页面名称：操作日志。
- 对应原型：`Screen / Operation Log` 以及八个 `Screen / Operation Log — Detail Modal / {操作类型}` 状态。不同桌面尺寸由共用响应式规则处理，不复制独立尺寸画板。
- 入口为一级导航“操作日志”，不存在二级菜单或二级切换按钮。
- 页面只记录真实改变业务状态的操作，不记录查看、搜索、筛选或系统卡牌数据加载。

## 2. 页面结构

- 桌面原型按常用的 1440 × 900 px 浏览器视口设计。
- 顶部复用全站一级导航，并将“操作日志”设为当前项。
- 一级导航下使用与卡组列表一致的 100 px 深绿色渐变身份栏，标题为“操作日志”，说明为“查看收藏、愿望单与卡组的变更记录”。身份栏右侧不放操作按钮。
- 操作日志只有一个列表页面。正文依次为自定义日期区间查询栏、每日类型汇总表格和页码区；点击汇总中的操作类型后，在当前页面上方打开明细悬浮窗。
- 汇总列表和悬浮窗明细都使用传统页码分页，不使用行内折叠、独立详情页或滚动自动加载。

## 3. 日期查询与顺序

- 页面只提供自定义日期区间查询，不提供“最近 7 天”“最近 30 天”等预设范围。
- 查询栏包含“开始日期”和“结束日期”两个自然日输入框，只显示年月日，不接受或展示时、分、秒；操作区只提供“查询”按钮，不显示“清空”或其他辅助按钮。
- 日期条件直接作用于 `operation_date`。开始日期和结束日期均为空时查询全部日志；只填写一端时按单侧日期边界查询；两端均填写时使用闭区间，完整包含开始日期、结束日期及中间每个自然日的全部操作。
- 开始日期晚于结束日期时不发送请求，并打开全局统一错误弹窗说明日期范围无效；查询栏内不重复显示行内错误。
- 点击“查询”后按输入框当前值从第一页重新加载。需要查询全部日志时，由用户将两个日期输入框置空后点击“查询”。
- “查询”按钮固定为 72 × 34 px，复用 `Screen / Deck Edit — Add Card Modal` 中“加入”按钮的浅灰底色 `#F0F2EE`、深色文字、`#D6DBD6` 描边和 8 px 圆角。
- 不提供操作类型筛选。
- 结果固定按 `occurred_at DESC, id DESC` 从新到旧排列，不显示排序选择项，也不允许前端切换升降序。
- 查询栏只显示在汇总页。右侧显示当前日期条件下的“日期＋操作类型”汇总行总数，例如“共 18 条汇总”，不是原始 `operation_log` 行数。

## 4. 每日类型汇总页

- 汇总的基本键为 `operation_date + action_type`。同一自然日内同一种操作只显示一行，行内数量为当前日期条件实际包含的 `operation_log` 条数；没有发生的类型不显示。
- 表格列固定为“日期、操作类型、操作次数”。日期显示中文年月日和星期。
- 日期固定从新到旧排列；同一天内按增加卡牌、减少卡牌、加入愿望单、移出愿望单、创建卡组、删除卡组、复制卡组、修改卡组的稳定顺序展示，不提供排序控件。
- 每页固定显示 10 条汇总，按页码请求后端；不提供每页条数切换，也不使用无限滚动。
- 页码区左侧显示当前汇总范围和总数，例如“第 1–10 条，共 18 条汇总”；右侧显示上一页、页码和下一页。第一页禁用上一页，最后一页禁用下一页。
- 汇总页和明细悬浮窗的分页按钮统一复用普通卡牌 Stepper 风格：32 × 32 px、浅灰底色 `#F0F2EE`、深色图标或文字、`#D6DBD6` 描边和 8 px 圆角。当前页使用稍深的灰绿色 `#DCE4DF`、`#AEBAB3` 描边和加粗页码区分，不使用绿色实心按钮；禁用按钮在相同样式上降低透明度。
- 切换页码时保留当前开始日期和结束日期条件。修改日期条件并查询时回到第一页。
- 操作类型使用轻量图标和绿色链接文字。点击类型名称在当前列表页打开对应日期、对应类型的明细悬浮窗；不在汇总表内展开，也不进行路由跳转。
- 打开悬浮窗时沿用汇总页的开始日期和结束日期条件。由于被点击的 `operation_date` 已处于该闭区间内，悬浮窗展示该自然日、该类型的全部操作。关闭后保留原日期条件、汇总页码和滚动位置。

## 5. 类型明细悬浮窗

- 悬浮窗固定在当前浏览器视口中央并使用固定尺寸，不使用汇总列表页面的文档坐标。半透明暗色遮罩固定覆盖当前浏览器视口，仅用于压暗并阻断底层交互，不使用背景模糊；遮罩和悬浮窗均保持在视口原位置。
- 悬浮窗打开期间必须锁定底层汇总列表：底层页面不能点击、翻页、修改日期条件或滚动，滚轮、触控滑动和键盘滚动不得穿透遮罩。明细内容超出弹窗可视高度时，只滚动弹窗内部内容区域；关闭后恢复汇总列表打开前的滚动位置。
- 标题直接组合显示日期和操作类型，例如“2026年9月24日 · 增加卡牌”，不再使用面包屑或重复的明细页标题。标题右侧显示具体操作总数和关闭按钮。
- 悬浮窗只能通过右上角关闭按钮关闭；点击悬浮窗之外的遮罩或底层页面不关闭，也不得触发底层操作。关闭不得重置汇总页日期条件、页码或滚动位置。
- 明细固定按 `occurred_at DESC, id DESC` 从新到旧排列，每页固定 10 条并在悬浮窗内部独立分页；翻页不得关闭悬浮窗。
- 明细悬浮窗桌面端外层背景框固定为 1040 × 650 px，不随当前页记录数量改变。每页最多显示 10 条；列表区域按当前页实际记录条数呈现，分页区紧跟最后一条记录向上或向下移动。记录不足 10 条时，未使用空间保留在分页区下方的弹窗背景中，不把列表强行撑成十行，也不缩小外层背景框。
- 1280 × 720 常用桌面视口中，1040 × 650 px 弹窗保持水平和垂直居中，左右各 120 px、上下各 35 px；八种操作类型共用该尺寸和定位规则，不分别复制响应式画板。
- 悬浮窗不显示日期区间输入框或操作类型筛选；日期和类型由被点击的汇总行确定。

## 6. 卡牌操作明细

- 增加卡牌和减少卡牌的明细表列为“操作时间、卡牌、印刷信息、数量变化”。印刷信息显示系列代码、收藏编号、语言和普通／闪卡；数量增加显示 `+N`，数量减少显示 `-N`。
- 加入愿望单和移出愿望单的明细表列为“操作时间、卡牌、印刷信息”；印刷信息显示系列代码、收藏编号和语言，不显示工艺或数量变化。
- 卡牌字段全部使用日志写入时的快照，不依赖当前 Card DB 仍存在对应记录。
- 操作日志是只读历史记录，当前卡牌行不承担收藏编辑、愿望单编辑或详情跳转操作。

## 7. 卡组操作明细

- 创建卡组、删除卡组、复制卡组和修改卡组的明细表只显示操作时间和卡组名称快照，不展开卡组内部牌张变化。
- 复制卡组显示新卡组名称；卡组重命名归入“修改卡组”，只显示修改后的名称。
- 删除后的卡组可能已经不存在，因此所有卡组日志行统一不提供卡组详情跳转。

## 8. 加载与状态

- 汇总列表或悬浮窗明细首次加载和翻页时，使用与表格行尺寸一致的骨架占位，并保留表头；明细加载期间不得关闭悬浮窗。
- 当前日期区间无结果，或从未产生过日志且未设置日期条件时，保留日期输入框、“查询”按钮、表头和分页区，表格内容直接为空；不显示专用空状态说明。
- 查询或翻页失败时保留当前页已有内容、日期条件和页码并打开全局统一错误弹窗，不在表格内增加重试入口，也不自动跳回第一页。

## 9. 当前原型样例

- `Screen / Operation Log` 展示按日期和操作类型合并的汇总分页列表。
- 八种操作类型分别提供独立的悬浮窗状态原型：
  - `Screen / Operation Log — Detail Modal / 增加卡牌`
  - `Screen / Operation Log — Detail Modal / 减少卡牌`
  - `Screen / Operation Log — Detail Modal / 加入愿望单`
  - `Screen / Operation Log — Detail Modal / 移出愿望单`
  - `Screen / Operation Log — Detail Modal / 创建卡组`
  - `Screen / Operation Log — Detail Modal / 删除卡组`
  - `Screen / Operation Log — Detail Modal / 复制卡组`
  - `Screen / Operation Log — Detail Modal / 修改卡组`
- 增加／减少卡牌原型展示操作时间、卡牌、印刷信息和数量变化；愿望单原型不显示工艺及数量变化；卡组原型只显示操作时间和卡组名称。
- 汇总列表和悬浮窗明细均每页固定 10 条；样例数量只用于说明分页结构，不代表实际固定数量。
